# ARC 算法 Harness：本轮实测结论

结论：真正的算法模块已实现、接入现有 Morphz Runtime，并在 Kaggle 上运行。
但目前**没有证明过关能力提升，也没有完成一组干净的完整预算对照**。
最新两次尝试都因输入超过 256K 提前终止，不能当成正常跑满后的性能分数。

## 算法实际执行到了哪里

不是要求模型“自己写算法”，而是固定 Python 模块执行：

- 二元切换模型辨识、恢复/叠加检查、GF(2) 消元和有界零空间搜索。
- 连通区域位移追踪，分离相同颜色的移动区域、目标和 UI。
- 离散运动拟合、后续转移检查、有界 A* 与每步真实观测验证。
- Runtime 的有限 Harness Program，每段 4 次推理；同一 Session 分段接续，
  不改变 Runtime 单个 Program 的固定推理额度，不重置整局计时或动作数。

最新 ls20 **真正执行了 56 次 A***，总计展开 1848 个状态，但没有找到候选
模型中的路线，因此没有提交 A* 规划出的导航动作。ft09 没有进入 GF(2)/A*
搜索；方法前置假设仍未成立。调用算法入口、执行探测和实际搜索是三个指标。

其中一个明确的算法抽象缺陷：把目标区域左上角直接当作物体目标锚点，
忽略了测得的移动步长。ls20 的保存观测中，物体锚点为 `[34,47]`，
动作位移为 5 像素；原始候选目标 `[35,11]` 不在这个可达坐标格上。
同色 UI 也可能被误列为候选目标。这需要修正目标/接触关系建模，
不是再给模型一句“认真搜索”，也不能据此否定算法路线。

## 接入阻断：256K 输入超限未进入正确恢复路径

服务端拒绝的实际输入为 281581 / 282554 tokens，上限 262144。
当前请求中的棋盘副本累积；ft09 从 4 份增至 32 份，中途缩减后又回涨。
SGLang 这条错误文案被分类为 `invalid_model_or_request`，没有进入已有的
`ContextLimit` 恢复分支。兼容分类缺口已由日志和源码定位；Context 回涨的
完整源级根因尚未证明。

详见 [Runtime 复现报告](BUG_CONTEXT_LIMIT_SGLANG_2026-10-24.md)。
它不是输出截断，也不是“模型想不到方案”的可靠证据。

## 验证与交付边界

- 61 项本地测试通过，包括真实 Runtime + mock provider + 合成引擎；
  测试通过不是公开关卡成绩。
- 最新两关的动作数、最高关卡数已逐项核对原始引擎轨迹；四段 Evaluation
  的 root Session 各自一致。原始结果与错误没有覆盖或改写成成功。
- 最新 30 条出站请求中，28 条 HTTP 200，2 条因超限 HTTP 400；
  每条只投影一张捕获绑定的原生 PNG，并非反复追加旧图片。
- 采样显存峰值 96511 / 97887 MiB。模型服务启动 901 秒，未混入游戏耗时。
- 全程使用免费 Kaggle GPU 配额；未训练模型、未调用付费 API、未提交排行榜。
- Kaggle Notebook 已完成，模型服务停止。平台显示 successful 只代表作业结束，
  不代表过关或完整性能评测通过。

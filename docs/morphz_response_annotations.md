# 响应注解：统一的开启／关闭契约

2026-10-17。本文描述当前实现；历史设计及其旧验收证据另存于
[历史记录](./archive/2026-10-17-response-annotations-history.md)，不构成兼容接口。

## 原则

认知求值的结果与其可读说明是两种信息。返回值 `T` 供实际调用方继续求值；
注解说明这次求值做了什么、得到了什么，不替代返回值，不决定任务状态。
所有逻辑 `infer` 都适用同一规则，不以“普通聊天／目标／中间过程／尾调用”划例外。
一次 `infer` 可以包含正常的工具往返，不等于只有一次物理 Provider 请求；
注解在原有响应中生成，不新增求摘要、起标题或修复元数据的模型请求。

## 一个设置，两个取值

`activation.response_annotations` 仅接受 `off`、`on`。省略时在准入处取 Runtime
配置默认值（默认关闭）；有效值随后冻结在实际 Thread，不跟随页面或配置变化。
定向补充继承原 Thread；新输入的合批只能发生在相同模式之间。
不提供自动判断、版本枚举、旧名别名或多套解析规则。

- 关闭：不附加注解契约、载体或提示。保留原工具定义、原始文本及 typed 返回传输。
- 开启：普通响应和所有 `infer` 使用同一元数据契约，要求在同一响应中生成简短
  标题和结果；工具轮的意图、阶段与已知回执解读仍可省略。开关控制元数据的生成
  和解析，不把元数据是否合规作为正文或业务返回值的成功条件。

Application 新输入和事项准入显式开启；Runtime 的默认关闭面向其他调用方。
这不是按场景偷偷切换，也不意味着每个调用方都必须采用注解。
精确重试保留原准入字段，省略与显式选择仍是不同请求，不因重开而改变请求身份。

## 返回值、元数据和发布权分离

开启时，普通 assistant 文本可以在最前面携带一个明确的元数据头，然后换行返回正文：

```text
<morphz-annotations>{"execution":{"title":"核对环境","result":"已确认系统类型"}}</morphz-annotations>
正文或原有 typed JSON／Yao 返回传输
```

只识别有界的响应起始头，不扫描业务 JSON 键、代码块或正文里的示例。流式处理只
短暂缓存元数据头，头结束后的正文立即原样输出。头最多 16 KiB；完整但无效的头
留局部诊断、保留正文，未闭合或过长的头保留原文本并明确诊断，不吞掉非空回答。
关闭时不识别或剥离这些字节。

已有 `reply({content, annotations})` 是可选的结构化载体，不是最终回复的唯一出口。
选择该载体时不能再同时提供另一个正文或工作调用，以免返回值和执行边界冲突。
两种载体共用同一字段、解析、可信来源与投影，不是协议版本或历史兼容别名。
`content`／正文是原值的既有文本传输；`annotations.execution.title`、`result` 是独立元数据。
例如 Bool 的内容仍是 `false`，具名数据类型仍是原 JSON，Program 仍是原 Yao 源码。
Runtime 提取 `content` 后沿原类型检查和 caller 路由继续，不把包装交给父程序，
不在业务对象中添加字段，也不根据业务键恰好叫 `reply` 或 `_annotations` 猜测协议。

`reply` 是响应载体，不是物理工具 Job，也不是给用户发消息的授权。
嵌套求值返回实际父 Plan；根程序只有满足已有交付类型和路由时才形成最终回复。
不恢复 `entry-result`，不增加第二次模型改写。`no_reply` 仍受原等待／静默约束，
既不要求伪造交付，也不向它的原参数语法塞入注解。

标题和结果须为有效、非空、有界文本；缺失或无效字段只局部拒绝，留下精确诊断，
不伪造标题／结果、不补模型、不把有效正文标为整轮失败。是否执行成功、是否完成
目标仍由真实业务返回、回执与 Runtime 状态决定。歧义控制、重复控制字段、空返回
或不合规 typed 业务值仍沿原失败边界停止，不能因注解降级而放行工作调用。
显示文本不包含隐藏推理；注解也不能制造百分比、权限、完成状态或 Objective 结算。

## 工具与缓存边界

开启后的载体名称、schema、说明和顺序使用一套公共定义；不按 Harness、返回类型或
当前问题增删工具，不在每次往返重建不同的注解协议。已有静态工具权限仍由 Harness
和部署授权控制；`reply` 不增加物理能力。开启预检拒绝保留名冲突，不覆盖业务工具。

工具往返的字节稳定性和 Provider 的实际缓存命中率是不同证据。协议统一后的首次
请求前缀改变不可避免；测试证明后续相同契约稳定，不能据此声称真实命中率已测量。

## 持久关系和原子边界

不新增活动表、注解生命周期或 PlanMachine 模式副本。唯一权威是原 Thread 的冻结设置。
Plan 协调器按准确 Thread ID 读取，并核对 agent/context/session/principal。
生成的 infer 请求 Event 携带该设置；SQLite／PostgreSQL 在现有
`create_evaluation_and_suspend_plan` 事务中再次核对父 Thread，创建同模式 child，
保存真实 `parent_thread_id`、请求、Signal 与 Plan 等待状态。精确重试不重复创建。
动态分支、并行子 Plan、恢复和 Program Value 都使用这一实际 owner 关系。

元数据仍保存在原授权来源 Event 的有界 bundle。来源核验继续检查
Thread／generation／Activation／model attempt／Event 身份；只读投影不信任模型给的
身份、共享 Session 或当前页面。查询沿既有索引按准确身份和有界批量执行，
不反复读取整线程，不复制正文建立另一个活动数据库。

控制失败的原授权错误 Event 保留校验前的 Provider adapter 输出（正文与原工具参数），
同时保留精确原因、SHA-256、字节数和完整／截断／不可用状态。捕获最多 2 MiB，
超过时明确为 JSON 前缀而非完整原响应，摘要仍覆盖全体原字节。它不是 HTTP 原包，
不含认证头、凭据或隐藏推理，不进入公开正文流；权限、保留和删除沿原 Event 生命周期。
流式解码拒绝也带回已收到的完整响应，不再一律以 `None` 丢弃。没有完整捕获时不能
根据清洗后的正文或合并报错断言模型未生成注解。

删除和保留沿原 Event、Thread、Plan 生命周期；注解不拥有业务对象。
本次未增加新表、SQL 列、索引、权限或业务删除路径。

## Desktop 的呈现

所有求值都能被观察，不等于每个物理模型请求都占一项顶层活动。
工作仍按真实父子关系组织；`infer` 的标题和结果属于它自身，不能覆盖父活动或
把父目标标为完成。纯 `infer` Harness 同样有原执行和有效标题，不会因为没有物理
工具就消失。取消、失败、运行和等待事实始终由 Runtime 决定。

移除复制原输入的“处理：xxx”兜底，也不展示内部 evaluator prompt。
无注解历史保留状态、命令和详情，不在读取时补推理或重放工作。
注解开关不控制正文可见性；讨论正文继续沿原消息类型流式呈现，不展示元数据 JSON，
不重新引入“求值结果／已用于回复”等普通用户不需要的技术标签。基础响应规则、
Context、Session IO 和消息工具只规定当前有效响应格式，不再同时要求“只能无工具
纯文本”和“只能 reply”。工具名称、schema 和顺序不随问题或载体选择改变。

## 数据切换与验证边界

生产代码仅识别当前取值，SQLite／PostgreSQL 的模式约束均只有 `off`／`on`；
退役的版本兼容解析和专用升级迁移已移除。已存在的开发数据不能因此删除。
部署到原测试 App 前，须确认没有在途执行，备份并先在副本验证一次性设置规范化；
保留所有身份、关系、正文、业务值、回执、草稿、凭据和未来安排，不能重发用户工作。
这项操作不是保留旧协议的运行分支。尚未完成切换时不得声称原 App 已验收。

确定性测试须分别证明：开启／关闭、单一 infer Harness、原 typed 值、同一响应的注解、
原请求次数、正常工具轮字节稳定、流式正文、非法元数据局部诊断、非法控制明确失败、父子及跨 Session
授权隔离、SQLite／PostgreSQL 一致性，以及补充、等待、取消和恢复不被改变。
合成 Provider 验证机制，不替代真实模型质量、真实缓存测量或原窗口验收。

> 状态验证，ME-08 Terminal-Bench 承担公开完整 Agent 外部验证。

本文所称“预实验（Pilot）”，是正式实验前的小规模试跑，用于检查任务难度、评分器、方差、成本和样本量设计。预实验期间允许修改协议，因此其样本与冻结协议后的确认性实验隔离，不用于论文的最终显著性结论。

本文所称“消融实验（ablation study）”，是从完整系统中有控制地移除或替换一个机制，同时尽量保持其他条件不变，以判断该机制是否真正贡献了观察到的效果。后文标题同时保留这一论文常用术语和直白中文说明。

## 0. 新实验统一运行约束

除非某个冻结协议明确声明并解释例外，2026-08-20 之后启动的 Pilot、确认性实验
和公开 Benchmark 接入统一使用：

1. 主模型为精确物理模型 `gpt-5.6-sol`，reasoning effort 为 `max`；通过
   CLIProxyAPI 兼容的 OpenAI Responses 路由调用；运行前必须验证逻辑模型与物理
   模型均为 `gpt-5.6-sol`，`fallback=false`，不得静默换模型；
2. Morphz 运行权限使用 `full-access`，不在 episode 中插入人工批准步骤，避免审批
   等待、拒绝或人工响应速度污染成功率和延迟；`full-access` 只作用于隔离实验节点，
   不得绕过 Benchmark 官方的容器、网络、数据、secret 或工具使用规则；
3. 使用独立于日常开发和产品实例的 Morphz 节点、独立数据库和独立 Context；不得
   挂载或读取共享 `context-default`、生产数据库、历史 Session 或个人开发状态；
4. 不同 arm/run 不得复用可写数据库。允许从同一个只读初始快照克隆，但每个 run
   必须得到新的数据库和 Context identity，并记录初始快照 hash、节点 ID、数据库
   路径/实例 ID 与 Context ID；
5. CLIProxyAPI 连接信息和凭据只通过实验节点的受管配置注入，不写入 fixture、trace、
   trajectory 或公开 Benchmark artifact。

## 1. 论文要证明的中心命题

Morphz 是一台 **S-Expression Cognitive Machine（S 表达式认知机）**：它将结构化、可寻址、可版本化的 Context 作为可执行认知状态和递归程序—数据表示；大语言模型作为可替换的非确定性语义处理器执行开放认知求值；确定性 Runtime 作为事务内核，对候选结果实施结构、权限、因果和版本校验，并提交权威状态或现实副作用。Agent 是认知机加载身份、Context 与能力后的实例。求值结果能够通过局部绑定、认知帧或关系直接重新进入后续求值。

实验不能只证明“Morphz 能完成任务”，而要分离并验证下列因果环节：

1. 递归结构化表达能被模型构造和求值；
2. 真实 Observation 能成为后续数据流、控制流和认知状态；
3. 稳定对象标识、版本和直接引用比重新解释消息历史更可靠；
4. 开放语义求值允许多个契约有效结果，并受 Context 变化约束；
5. 确定性 Runtime 能在候选认知和现实副作用之间保持权威边界；
6. 上述机制能够导出跨 Session、长时间运行、并发和恢复能力。

## 3. 实验组合

### ME-00：实验基础设施与校准

目的：建立统一 manifest、Run ID、产物目录、确定性评分器、汇总器和环境审计。

必须完成：

- 捕获 Runtime commit、dirty diff hash、协议版本和评分器版本；
- 捕获 Provider、模型精确标识、解码参数、上下文与输出预算；
- 捕获 CLIProxyAPI 路由、requested/physical model、reasoning effort 与 fallback 状态；
- 捕获授权模式、实验节点 ID、数据库身份、Context ID 和初始状态 hash；
- 固定 fixture ID，并支持各 arm 配对执行和交错顺序；
- 区分模型失败、Runtime 失败、评分失败和 Provider 故障；
- 原始响应、工具调用、Context/Event History 快照完整落盘；
- 汇总语义成功率、严格成功率、成本和错误分类；
- 检验从原始产物重新评分能够得到相同结果。

ME-00 完成前可以继续做工程探针，但不得启动正式确认性批次。

### ME-01：核心机制拆解对比（结构化 Context 与结果回流消融实验）

这是论文优先级最高的实验。

这里的“结果回流”指模型或工具产生的结果不只作为一条新消息保存，而是被转换为带稳定标识、来源、版本和关系的认知对象，使后续求值能够直接引用。该实验通过逐项关闭结构化状态、直接引用或事务提交等能力，分辨最终提升究竟来自哪一部分。

候选 arms：

1. `append_only`：完整或受预算限制的消息历史；
2. `retrieval_only`：按需检索原始事件，不建立权威结构化认知对象；
3. `json_memory`：非类型化 JSON 状态；
4. `structured_no_direct_reentry`：存在结构化对象，但后续仍通过文本重解释；
5. `full_morphz`：稳定标识、版本、来源、直接绑定/帧引用与事务提交。

ME-01 的基础能力 Pilot 不制造 Context 长度压力，也不把简单窗口截断作为现代 Agent 的
主要基线。周期性 `runtime_compaction` 与 Morphz 增量式认知维护的公平比较只在 ME-06
长程固定事件流中执行。

任务族：

- 延迟引用：早期产生对象，数轮后用于行动；
- 修订与冲突：新证据取代旧事实；
- 来源约束：相同命题来自不同权威级别；
- 跨 Session：另一个 Session 使用已提交认知对象；
- 隐藏行动：最终工具参数只能由当前权威状态推出；
- 负迁移与隔离：不相关主体、项目或 Session 不得继承状态。

主要指标：隐藏行动成功率。次要指标：陈旧事实拒绝率、修订正确率、来源/因果正确率、跨 Session 连续性、污染率、请求数、Token、延迟和成本。

### ME-02：表示形式拆解对比（表示形式消融实验）

在同一状态机制和直接回流机制下，提供语义等价、信息等量的：

- annotated S-expression；
- JSON AST；
- 自然语言/Markdown 程序；
- 可选 Typed DSL。

主要指标：端到端语义任务成功率。次要指标：可解析率、引用/作用域/分支精确率、修复率、请求数和 Token。

本实验不预设 S-expression 必须全面胜出。若结构化表示接近而自然语言退化，可以支持“递归结构而非具体括号语法是核心”；若各组接近，则必须诚实缩小表示优势主张。

### ME-03：非确定性认知求值特征

设计存在多个合法结构化结果的 bounded-open symbol，并设置 closed operator 对照：

- 在 Context 不变时重复求值，测量契约有效率和合法多样性；
- 增加、删除或修订认知帧，检验结果分布是否发生可解释变化；
- 对候选结果施加类型、权限、版本和因果校验；
- 检查候选结果变化时，权威提交和现实副作用仍保持确定性约束。

主要指标：契约有效率与 Context 干预敏感度。多样性是描述性指标，不把提高 temperature 当作非确定性成立的证据。

### ME-04：Runtime 权威边界与故障注入

不依赖大量模型调用，优先建立确定性证据：

- 非法 capability 或工具参数；
- 无效表达、类型或结果契约；
- 陈旧版本提交和并发写冲突；
- 重放、重复现实副作用；
- 工具完成后、Observation 提交前崩溃；
- Context 已提交、用户回复前崩溃；
- 恶意 Observation 或 Prompt Injection；
- 多 Session/Principal 的权限和状态隔离。

主要指标：未经授权的现实副作用必须为 0；同时报告冲突发现率、重复防止率、恢复正确率和因果轨迹完整率。

### ME-05：跨模型能力与采用倾向

分成两类，不能混为同一个问题：

- `capacity`：明确要求使用该表示和机制，测量模型能否执行；
- `adoption`：只暴露能力，不强制采用，测量模型是否会自然选择。

预印本至少覆盖三个模型家族；正式投稿目标为四个。所有 arm 在同一模型内比较，禁止拿不同模型的公开榜单分数直接归因于 Runtime。

### ME-06：长期、多 Session、迁移与恢复

使用 100–200 轮以上、多个 Session 和多次进程重启的固定事件流，包含：

- 稳定事实、短期过程、冲突修订和噪声；
- 来源可靠性变化；
- 模型切换；
- 并发 Context 更新；
- 正迁移、负迁移和主体隔离。

主要对照为同模型、同任务的现代 Agent 周期性 `runtime_compaction` 与 Morphz 增量式
Structured Context 维护；不使用“直接丢弃旧消息”作为主基线。最终正确率首先检验 Morphz
在获得跨 Session、事务、并发、恢复和审计能力后是否退化；compaction 停顿、维护调用、
Token 和延迟作为机制与成本诊断，不预设 Morphz 必须在每项上胜出。

主要指标：最终隐藏行动/状态正确率。次要指标：陈旧状态率、污染率、Frame 增长、Context 压力、恢复正确率和累计成本。

### ME-07：公开 Benchmark 外部验证

分为两个互补轨道：

- ME-07A Terminal-Bench/Harbor：测量完整 Coding Agent 的外部系统能力，只作为通用能力和
  宣传数据，不冒充 Structured Context 或非确定性认知求值的因果证据；
- ME-07B Mem2ActBench：要求跨 Session 记忆进入后续工具选择和参数落地，与 Morphz 核心
  机制更一致，仍是论文外部有效性的首选机制相关 Benchmark。

执行纪律：

- 先做一个不进入正式统计的接入样本；
- 固定同一模型、工具环境和预算比较 Morphz 与基线；
- 保留官方评分器结果，并增加 Morphz 的 Context/Event History 因果分析；
- 报告适配改动，不能把改变任务语义后的结果称为官方同榜成绩；
- 将公开 Benchmark 作为外部有效性证据，不替代 ME-01 的核心消融。

### ME-08：扩展公开验证（可选）

根据时间和接入成本，从以下选择一项：

- MemoryArena：行动—反馈—记忆—后续行动链；
- MemoryAgentBench：优先 conflict resolution 和 test-time learning；
- LongMemEval-V2：长期状态、工作流和冲突的大规模补充。

Terminal-Bench/Harbor 与 π-Bench 保留为通用 Agent 能力和系统案例；可以登记在 ME-07A，
但不能作为认知求值核心主张的唯一证据，也不替代 ME-07B。

## 4. 分阶段推进

### Phase 0：实验地基

范围：ME-00，以及 ME-01/02/03/04 的协议草稿。

退出条件：

- Run 产物可复现、可重新评分；
- 主要指标和排除规则写入协议；
- 至少一个模拟 Run 验证总账和产物链路；
- 论文核心术语与实验变量没有漂移。

### Phase 1：核心因果证据

范围：ME-01 Pilot、ME-04 确定性故障实验。

推进顺序：先实现最有区分力的三个 arm——`append_only`、`structured_no_direct_reentry`、`full_morphz`；Pilot 证明任务和评分器确实能区分状态机制后，再扩展其余 arms。

退出条件：

- Pilot 无明显天花板/地板效应；
- 评分器不依赖主观 LLM 判断即可覆盖主要指标；
- 根据 Pilot 效应和方差冻结 confirmatory 样本量；
- ME-04 的关键安全不变量通过确定性测试。

### Phase 2：表示与求值机制

范围：ME-01 confirmatory、ME-02、ME-03。

退出条件：

- ME-01 主要指标完成确认性统计；
- ME-02 在等信息条件下完成至少三个表示组；
- ME-03 完成 Context 干预与 closed/open 对照；
- 论文核心主张依据结果收缩或确认。

### Phase 3：泛化与长期运行

范围：ME-05、ME-06。

退出条件：

- 至少三个模型家族完成核心子集；
- 长运行使用固定协议完成，不混入中途修订批次；
- 跨 Session、迁移、隔离和恢复均有隐藏评分。

### Phase 4：公开 Benchmark 与论文收口

范围：ME-07，时间允许时执行 ME-08。

退出条件：

- 至少一个公开 Benchmark 完成可复现评测；
- Claim–Evidence Matrix 中每个核心定量主张均指向冻结结果；
- 生成主表、置信区间、错误分类和代表性失败案例；
- 论文、代码和匿名化实验包中的数字一致。

## 5. 样本与统计计划

以下是规划原则，不在 Pilot 前锁死最终数字：

1. Pilot 建议每个主要 arm、每个任务族约 20 个配对 episode；Pilot 只校准任务、效应和评分器；
2. confirmatory 样本量根据 Pilot 的配对差异和置信区间确定；如果无法稳定估计，核心二元指标默认目标不少于每个主要比较 50 个配对 episode；
3. 各 arm 共享 fixture ID，并按预生成顺序交错执行，避免时间和 Provider 漂移；
4. 二元配对结果报告差值、bootstrap 95% CI，并按条件使用 McNemar 或配对置换检验；
5. 连续成本指标报告中位数、四分位距和配对 bootstrap CI，不只报告均值；
6. 多组探索比较与预先声明的主要比较分开，必要时使用 Holm 校正；
7. 确定性评分为主，LLM judge 只用于无法机械判定的次要开放质量，并进行抽样人工复核；
8. Provider 超时或明确服务故障可以按预注册规则补跑；模型产生空响应、非法结构、错误工具或预算耗尽必须计为模型/系统结果，不能删除。

## 6. 结果进入论文的门槛

内部可审阅预印本的最低核心证据包：

- ME-01 三个核心 arm 的确认性结果；
- ME-02 等信息表示消融；
- ME-03 的 open/closed 与 Context 干预结果；
- ME-04 权威边界和恢复；
- ME-05 至少三个模型家族的核心子集。

公开发布时强烈建议再完成 ME-07；它不是预印本成立的逻辑前提，但能够显著降低“任务为 Morphz 量身设计”的质疑。如果接入尚未完成，论文必须明确标为后续工作，不能暗示已有外部验证。

更完整的会议投稿包再加入 ME-06 全量长期实验、四模型矩阵和第二个公开 Benchmark。

## 7. 已有证据的处理

现有实验不丢弃，但按证据级别重新登记：

- 五模型 Context pressure：`F`，用于跨模型可行性；
- bind/if 18 episodes：`F`，用于真实 Observation 回流的微基准；
- S-expression 五组对照：`F`，因样本量、模型数和提示信息量未完全满足确认性设计；
- Context long-run：`F`，协议中途演进，作为发现机制和失败模式；
- ForgeDepot 并发与恢复：`F`/案例研究；
- Rust/Runtime 自动测试：根据覆盖范围登记为 `D`；
- 原始 episode 丢失的 program-construction probe：只保留历史叙述，必须重跑后才能产生定量结果。

## 本次发现与修正

| 场景 | 实际问题 | 本次修正与边界 |
| --- | --- | --- |
| 当前理解 | 模态遮住工作现场，另设纠正输入，并直接提交带技术步骤的指令 | 非模态右栏展示公开摘要、版本和来源。梳理／更新／纠正只准备统一输入草稿，不自动发送、不改 Session；窄窗准备草稿后关闭侧栏，避免挡住发送。没有暴露内部推理。 |
| 空间菜单 | 原绝对定位菜单与应用层级、关闭和键盘逻辑各自实现；完整回归在应用打开时出现导入点击未进入弹窗 | 采用现有顶层弹出菜单组件，统一方向键、Escape、外部点击和触发器焦点返回。该失败发生在导入之前，不是百万字朗读管线失败。 |
| 长内容编辑 | 保存／取消在正文底部，长文需要滚动寻找；阅读旧版本时“编辑”没有说明实际目标 | 操作进入现有工具栏，不增加 Header。支持 Cmd/Ctrl+S；无改动、保存中、冲突时不误提交。旧版本明确“编辑当前版本”，仍保留人工草稿和版本冲突处理。 |
| 表格／表单／报告 | 筛选后新增记录仍被旧条件隐藏；新增入口远离筛选，空表与无结果混淆 | 筛选、数量、新增就近放置，新增清除筛选并聚焦新行；空结果可清除。可选说明／字段设置折叠，表单勾选恢复合理尺寸；报告区分编辑预览和已存版本。不是完整表格软件。 |
| 来源连接 | 读取失败容易与没有来源混淆；操作错误可能被后台刷新抹掉；说明和错误占据过多画布 | 加载／空态／读取失败分开，失败可重试；操作错误保留到下一次操作。轮询不重叠、不覆盖较新的操作结果。只读与暂停／断开语义保留，详细同步说明折叠。 |
| 输入与画布 | 默认展开但尚未聚焦的输入区，在用户点击编辑后仍占据窄窗口内容空间 | 点击主画布触发未固定输入收起；固定输入仍保留，模态暂停与显式打开输入的优先级不变。 |
| 朗读 | 文档标题重复，原生粗滑块、段数字符统计和操作占据多行；短句只有一段时进度不动 | 紧凑控制带只常驻播放／暂停、实际音频进度、语速、详情与关闭。章节和当前原文按需展开；单段按秒显示和定位，多段保留段落跳转，拖动已解码音频不重新合成。尚未加载时不假画满格、不假造总时长。 |

## 朗读证据纠正

“百万字通过”只指 TXT 导入、分段、连续请求、暂停／恢复和章节跳转的自动回归；原测试使用模拟供应商与静音 WAV，不能证明真实合成、音响出声或百万字全本实际朗读。用户指出短句无声后，已当面纠正表述，不能继续将其简称为“百万字朗读验收通过”。

随后针对当前中心真实请求短句，获得非静音的 16kHz PCM WAV；新增 `scripts/live-tts-playback.ts --live-center=http://127.0.0.1:65424/`，只创建隔离资料／profile，实际调用当前中心的合成服务并交给 Electron 原生解码和播放，不读取麦克风或暴露 Key。首轮短句音频约 2.59 秒，RMS 2778、播放进度前进、未静音、无媒体或控制台错误。它验证链路，不冒充扬声器实听；用户随后明确反馈“朗读有声音了，没问题了”。没有定位到用户先前无声的确定根因，不宣称本轮修复了该根因。

朗读 UI 回归使用明确标注的合成音调，检查紧凑尺寸、秒级进度、同段拖动不重新请求、明暗与窄窗口；不再用这项回归证明真实供应商或声学输出。

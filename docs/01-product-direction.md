# 产品定位与原则

日期：2026-09-06  
状态：产品设计草案，不代表已发布功能

## 产品出发点

MorphzWork 探索人与 AI 如何共同推进工作。现实中的工作既包含人交给 AI 的任务，也包含 AI 为实现目标而安排给人或其他 Agent 的事务。工作还会跨越聊天、开发环境、网页、手机和团队成员。

产品关注的使用摩擦包括：AI 提出的行动计划留在聊天中，用户需要自行记住和执行；用户要把 AI 写的内容复制到网页；跨应用操作之后，还需要回到原会话重复说明结果。

产品从这些需求出发，结合 Morphz 能力设计体验，并通过实际工作流程验证使用效果。

## 一、Agent 自主规划，人可以调整

Agent 根据目标组织事务、安排执行者、处理依赖并持续推进。人可以在之后修改负责人、模型、时间、优先级和方向。

不把“人先逐项确认计划”设为所有工作的默认前提。自主安排仍受已授予的权限、预算和团队协作规则约束；规划一项外部操作与获准执行该操作需要区分。

AI 给出的一般建议和正式分派的事务，也需要有可理解的边界，避免把每句讨论自动变成正式待办。具体形成规则待设计。

## 二、人与 Agent 都是正式参与者

事务可以指派给用户自己、用户的协作人员或 Agent。Human → Agent、Agent → Human，以及后续结果回流，都属于正常协作流程。

Agent 请求人的参与，不仅是遇到权限弹窗或无法执行时的例外。安排人做判断、联系、创作或现场操作，本身就是产品要支持的一等能力。

团队中的指派权、对方是否需要接受、谁能修改分工，需要遵守协作关系；Agent 不能自行取得对其他人的指挥权限。

团队成员通过 Principal（主体）保持稳定身份，可以从不同设备和 Session 与同一个 Agent 对话。Agent 能区分请求来自谁、谁负责什么，并在授权范围内把不同事务分派给不同成员的 Inbox。共同使用一个 Agent 不要求成员共用账号，也不要求所有交流发生在同一个群聊中。详见[Principal 与团队协作](./06-principals-and-team-collaboration.md)。

## 三、通用 Inbox 承载事务

Inbox 不限于审批，也不只是通知集合。它应让参与者找到需要自己执行、回应、决定或交付的工作，并能调整相关安排。

事务负责人、Agent 执行所用模型、交付目标是不同维度。为某项事务更换模型，不应因此创建一个失去原有进度的新任务，也不必改变 Agent 身份。

具体事项如何进入 Inbox、共享工作如何呈现、已读与处理状态如何区分，见生命周期草案。

## 四、Cloud 或自托管中心，各终端是 Edge

默认 Cloud 模式下，中心承载持续的 Agent 状态。Web App、Desktop、Mobile 和浏览器扩展都是连接中心的 Edge，不是各自维护独立认知后再彼此拼接的 Agent。

自托管模式保留同样的产品关系，只是中心由用户部署。这里的“一个中心”表示逻辑状态与权威一致，不预先限定为单进程、单服务器或某种数据库拓扑。

聊天记录必须同步。任务、产物、进度和相关认知同样属于中心状态。终端可以打开已有 Session，也可以建立不同 Session；会话记录同步与多 Session 共享认知同时成立。

共享状态不意味着所有参与者和所有网页都有权读取全部内容。Session、任务和产物的可见范围必须符合身份与授权。

## 五、浏览器是现场工作的入口

Desktop 内置浏览器是核心工作区之一。用户可以在其中登录网站，在授权范围内由 Agent 协助操作，并随时接管。浏览器扩展并行保留，用于在用户已有的外部浏览环境中工作；内置浏览器不保证兼容所有网站的登录流程。

浏览器扩展可以成为另一个 Session。在用户打开输入框后，用户可以直接要求它依据最新进展撰写内容，无须先在桌面应用生成固定草稿。

页面提供当前场景，共享认知与相关会话提供持续理解。扩展不仅用于展示和搬运内容，还承担现场交互与获准的执行。

## 六、时间与优先级共同参与安排

Agent 的安排需要考虑截止时间、预计耗时、优先级、依赖和人的可用时间。人能够理解安排的依据，也能覆盖或调整。

临近截止、重要程度高、能解除依赖阻塞是不同因素，不应简单折叠为“最新消息排在最前”。排序和提醒策略仍需实际验证。

## 产品边界

- MorphzWork 是完整应用产品的探索，不局限于 Desktop，也不只是 Runtime Dashboard 的包装。
- 日常聊天保留轻量体验，不要求每句话都成为正式事务。
- 多端应用属于同一 MorphzWork 产品，通过明确的 API／SDK 使用 Morphz Runtime。
- Web App 设计为完整用户入口，面向云端和自托管；CLI 按需获取兼容发布包并启动，二进制仅内嵌 Dashboard。Desktop 可额外安装，详见[应用架构与分发](./05-application-architecture-and-distribution.md)。

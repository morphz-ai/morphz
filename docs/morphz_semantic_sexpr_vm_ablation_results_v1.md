## 1. 本轮回答的问题

本轮把刚验证过的“纯 SExpr 结构 + 算子内部自然语言定义”加入多组对照，比较五种表达方式：

1. `external_nl_vm`：System Prompt 用外部自然语言定义 VM，任务使用可读 SExpr；
2. `bare_readable`：只有普通工具 Agent 身份，任务使用可读 SExpr；
3. `symbolic_kernel`：System Prompt 是纯 SExpr，只给符号形式，不给完整自然语言语义体；
4. `annotated_kernel`：System Prompt 是纯 SExpr，六个基础算子内部带简洁自然语言定义；
5. `direct_prose`：普通工具 Agent 身份，任务使用等价自然语言过程。

所有组使用相同模型、标准 Function Calling 工具、确定性工具结果、最大轮次和评分规则。Pilot 的 20 个 episode 只用于检查实验装置，不进入正式统计。正式轮共 100 个 episode。

## 2. Kernel 与任务语法

`annotated_kernel` 使用共享 Kernel，定义：

- `seq`：从左到右求值；
- `call`：发出真实标准 Function Calling；
- `fallback`：主表达式明确失败后才求值备用表达式；
- `bind`：绑定真实精确结果，支持 `name.field`；
- `if`：只求值一个分支；
- `reply`：产生最终无工具回复。

`process` 被放在声明层，不算第七个基础算子。它定义命名过程、参数、局部作用域和最后表达式返回值。

为避免旧实验语法污染，本轮可读 SExpr 任务统一改写为上述六算子语义；早期的不透明 `p0/s1/a1` 缩写不进入本轮主对照。

## 3. 正式结果

| 组别 | 完整成功 | 语义成功 | 平均得分（满分 5） | System Prompt 字符数 |
|---|---:|---:|---:|---:|
| `annotated_kernel` | 16/20（80%） | 16/20（80%） | 4.60 | 1239 |
| `external_nl_vm` | 16/20（80%） | 18/20（90%） | 4.80 | 655 |
| `direct_prose` | 15/20（75%） | 15/20（75%） | 4.50 | 27 |
| `symbolic_kernel` | 13/20（65%） | 15/20（75%） | 4.30 | 412 |
| `bare_readable` | 12/20（60%） | 12/20（60%） | 4.00 | 27 |

完整成功要求精确工具计划、真实因果轮次、正确分支和最终交付全部通过。语义成功允许额外的错误调用后恢复，因此外部 VM 和纯符号组的语义成功率高于完整成功率。

## 4. 逐任务结果

| 组别 | 线性发现 | 失败回退 | 过程复用 | 无动作分支 |
|---|---:|---:|---:|---:|
| `annotated_kernel` | 3/5 | 5/5 | 3/5 | 5/5 |
| `external_nl_vm` | 5/5 | 4/5 | 2/5 | 5/5 |
| `direct_prose` | 5/5 | 5/5 | 0/5 | 5/5 |
| `symbolic_kernel` | 3/5 | 5/5 | 0/5 | 5/5 |
| `bare_readable` | 5/5 | 3/5 | 0/5 | 4/5 |

最有区分度的是过程复用：候选组 3/5，外部 VM 2/5，其余三组全部 0/5。候选和外部 VM 能维持“Alpha 完整过程结束后再执行 Beta”的局部过程边界；裸 SExpr和自然语言倾向先执行两个搜索，再统一验证，从而打散过程体。

## 5. 候选组的四次失败

`annotated_kernel` 的失败不是变量串扰或错误条件分支：

- 两次线性发现直接回复可预测的 `NOVA-VERIFIED`，完全跳过真实工具链；
- 两次过程复用正确完成全部六个工具调用，但随后返回空正文，缺少最终 `reply`。

因此候选组当前的主要问题不是 `bind/if/fallback` 解释错误，而是两类边界服从问题：是否开始真实执行，以及全部动作完成后是否稳定交付最终回复。

工具轨迹是完整成功的必要条件，所以可预测交付 token 没有造成假阳性。但下一版夹具仍应改用不可从任务名称推测的不透明交付值，以改善失败诊断质量。

## 6. 成对比较

同一轮同一任务上，候选组与其他组的成对结果：

| 对照组 | 两者都成功 | 仅候选成功 | 仅对照成功 | 两者都失败 |
|---|---:|---:|---:|---:|
| `external_nl_vm` | 13 | 3 | 3 | 1 |
| `bare_readable` | 10 | 6 | 2 | 2 |
| `symbolic_kernel` | 12 | 4 | 1 | 3 |
| `direct_prose` | 13 | 3 | 2 | 2 |

候选相对裸 SExpr 和纯符号 Kernel 有正向差值，但 20 个配对样本仍太少，不能把 20 个百分点的总体差异解释成稳定统计优势。候选与外部 VM 的完整成功完全持平，成对胜负也是 3:3。

## 7. 可以得出的结论

1. **候选没有退化。** `annotated_kernel` 的完整成功率与外部自然语言 VM 相同，达到预注册的候选通过底线。
2. **自然语言算子定义有初步增量价值。** 相比裸可读 SExpr，完整成功率从 60% 提升到 80%；相比只给符号形式的 Kernel，从 65% 提升到 80%。过程复用上的 3/5 对 0/5 是最明确的结构信号。
3. **尚未证明整体优于外部 VM。** 两者完整成功都是 80%，外部 VM 的语义成功反而更高。候选的优势目前主要体现在干净的过程结构，不是所有任务的工具服从。
4. **自然语言仍然很强。** 直接自然语言在三个简单任务上都是 5/5，只在过程复用上稳定打散模块边界。
5. **纯符号不足以替代语义说明。** 纯符号组能执行回退和简单条件，但在过程复用中 0/5，并出现额外错误调用或空响应。

当前最合理的产品方向是保留 SExpr 内自然语言算子定义作为 VM Kernel 候选，同时继续优化执行/回复边界并扩大样本，而不是宣称它已经全面胜过外部自然语言契约。

## 8. 成本与结论边界

候选固定前缀是 1239 个字符，约为外部自然语言 VM 的 1.9 倍、纯符号 Kernel 的 3 倍。该前缀适合放在稳定前缀中使用 prefix cache，但本报告没有采集服务端实际 token 与 cached-token 指标，不能用字符数替代真实成本结论。

本轮只执行了既有四任务核心子集：线性发现、失败回退、过程复用、无动作分支。深层嵌套恢复、独立 Reply Boundary 和更长依赖链尚未进入五组正式对照；`bind/if` 的精确引用与局部作用域另见 [`bind` / `if` 算子真实评测 v1](./morphz_bind_if_operator_eval_v1.md)。

此外，本轮只有一个模型、每格五次，中文候选 Kernel 与英文外部 VM 之间也存在语言差异。结果足以支持继续研究和不退化判断，不足以冻结最终 Kernel。

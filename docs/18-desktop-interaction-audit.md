# 桌面交互审计

审计日期：2026-09-09。范围是现有桌面产品，不是专业认知应用的功能规划。先记录问题，再按用户确认统一实施；下方原始问题保留为修改依据，不代表最新界面仍有这些行为。测试使用隔离中心，没有对个人中心发送测试消息，也没有进行用户研究。

## 结论

主要问题不是按钮不够漂亮，而是操作入口、工作对象、交付结果和返回路径没有贯彻同一套规则。用户能让 Agent 完成工作，却仍要猜结果在哪里；能进入一个界面，却不一定能按原路返回；有些可见控件表达的能力与实际行为不符。

记录的 13 项均已实施，其中 A01 在审计时已调整，其余项在本轮修复。P1 表示阻碍主要工作流程或容易造成误操作；P2 表示增加学习、查找和操作成本，不表示存在数据安全漏洞。验收记录见文末。

## 实施结果

| 项目 | 最新行为 |
| --- | --- |
| A01 项目会话 | 项目行直接新建；旧对象打开、旧文档保存和迟到的新建回执都不能抢走后来选择的页面或会话。 |

| A04 返回路径 | 顶栏提供紧凑前进／后退及快捷键，恢复对象版本、应用、列表筛选与阅读现场；不切换 Session、不重放任务。 |

| A07 通知 | 打开前重新校验对象访问权限；保存已读失败不阻止阅读，待补记状态本地持久保留，网络恢复后重试。权限错误仍拒绝读取。 |
| A08 搜索 | 全局入口明确为“搜索资料”，局部为“搜索标题”。没有暗示已支持项目或会话全文检索。 |
| A09 图标 | 执行使用任务清单图标，批注使用消息批注图标，不再以同一侧栏图标表达不同动作。 |
| A10 模型 | 从 Runtime 实际模型目录选择。输入菜单只影响本次输入；事项的模型设置用于其后续执行。不改变全局模型或已在运行的请求。目录不可用时解释原因并可重试。 |
| A11 文案 | “让 Morphz 起草”“手动写文档”明确区分动作；用户界面将内部的交互产物称为“表格与报告”。 |
| A12 网站 | 用户在宿主界面主动打开网站对象即进入内置网页；刷新、恢复历史或应用消息不会自行触发外部浏览。Agent 的读取、填写和点击授权仍单独处理。 |
| A13 连接 | 消息区不再重复显示大块断线说明。输入附近保留紧凑、可操作的提示，详情分别说明中心、Agent 与模型状态。 |

交付关联是新增的持久记录：旧消息没有可靠产物来源时不补造入口，既有对象仍可在资料或搜索中找到。这里的模型选择、普通导航和显式浏览不是后台线程 steering，也不是给认知应用放开桌面权限。

## 已处理

### A01 · 项目会话入口过深

- 原路径：进入项目 → 顶部对话选择器 → 新建。用户必须先知道会话管理藏在哪里。
- 现路径：侧栏项目行右侧的方框笔形按钮，单击新建并进入输入。不是加号；顶部选择器已移除。已有会话放在项目下，点击切换，重命名、归档和恢复放在条目菜单中。
- 保留原应用、对象、独立草稿与后台任务。创建失败可以重试，不提前发送消息；较早的对象打开回执不干扰新的会话选择，创建回执也不抢走用户之后选择的页面。
- 实现：[ProjectConversations](../apps/web/src/ProjectConversations.tsx)、[App](../apps/web/src/App.tsx) 的 `selectConversation` / `createProjectConversation`。
- 验收：项目会话 5 项界面专项通过；真实 Electron 覆盖直接新建、应用保留、草稿、归档与恢复。不是对 Codex 界面的逐像素复制。

## 优先处理：完成一件工作之后能继续使用它

### A02 · Agent 交付的文档缺少直接入口 — P1

**路径**：让 Agent 创建文档 → 收到“已保存”回复 → 想打开文档。现有回复通常只是文字，用户需要另找资料应用或搜索。

**证据**：[Conversation](../apps/web/src/Conversation.tsx) 的 `message-object-link` 只来自原输入的 `artifactId`，不是工具创建的产物。回复渲染没有把实际产物回执转成对象入口。这也与用户此前的实际反馈一致。

**处理**：将真实工具回执中的对象 ID、版本与当前输入／执行根关联，在交付处提供紧凑的对象入口。不能从标题或模型宣称“已保存”推断成功，也不能把原输入引用当作新产物。

**验收**：文档、事项、图片等产物均可从交付位置直接打开；并发交付不串对象；无权限、对象不存在、创建失败分别有真实说明。打开产物不切换其来源 Session。

### A03 · 文本里的链接不能打开，图片只剩占位文字 — P1

**路径**：打开回复或文档 → 点击链接／查看内嵌图片。

**证据**：[Conversation](../apps/web/src/Conversation.tsx) 和 [ArtifactEditor](../apps/web/src/ArtifactEditor.tsx) 的 Markdown 渲染将 `a` 转成 `span`、`img` 转成文字。文档链接甚至保留链接样式，却没有链接行为。源码确认，不是网络加载失败。

**处理**：建立统一的安全打开路径：内部对象链接打开对象，用户主动点击的合法网页链接进入明确的浏览器目标。授权内附件可显示预览；外部图片不得为了显示而无提示地发送网络请求。

**验收**：鼠标和键盘均可打开合法链接；危险协议被拒绝；内部对象权限照常校验；消息或文档内容不能借链接获得桌面执行权限。

### A04 · 对象跳转没有可恢复的返回路径 — P1

**路径**：从资料列表打开 A → 从关联对象进入 B → 想回到 A 的原位置。

**证据**：[App](../apps/web/src/App.tsx) 的 `openObject` 保存当前对象，未建立对象浏览历史；[ApplicationHost](../apps/web/src/ApplicationHost.tsx) 的“所有资料”清空对象选择，返回集合，不是返回上一个对象。内置网页自己的后退不能解决宿主对象导航。

**处理**：提供轻量的前进／后退，保存视图、项目、应用、对象版本和阅读位置。返回列表时恢复筛选与滚动，而不是要求用户重新查找。

**验收**：列表 → A → B → 后退能回到 A 原位置，再后退回原列表；不改变会话、重启任务或丢弃编辑草稿。已失去权限的对象不能通过历史重新读取。

### A05 · 通用资料导入隐藏在空间菜单，资料页只写“导入图片” — P1

**路径**：进入“资料”，希望导入一份 PDF 或 Markdown 文件。页面可见入口是“导入图片”；真正的“导入资料”藏在空间的省略号菜单。

**证据**：[ObjectCollection](../apps/web/src/ObjectCollection.tsx) 的 `onImport` 与 [App](../apps/web/src/App.tsx) 的“导入资料”是两条入口。

**处理**：资料应用提供直接可见的“导入资料”，允许选择已支持的文件类型；图片只是其中一种。文件夹持续同步属于较低频、需要额外授权的选项，不与一次性导入混为一谈。

**验收**：从资料界面直接导入支持的文件；完成后能打开结果；失败保留可重试路径；不支持的格式明确说明。不得因此扩大文件夹授权范围。

### A06 · 关闭弹窗后重新聚焦输入，仍可能意外收起 — P1

**复现**：输入草稿 → 操作控件／应用 → 打开“新建项目” → Escape 关闭 → 再次打开输入框。组合回归中重新聚焦后文本框仍消失。

**证据**：[composer-focus.spec.ts](../tests/composer-focus.spec.ts) 的“按钮和弹窗不误收起”用例，本轮两次组合回归均在最后的草稿检查处失败。相关实现为 [useExchangeFocus](../apps/web/src/useExchangeFocus.ts)、[useModal](../apps/web/src/useModal.ts)。尚未确认根因，不能归咎于用户操作，也不能因为别的输入测试通过就宣称已解决。

**处理**：追踪焦点恢复、外部点击和延迟收起的真实事件顺序，保证用户最新的展开／输入意图优先。不得通过全局强制固定输入、删除断言或增加任意等待时间掩盖问题。

**验收**：鼠标、快捷键、弹窗关闭和应用 iframe 间切换连续重复执行；没有误收起，草稿和选区保留。真正离开且未固定时仍按规则收起。

### A07 · 通知的“标记已读”失败会阻止打开事项 — P1

**路径**：点击已知事项通知，同时已读状态请求失败。用户不能从该通知打开事项。

**证据**：[Notifications](../apps/web/src/Notifications.tsx) 只有 `change({ action: "read" })` 成功才执行 `onOpen`；失败提示为“通知设置未保存”，也没有准确表达打开事项的意图。源码确认，尚未专门做网络故障注入。

**处理**：将读取已授权事项与保存已读状态解耦；已读失败不阻碍阅读，并提供不打断工作的重试。认证失效或权限撤销仍必须拒绝读取。

**验收**：单独模拟已读状态保存失败，仍能打开授权内事项；网络恢复后补记已读；权限错误不会被当作普通同步错误绕过。

## 应统一执行的交互规则

1. 高频动作出现在对象或项目本身；不要求用户先进入一个隐藏的管理界面。
2. 交付必须可使用：结果在哪里出现，就能从哪里打开。后台执行细节仍按需查看。
3. 进入、退出、返回是完整的一组行为。返回恢复原现场，不改变下一次输入范围以外的执行状态。
4. 控件名称、样式与实际行为一致。链接像链接就应能打开，搜索范围要说清楚。
5. 最新的用户操作优先于旧异步回调；显隐变化不丢草稿，也不重定向后台任务。
6. 权限、发布确认和真实失败不能当作“步骤太多”删除。压缩的是重复入口与多余说明，不是人的控制权。
7. 验收覆盖有内容、失败、迟到回执、键盘和最小桌面窗口，不只检查空态截图。

## 不应回退的已有行为

- 一个持续的默认会话与项目内可选独立会话；对象关联只限定下一次 activation。
- 单一输入、Agent-first 创建、人工直接编辑；新建快捷动作不自行提交。
- 对象版本冲突保护、本地编辑草稿保存与明确放弃确认。[ArtifactEditor](../apps/web/src/ArtifactEditor.tsx) 已有这些保护，不能笼统写成“编辑一定丢失”。
- 紧凑且与内容连续的标题区、不占布局的关键提示、流式消息与独立执行侧栏。
- 浏览器授权、Principal 权限与真实工具回执，不因追求少点一下而绕过。

## 原审计建议的实施顺序

第一批收尾交付路径：A02、A03、A05，并解决 A06 的可复现焦点问题和 A07 的通知打开耦合。目标是“说完以后能拿到、打开并继续使用结果”。

第二批统一导航、检索与状态表达：A04、A08、A09、A13。目标是“知道当前在哪、能找到目标、能回到刚才”。

第三批处理需要明确产品行为的 A10—A12，再进入各认知应用的专业编辑体验。不用这一轮审计重新推倒 Session、对象模型或整套视觉设计。

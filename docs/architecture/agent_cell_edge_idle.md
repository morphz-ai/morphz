# Agent Cell：空闲 Edge 连线与原生休眠

日期：2026-09-09。仅影响显式 hosted Runtime；普通本机/自托管运行不启用
HostRequestGate，也不改变其 Edge 长轮询行为。

## 原因与边界

之前 HostRequestGate 将每次 Edge 心跳和长轮询视为业务活动，并把整个长轮询
响应生命周期计作正在执行；Cloud 又在每次 Node 请求前启动 Container。因此
持续在线但无任务的 Edge 会阻止休眠，或立即唤醒刚退出的计算。

现在只有四种精确 POST 路由属于被动维护：Node challenge、connect、heartbeat、
jobs/claim。它们不延长业务活动时钟；鉴权、证明签名、Node 绑定、Claim CAS
仍由原生 SDK 完成。它们不是只读操作，不能跳过执行保护或伪造成功回执。

已鉴权且领取结果确实为空后，claim handler 才暂停当前 RequestPermit，等待命令
或休眠通知；再次尝试领取前必须恢复 permit。恢复与 begin_park 共用同一把锁，
不能在休眠已开始后继续领取。其他请求、业务预约、响应传输继续保留原有保护。
暂停/恢复重复调用以及响应断开均不能使计数下溢。已存在的 Job、EdgeCommand、
后台进程等原生 quiescence 检查不变，没有清理任务或忽略 owner 来制造空闲。

## Cloud 和设备端协同

Cloud 对上述维护请求不主动启动容器，也不创建业务预约；容器运行时，保留原 Node
凭据和请求体交给原生鉴权。容器停止时返回明确的 503 `edge_runtime_sleeping`
与 `admission=not_accepted`，不是心跳确认、连接令牌、空任务结果或执行成功。
领取后的回执中断仍是 502 / unknown，不改写为睡眠或自动重放业务请求。

Edge 只对精确的休眠/正在休眠响应安静地每两秒重试，仍支持立即停止。401/403、
限流、其他网络错误及未知执行结果保持原失败处理。用户消息、命令结果、Job 心跳、
取消、上传等不属于被动维护，仍走正常唤醒/执行保护；无需修改任何审批权限。

## 验证

- 原生 gate 7 项：互斥、空轮询暂停/重新领取、重复暂停计数、休眠通知、活动时钟、
  业务预约不可降级以及响应体保护。
- Edge 响应解析：503 睡眠不会被解析为成功领取；鉴权和 unknown 不会被吞掉。
- Cloud 路由/传输：维护不唤醒，真实结果仍唤醒；保留 Node 凭据与原请求体，
  去掉伪造内部预约，回执丢失不重放。
- 真实本机 Host + workerd + Edge（两个工作协程）定向门禁通过，40.39 秒：
  连线保持但主机自然退出，持续轮询不启动主机；用户消息恰好唤醒一次，实际
  四秒命令跨过两秒空闲阈值仍存活，完成后再次自然休眠且输出只出现一次。
- 包含此场景的完整 Host/workerd/R2 进程套件 8 项通过（232.54 秒），覆盖
  实际 alarm、入口/休眠竞态、提交回执丢失及空缓存附件恢复；不是仅跑新增用例。
- Cloud 相关 5 个文件的 18 项测试、TypeScript 检查通过；原生 Clippy
  `-D warnings`、格式及默认非 Cloud 特性的库检查通过。
- 原生全库 1,335 项通过、8 项既有跳过。首次在嵌套沙箱且高并发下，9 项
  Seatbelt 测试无法安装沙箱、4 项 Runtime 测试超时；在沙箱外以两个测试线程
  重跑全库后全部通过（124.42 秒），未为此修改或跳过失败测试。

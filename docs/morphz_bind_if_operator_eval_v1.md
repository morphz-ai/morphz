# Morphz `bind` / `if` 算子真实评测 v1

日期：2026-07-13
模型：`gemini-3-flash-agent`
正式报告：`/private/tmp/morphz-sexpr-bind-if-formal-networked/sexpr-bind-if-eval-v1-20260713T052728.054Z-41261/report.json`

## 1. 要回答的问题

这次评测不试图一次证明整个 S 表达式 VM，而是集中回答两个风险最高的问题：

1. 模型能否把真实工具结果绑定到 `bind`，并在后续多轮调用中精确引用 `name.field`？
2. 模型能否根据真实绑定值执行 `if`，只调用被选中的分支？

同时观察自然语言算子定义是否会改善 `seq` 的严格顺序和 `reply` 的最终交付语义。

Runtime 在实验中不解析变量、不替模型选择分支。工具通过标准 Function Calling 调用，工具结果中的不透明 token 不出现在任务表达式里，模型必须读取真实 Observation 才能继续。

## 2. 对照组

### `annotated_kernel`

系统消息整体保持 S 表达式结构，自然语言只放在表达式内部，用于明确 VM 身份、命名过程，以及六个基础算子 `seq/call/fallback/bind/if/reply` 的语义。

其中 `bind` 明确要求：先完整求值、绑定精确结果、用 `name.field` 取字段、不可猜值、每次命名过程调用拥有独立局部作用域。

其中 `if` 明确要求：读取真实绑定值，只求值一个分支，未选分支不得产生调用、绑定或回复。

### `bare_readable`

系统消息只有 `You are a tool-using agent.`，任务 S 表达式和工具与实验组完全相同，不提供算子自然语言定义。

## 3. 测试任务

| 任务 | 压力点 | 重复次数 |
|---|---|---:|
| `binding-chain` | 四级绑定链 A → B → C → D，后一步必须使用前一步返回的精确 token | 3 |
| `repeated-local-scope` | 同一命名过程连续调用 Alpha、Beta、Gamma 三次，内部都使用同名局部绑定 `observed` | 3 |
| `alternating-if-branches` | 四个运行时条件依次为真、假、真、假，只允许调用对应分支 | 3 |

两个提示组各 9 个 episode，共 18 个。每个任务都由确定性验证工具检查具体 token、回执和分支。

## 4. 评分拆分

不能把所有失败笼统归因到 `bind/if`。本评测分别记录：

- `reference-and-branch-accuracy`：工具参数中的绑定值、分支选择、调用集合是否完全正确。
- `causal-dataflow`：消费者调用是否发生在生产者真实结果之后。
- `strict-seq-rounds`：`seq` 中每一个工具调用是否都严格进入后续请求轮次。
- `exact-tool-plan`：工具调用是否与表达式文本顺序完全一致。
- `final-delivery`：最终无工具回复是否包含正确交付值。

`dataflow_success` 只由前两项决定；全语义通过还要求严格 `seq` 和最终交付。

## 6. 观察到的具体行为

两组都完成了以下行为：

- 四级链中的 B、C、D 都引用了前一个工具刚返回的精确 token。
- Alpha、Beta、Gamma 三次过程调用没有混淆同名局部绑定。
- 真、假、真、假四个条件全部选择正确，没有调用未选分支。
- 所有验证工具都收到正确回执，最终交付值也全部正确。

裸组的四次全语义失分都不是绑定或分支错误：它把彼此独立的调用并行批处理了。三次发生在真假交替任务，一次发生在重复局部作用域任务。带定义组则 9/9 严格按 `seq` 从左到右逐步求值。

## 7. 当前结论

在当前深度下，担忧没有复现：Gemini 能在多轮真实工具调用后保持精确引用，能在命名过程重复调用时维持局部作用域，也能根据绑定的布尔值稳定选择唯一分支。

自然语言算子定义没有提高本组样本中已经达到 100% 的 `bind/if` 数据流正确率，但显著提高了求值行为的可预测性：全语义通过从 5/9 提升到 9/9。代价是严格串行带来更多请求轮次；实验组平均轮次比裸组多约 41%。

因此，六个基础算子的自然语言定义应保留。它们不是为了重复模型先验，而是在固定这台 VM 的具体语义。若以后需要合法并行，应增加独立的显式并行算子，而不是让 `seq` 同时承担“严格顺序”和“可优化依赖图”两种含义。

## 8. 结论边界

这仍是初步通过，而不是完备证明：

- 只测试了 Gemini 一个模型、每项三次。
- 最深绑定链为四级，过程复用为三次，条件分支为四次。
- 条件是直接布尔字段，尚未测试嵌套条件、复合谓词和深层字段路径。
- 本轮没有单独覆盖 `fallback` 失败路径，也没有压力测试几十次过程调用后的引用稳定性。

下一阶段适合增加深链、嵌套 `bind/if`、多次局部作用域复用和 `fallback` 的独立算子测试，再决定是否需要语法或 Runtime 层面的辅助。

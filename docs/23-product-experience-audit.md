# 产品流程与视觉体验审计

日期：2026-09-11。基线：`codex/desktop-ux` 的本地提交 `93eb63d` 及用户正在使用的 Morphz 桌面窗口。按当前真实界面逐项讨论，不从空白界面重新设计，也不把已经实现的合理设计包装成新增建议。

用户先要求记录、后明确要求继续正在进行的修复。首轮完成已确认的三项问题，随后按用户指出的归属信息仍独占一行继续修正 S13；其他建议与架构限制继续留档，不能把整个搜索审计标为完成。未提交、推送、合并或发布。

后续用户以实际截图指出“引用并提问”像正文、长句按钮缺少可操作感，以及字体亮度和辅助信息混在一起，明确要求统一处理。本轮因此扩展到共享视觉层与同类动作，而不是再只修搜索的一条间距。实际范围见“统一视觉与操作层级”；未涉及数据库、会话路由或专业应用重建。

## 已达成的产品判断

- 侧栏的职责：帮助用户找到、切换和继续自己的工作，同时看清这些工作的归属。
- 搜索位于主导航上方，已有放大镜、搜索文字和快捷键提示；肯定并保留现有入口，不调整其位置或重做样式。
- 当前搜索面板的位置、宽度、范围选择、自动输入焦点、方向键／Enter／Escape 和返回路径保留。
- 默认列表实际是“最近修改”，不是“最近访问”。二者需求不同，不能未经论证替换。
- 每项评审先记录事实，再说明问题与影响；明确区分已确认缺陷、待讨论建议、架构限制和已验证修复。

## 本轮修复的准确范围

### S01：多关键词

- 按空白分隔、忽略大小写、去重，词之间采用 AND；顺序不影响是否匹配。
- 所有词必须在同一授权对象中出现，可以分布于标题与正文。引号、百分号、下划线、`OR`／`AND` 等仍作为字面内容，不执行用户提供的查询语法。
- 长度至少三个字符且可索引的词通过 FTS5 候选集合求交；短词继续做精确子串检查。全部都是短词时仍会扫描投影表，该性能问题没有被解决。
- 保留标题命中优先、更新时间与对象 ID 的稳定排序，以及准确计数、分页、项目过滤和权限检查。
- PDF 多词允许出现在不同页，但单个词不能跨页拼接；打开页码与引用仍对应某一页的真实原文，不拼造跨页引用。
- 搜索面板和 Agent 对象工具都使用中心的同一检索方法，领域参考实现保持相同语义。

### S02／S03：结果展示与点击

- 无具体来源时，不再显示“工作空间内容”；已有相对路径仍显示，并可打开对应结果。
- 标题、归属、摘要和来源组成同一个原生打开按钮，鼠标和键盘行为一致；不在按钮内嵌套“引用并提问”按钮。
- “引用并提问”保留为独立操作，只准备引用与输入，不自动发送。
- 摘要文字仍可以拖选；拖选释放不打开对象，键盘明确激活仍可以打开。
- 保留摘要 160 个 UTF-16 单元／两行的现有限制，没有额外增加高亮、长预览、筛选器或关闭按钮。

### S13：归属和来源与标题同行

- 最近修改与搜索结果共用标题行：名称在左，所属空间、可用页码与真实来源路径在右，不再占用独立行。摘要仍在下方，独立引用行为不变。
- 元信息最多占标题行 45% 宽度，名称与元信息各自单行省略；长标题、项目名和路径保留完整提示及可访问文字。来源并未删除或改绑。
- 仅修改前端，不更新中心、迁移数据或发送消息。原桌面窗口已通过热更新实测默认列表、“交互 验收”六项结果，以及“reading”的真实 `reading.md` 来源同行。

### 统一视觉与操作层级（S06／S09／S14–S16）

- 搜索：引用变为引号图标加“引用”的 28px 次要按钮，与标题同行、始终可见；不嵌套按钮，不自动发送。对象打开仍覆盖标题、归属与摘要，拖选行为保留。所有结果按相同动作列留位，事项没有引用按钮也不造成归属错列。
- 层级：`--ink` 负责标题与动作，`--text-secondary` 负责摘要／辅助正文，`--muted` 负责归属、版本和计数。内容卡片、项目卡片、通知、文档、事项与来源说明接入同一组角色；不是简单给整页再加一层透明度。
- 表面：搜索、菜单和短弹窗改为稳定实色；半开交流保留原有半透明现场。新中性选择色与普通悬停色区分，不改电光青／鸢尾紫／暖珊瑚／纯单色的品牌配色。
- 操作：内容目录的起草、导入、写文档，项目／事项目录的新建，文档的朗读、版本、编辑、副本／选区提问，事项补充、来源连接，以及弹窗取消／分页使用明确的次要控件规则。选区工具增加提问／批注／朗读图标。导航、筛选和窗口图标不批量套边框；完成与授权等关键后果仍用完整可见文案。
- 摘要：前端选择最早命中词之前最近的句子边界；只移除与当前页一致、非查询目标的尾部 `Page n / m`。超长显示保留省略符并避免切开代理字符对。文件名仅在去扩展名后与标题完全一致时不重复常驻，来源仍在提示与对象详情。后端原始 `quote`、版本、页码及权限不变。
- 范围边界：本轮未补齐表格的匹配单元格摘要、语义高亮、统一项目／对话索引、短词性能和海量存储。搜索高度仍随实际结果变化，不把它扩成固定大空框。不能据此声称整个产品已达到最终审美或完成全部无障碍审计。

真实窗口检查：同一 Electron 与开发中心，检查了搜索的原“测试”四项结果、内容目录、文档阅读、事项列表与详情、导入及已有来源连接，并查看亮暗两种搜索外观。用户开始自行打开《桌面能力验收》后停止手动切页，保留其文档和版本查看，仅将临时亮色恢复到原“跟随系统／电光青”。本轮没有重启中心、采集麦克风、发送输入或改写内容对象。

### S17：从资料操作到 AI 提问入口（已被下述行内方案替代）

## 当前检索底层及容量边界

实现依据：[持久搜索索引](../apps/service/src/search-index.ts)、[领域检索](../packages/core/src/retrieval.ts)、[中心存储](../apps/service/src/store.ts)、[搜索面板](../apps/web/src/LibraryDialogs.tsx)、[摘要处理](../apps/web/src/document-presentation.ts)。

1. 对象最新标题／正文被投影到 `search_object`，原始版本数据与该投影在同一事务中提交；`search_fts` 是外部内容 FTS5 表，由触发器维护。不是每次搜索都解析整份工作空间 JSON。
2. 分词配置为 `tokenize='trigram case_sensitive 1'`，输入和索引文本先转小写。trigram 是连续三字符切片，不理解中文词语边界，也没有拼音、同义词、语义检索或中文词典。
3. 查询先取可索引词的候选，再做字面匹配及 Principal／项目过滤；返回授权范围内的计数、每页最多 50 项（界面默认 20）、原文摘要与可用 PDF 页码。当前不是 BM25 相关性排名。
4. SQLite FTS5 的 trigram 全文 MATCH 无法匹配少于三个 Unicode 字符的词，这是其 tokenizer 边界；当前短词通过 SQL `instr` 扫描保持正确性，而非已有高效中文短词索引。[SQLite FTS5 官方说明](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)
5. PostgreSQL 原生提供 `tsvector`／`tsquery` 全文检索及 GIN 等索引，也有 `pg_trgm` 的三字符相似度与子串索引能力；这些不是本应用已经接好的能力，换数据库也不能自动等同于完成中文分词。[全文查询控制](https://www.postgresql.org/docs/current/textsearch-controls.html)、[全文索引类型](https://www.postgresql.org/docs/current/textsearch-indexes.html)、[pg_trgm](https://www.postgresql.org/docs/current/pgtrgm.html)

工程判断：当前属于可工作的 SQLite 内容搜索，不是已经验收的海量中文知识库方案。本轮没有大量文档基准，不承诺支持十万／百万文档或特定延迟。

后续架构评审需要确定统一的中文分词与查询语义、短词及子串策略、SQLite／PostgreSQL 搜索适配边界、对象与版本按需读取、增量索引、排序／分页方式与权限一致性。之后用不同数量和长度的中文文档、短词／长词／多词、冷热缓存及并发读写做基准，再给容量结论；本轮不擅自迁移数据库或安装新分词依赖。

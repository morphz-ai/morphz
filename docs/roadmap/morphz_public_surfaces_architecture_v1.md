# Morphz 公开产品界面与主站架构 v1

> 状态：执行基线  
> 日期：2026-09-02  
> 适用范围：技术主站、独立人格站、后续 C 端 Agent 产品与 Cloud/SaaS 的边界

## 1. 结论

Morphz 的公开界面由同一技术内核衍生，但承担不同任务。它们共享品牌与事实来源，不共享产品工作流。

| 公开界面 | 域名 | 核心任务 | 代码归属 |
|---|---|---|---|
| 技术主站 | `morphz.ai` | 解释计算模型，发布文章、论文、源码、文档与安装入口 | 当前仓库 `website/` |
| 独立人格站 | `chat.morphz.ai` | 展示官方 Morphz 人格的状态、活动与公开交互 | 独立站点项目 |
| C 端 Agent 产品 | 待定 | 让登录用户运营一个自己的 Agent，并接入自己的执行节点 | 后续独立产品界面 |
| Cloud / SaaS | 待定 | 为个人或组织创建、托管和管理 Agent Runtime | 后续独立服务 |

技术主站是产品定义和证据的权威入口。独立人格站是一个运行实例，不是 Morphz 的全部产品；未来 C 端产品和 SaaS 也不能反过来改写 Runtime 的技术定义。

## 2. 技术主站的信息架构

主站一级入口固定为：

1. **文章**：`From Chat Completion to Structured Context Evaluation`，面向最广泛的技术受众解释计算模型；
2. **论文**：双语预印本、研究问题、贡献边界和实验记录；
3. **文档**：只描述当前实现可验证的行为；
4. **下载**：macOS、Linux 和原生 Windows 的安装与源码构建路径；
5. **源码**：GitHub 权威实现。

`chat.morphz.ai` 以“实时人格”的独立外链出现。它不进入安装流程，也不与用户私有 Agent 共用名称或页面状态。

## 3. 发布节奏

### 第一阶段：技术产品

同一节奏发布文章、论文、源码、预编译版本、TUI、Dashboard 和技术主站。目标是先让技术领域用户理解、复现、检查并反馈计算模型。

### 第二阶段：官方人格

独立发布 `chat.morphz.ai`。人格站持续展示活动与状态，成为 Morphz 的公开运行实例，但不承担个人 Agent 创建流程。

### 第三阶段：用户产品与服务

个人 Agent 产品和企业 Cloud/SaaS 根据验证结果分别推进。二者共享 Runtime 能力，但各自拥有身份、计费、租户、数据和运维契约。

## 4. 代码边界

- `website/` 不依赖人格站后端、个人 Agent API 或 Cloud 控制面才能构建；
- 主站的文章、论文与公开文档可以单独部署和长期引用；
- Dashboard 继续内嵌于 Runtime，面向运行时操作，不被主站复制成一套低层控制界面；
- 站点之间通过稳定 URL 连接，不通过复制组件和业务状态形成隐式耦合；
- 主站中的未来能力必须显式标注状态，不能用产品文案代替已经交付的行为。

## 5. 视觉关系

技术主站使用结构化求值、运行时边界、因果路径和证据索引作为视觉语法。独立人格站可以拥有更强的时间感、活动感和人格表达，但不复制主站页面，也不把通用聊天界面当作品牌核心。

二者允许共享：标志、基础字体、结构线、状态色和运动原则。二者不共享：导航结构、核心任务、会话状态和产品入口。

## 6. 验收条件

- 访客在主站首屏和导航中能找到文章、论文、文档、下载与源码；
- Windows 被表述为原生支持，WSL 只作为可选路径；
- 论文中英文 PDF 具有稳定的站内 URL；
- 主站链接独立人格站，但不会出现“创建我的 Agent”等 C 端流程；
- 删除公开设计实验和已经放弃的混合页面；
- 中英文路由、构建、内容测试、lint 和 CI 全部通过；
- Persona、Cloud 或 C 端服务不可用时，技术主站仍可完整构建和阅读。

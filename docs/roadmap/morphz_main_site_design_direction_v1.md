# Morphz 主站视觉与交互方向 v1

> 状态：历史视觉研究；信息结构仍有效，视觉层已由 v2 实现取代
> 日期：2026-08-26  
> 适用范围：`website/` 技术主站、文档、技术文章；独立人格站共享设计基因，但保持人格语域

> 2026-09-02 更新：本文确立的 Context Evaluation Field、论证顺序、证据路径与可访问性要求继续有效；“纸与石墨”的具体配色和第 6 节的视觉排除项不再是当前实现约束。现行主站采用深色、动态但仍有语义约束的技术叙事。产品边界与域名职责以 [`morphz_public_surfaces_architecture_v1.md`](./morphz_public_surfaces_architecture_v1.md) 为准。

## 1. 目标

主站必须让访客先感知到 Morphz 是一种不同的计算模型，再阅读功能说明。视觉优化的目标不是“更像一家成熟 AI 公司”，而是消除通用 AI SaaS 模板感，建立只有结构化上下文求值才成立的页面语言。

核心判断标准：隐藏 Logo 和产品名后，页面仍然存在可以辨认为 Morphz 的结构与交互。

## 2. 参考站带来的启发

DeepSeek Harness 的有效之处不在蓝色、玻璃效果或终端框，而在于：

1. 首屏用具有物理质感的主视觉建立记忆，而不是用抽象渐变填空；
2. 页面按章节导演滚动节奏，标题、说明和产品证据轮流成为主角；
3. 产品截图直接承担可信度，不让功能卡片代替证据；
4. 字体、像素标签、悬浮导航和图像材质服从同一个产品世界观；
5. 每屏只讲一个命题，留白不是空缺，而是叙事节拍。

Morphz 不复制其流体背景、蓝色体系、玻璃导航、像素字或页面构图。参考站只用于确认：一个开发者产品网站可以同时保持技术清晰和强烈个性。

## 3. 现状问题

- 左侧大标题、双 CTA、右侧终端卡片是高频 AI 产品首屏模板；
- 青色、紫色、珊瑚渐变和发光圆形没有产品语义；
- 三张特性卡与四步流程主要在“介绍功能”，没有展示计算模型；
- 所有内容被装进相似圆角容器，信息层级依赖卡片数量而不是版式；
- 首页、文档和技术文章只是共用颜色，没有形成完整的出版与仪器语言；
- 访客看不到 Context、Session、Evaluation 和持久状态之间的关系。

## 4. 选定方向：Living Specification

主站被设计成一份正在运行的技术规范：既有论文与标准文档的克制排版，又有仪器界面的实时状态。页面不是“关于 Morphz 的营销展板”，而是 Morphz 计算模型的一次可视化投影。

### 4.1 视觉基因

- **纸与石墨**：温暖的浅色底、接近印刷墨色的正文，摆脱默认深色 AI 控制台；
- **信号色**：只保留一种朱红状态色和一种钴蓝结构色，分别表达状态变化与结构引用；
- **结构线**：页面网格、章节编号、因果连线和边界标记都承担语义；
- **编辑式排版**：大标题和正文以出版节奏组织，不用连续卡片填满空间；
- **等宽注释**：仅用于状态、算子、标识符和证据标签，不把整站做成终端；
- **不对称留白**：让章节像论证推进，而不是组件目录。

### 4.2 标志性交互：Context Evaluation Field

首屏展示一个结构化上下文求值场：

```text
Session input → Context selection → evaluate → durable state
```

它必须呈现以下语义：

- 消息只是输入事件，不等于 Context；
- Frame、Objective 和 Recall 以结构节点进入求值；
- 模型产生非确定性语义结果；
- Runtime 验证并提交新的持久状态；
- Session 可以变化，Context 身份保持连续。

动画只用于表示求值路径和状态提交。关闭动画后，静态图仍然可以被理解。

## 5. 页面结构

### 5.1 首页

1. **首屏**：中心命题、发布状态、五个正式入口、Context Evaluation Field；
2. **计算边界**：模型与 Runtime 各自负责什么；
3. **一次求值**：用单一横向轨迹解释输入、选择、求值、提交与延续；
4. **可验证现象**：跨 Session、并发隔离、恢复三个可观察结果；
5. **论文与文章**：Idea、Paper 和 Source 的证据路径；
6. **Quick Start**：保留真实命令，但不再伪装成悬浮终端产品卡；
7. **Preview 边界**：明确 Developer Preview 和 Experimental 能力。

### 5.2 文档

- 保留高密度导航，但改为规范文档的章节索引语言；
- 当前页、状态、来源和版本成为一等信息；
- 减少圆角容器，使用分隔线、边注和清晰的文本列；
- 代码、表格、引用与状态标签使用同一语义色体系。

### 5.3 技术文章

- 采用独立出版物版式，增强标题、摘要、作者、日期和目录的节奏；
- 正文保持长文阅读舒适度，不把营销组件插入论证；
- 关键公式、定义和反例具有稳定的可引用视觉格式。

## 6. 不采用的手段

- 蓝紫渐变、发光球体、随机粒子、网格宇宙背景；
- 为每项功能创建一张圆角卡片；
- 用机器人、大脑、神经网络或魔法光束作为主视觉；
- 没有信息含义的滚动视差和 3D 倾斜；
- 只在首屏放一句宏大口号，产品证据藏到页面末尾；
- 为制造“高级感”牺牲中文排版、可访问性或页面性能。

## 7. 实现门槛

- 桌面、13–16 英寸笔记本、平板与手机均无横向溢出；
- 内容最大宽度稳定，宽屏不无限拉伸；
- `prefers-reduced-motion` 下关闭非必要运动；
- 键盘焦点清晰，文本与状态色满足可读对比；
- 首屏不依赖大体积视频或图片才能成立；
- JavaScript 不可用时，核心叙事和结构图仍可阅读；
- 中英文保持相同的信息层级，而不是逐像素强行同宽；
- 构建、HTML 路由测试和 lint 全部通过。

## 8. 与独立人格站的关系

技术主站是“可审计的机器说明”，独立人格站是“同一台机器对外生活的界面”。二者共享：

- 石墨、纸张、结构蓝与状态红；
- Context/Thread 的线与节点语言；
- 清晰的状态与来源标记；
- 克制、非拟物的动效规律。

独立人格站可以更有情绪和时间感，但不能重新退回常见聊天机器人视觉；技术主站也不能借人格表达替代证据。

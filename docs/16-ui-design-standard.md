# Morphz UI 设计规范与优化方案

状态：已采纳的设计基线，公共 UI 首轮已实施。下文同时保留完整目标与初次审计；不表示每个目标都已实现。实际完成范围见本文末尾与实施记录。界面对外使用 Morphz，MorphzWork 继续作为工程项目名。

## 1. 规范依据与适用范围

以 Apple Human Interface Guidelines（HIG）作为当前桌面体验的主要依据，用 W3C 的键盘、焦点和可访问性要求补充 Electron/Web 的实现规则。官方规范解决平台惯例，Morphz 的产品原则解决工作如何组织；不能把自己的交互设想或像素值说成 Apple 的规定。

已经核对的官方依据：

- [Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)：利用桌面空间、减少不必要的层级与模态打断，支持键盘、窗口调整和持续工作。
- [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：按当前内容选择和分组动作，定义窗口变窄时的收纳顺序。
- [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)：导航的层次、显隐、空间适配与可定制性。
- [Modality](https://developer.apple.com/design/human-interface-guidelines/modality)：只有明确收益才采用模态，任务应清楚、简短，避免多层弹窗，并保护未保存内容。
- [Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields)：明确搜索范围、及时反馈、简化结果，并提供适当的范围筛选。
- [WAI-ARIA APG：Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：打开后的焦点、模态内 Tab 循环、Escape 和关闭后的焦点返回。
- [WCAG 2.2：文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：文字可读性和控件可操作性。

HIG 不要求跨平台应用照搬所有 Apple 材质。当前使用 Electron，保留真实系统窗口控制、系统字体及平台快捷键，不绘制假系统窗口按钮，也不把 CSS 模糊效果宣称为原生 Liquid Glass。未来其他平台遵守各自惯例，共享产品语义，不强求像素一致。

本文件是 UI 优化的目标规范；与早期界面草案冲突时，以这里的设计原则为准。实际已实现情况仍看 [实施记录](./13-implementation-status.md)，应用宿主协议仍看 [应用与工作空间](./15-cognitive-application-host.md)。

## 2. 产品原则：围绕工作，而不是围绕会话

### 2.1 工作和对象是组织单位

用户来到 Morphz，是为了写作、开发、阅读、处理事项或继续思考。输入是参与工作的方式，消息是交流记录，Artifacts 是可继续使用、编辑、关联的工作对象。普通交流也可以只留下消息，不强迫每句话变成事项或文档。

不提供“新建对话”入口，不要求先建立聊天才能开始工作。默认不设置独立“聊天”导航、最近聊天首页或聊天管理页。完整消息记录仍然保留、同步、可查找；隐藏 Session 不等于隐藏交流过程。

### 2.2 能力对应的体验

| Morphz 能力与产品关系 | 用户的真实需求 | UI 必须体现的结果 |
| --- | --- | --- |
| 一个持续的 Agent，在授权范围内共享认知 | 换工作现场不想反复解释背景 | 切空间自动接续；不展示重置记忆或切换 Agent 的假象 |
| 空间级 Session | 不同工作的交流不能混杂 | 工作台、各项目、事项有自己的记录；Session 不进入导航 |
| 多条工作并发推进 | 等待一项工作时继续做其他事 | 新输入仍可用，进度归到具体工作；停止一项不停止全部 |
| Human 与 Agent 都是 Actant | 人能主动创作，也能接到 Agent 的安排 | 事项与对象按能力提供直接操作，不把所有事都变成“让 AI 帮我” |
| Artifacts 与版本、关联关系 | 找到真正的文件、结果、来源和后续工作 | 消息中的交付能打开对象；人编辑后 Agent 使用正确版本，不只显示文本副本 |
| 认知应用有可选的平台界面 | 不同工作需要不同工具 | 应用决定主体界面，宿主保持导航、权限和输入的一致性 |
| 中心与 Edge 分离 | 关窗口、切应用不应中断后台工作 | 界面显隐不等于运行启停；状态、任务和消息以中心回执为准 |

共享认知始终受 Principal 和工作空间授权约束；“同一个 Agent”不意味着任何人或应用能读取所有资料。

### 2.3 元素取舍规则

每个常驻元素都应回答：它帮助用户在当前场景完成什么？使用频率如何？离开这一层以后还能从哪里找到？

- 高频且属于当前场景：直接可见。
- 低频但必要：放进相关对象菜单、检查器或设置，不散布于所有页面。
- 当前不可用：优先不显示；若用户确实需要知道缺了什么能力，显示原因和恢复方式。
- 只是重复说明、开发诊断或占位：移出日常界面，不用装饰填满空间。

减少元素不能以隐藏失败、未发送、权限限制或人的待办为代价。

## 3. 窗口与页面职责

主窗口采用稳定的三层关系：侧栏选择工作范围，主区呈现应用或对象，居中的输入与交流区域供人参与。对象检查器按需出现，不默认再加一个聊天侧栏。

### 3.1 侧栏和顶栏

- 侧栏保留搜索、事项、工作台、项目，以及用户固定或近期使用的项目。项目导航可以在侧栏直达，项目目录负责搜索和管理大量项目，不重复堆两份完整列表。
- 最近对象移到快速打开或相应空间；不在侧栏长期混排对象、会话和运行日志。
- 人与中心入口置于侧栏底部；等待人处理的重要事项不能只藏在底部的通知图标里。
- 顶栏保留位置、导航及当前内容的少量主要动作。安装应用归应用管理，导入归目标空间，外观归设置，“当前理解”归空间详情，执行日志归对应工作详情。
- 移除常驻的“内容／对话”一级视图切换。输入与交流属于当前工作空间，不是与工作区争夺入口的另一个产品。
- 层级只在有信息时出现：位置已在顶栏说明，就不在主体重复三次标题和一句欢迎语。应用页签只有在存在应用或需要切换时占用空间。

### 3.2 页面清单

| 页面 | 核心问题 | 应当存在 | 应当移走或删除 |
| --- | --- | --- | --- |
| 工作台 | 此刻要开始或继续什么工作？ | 可启动的应用、已打开应用、当前成果、AI 输入；有内容时可保存为项目 | 跨项目统计大屏、最近聊天入口、强迫选应用后才能输入、重复的开场说明 |
| 项目目录 | 去哪个项目？ | 搜索、排序、固定项目、新建项目、必要的状态摘要 | 文档编辑器、所有项目的混合消息列表、默认展开的大段运行日志 |
| 项目工作空间 | 如何推进这项工作？ | 项目身份、已打开应用、应用自定义主体界面、当前对象及交流 | 把每个项目都固定成通用文件卡片页；用欢迎区挤压工作画布 |
| 事项 | 谁需要做什么，什么时候做，接下来会发生什么？ | 待我处理、进行中、等待、已完成等筛选；负责人、时间、优先级、交付入口 | 消息已读冒充事项完成；只按最新消息排序；所有日志默认摊开 |
| 应用／对象 | 如何阅读、修改或使用它？ | 应用专属工具、主体内容、必要的关联与版本入口 | 同一批通用“新建”按钮覆盖所有场景；每开对象再建一个聊天 |

纯讨论可以直接在工作台输入，不先命名项目、不安装应用、不强迫生成文档。选择应用可以由用户完成，也可以由 Agent 在已安装且授权的范围内建议或打开，界面要说明实际发生了什么。

项目目录不是新 Session。保留每页 AI 输入的约定，但在目录中明确显示“工作台”，不要静默沿用上一个项目的发送目标。事项中的一般交流属于事项空间；针对具体工作回应或调整时，操作需携带来源工作标识，并明确作用对象。

## 4. 输入框与消息列表：一个交互区域，不另造聊天入口

以下规定输入区的目标行为。基础展开、隐藏、历史和滚动已实施；定向跟进等涉及执行路由的目标仍需后续实现。

### 4.1 位置和状态

主区底部保留横向居中的输入区，与回复阅读列对齐。它采用正常布局占位，不能盖住视频时间线、编辑器末行或网页的提交按钮。应用主体可使用全宽，不被消息阅读宽度限制。

输入区可以从“仅输入”向上展开“当前交流”，也可由用户主动扩大为完整记录。完整记录是当前空间交流区的展开态，不是新页面、新会话或一个新的左侧导航项。展开和收起不卸载当前应用，也不清除编辑状态。

| 用户动作或事件 | 交互规则 |
| --- | --- |
| 空间没有交流 | 保留简洁输入，空白区域不放巨大的“开始聊天”占位 |
| 开始输入 | 不切页面、不打开空消息列表；保留编辑选区和明确引用 |
| 提交输入 | 就近显示这次输入和发送状态；正常内容视图中显示紧凑交流区域，不直接替换整个应用 |
| Agent 回复 | 在同一区域接续；交付以对象链接或卡片呈现，用户可打开；不自动抢占用户正编辑的对象 |
| 用户希望深入讨论或回看 | 从交流区展开完整记录，可按相关工作查看，之后恢复原内容位置 |
| Cmd+J / Ctrl+J | 保留显示／隐藏输入区域的约定；隐藏前保存草稿，恢复原对象焦点；后台工作不停止 |
| 用户主动收起交流 | 新回复通过未读和状态提示告知，不擅自重新展开 |
| 切换项目或事项 | 恢复目标空间的输入与消息位置，原空间继续执行；迟到回复不抢回界面 |
| 打开同空间其他应用／对象 | Session 不变；草稿、明确引用和应用关联分别恢复，不把旧选区带到新对象 |

输入隐藏后提供一个轻量“显示输入”控件和“显示”菜单命令，快捷键不是唯一发现方式。这是输入区域的显隐控制，不是“聊天入口”。只有实际评审表明完整记录无法被发现时，才重新讨论是否需要独立入口；不预先添加。

“仅输入／当前交流／完整记录”是布局状态，不是三套消息数据。应由一个明确的状态模型管理，而不是多个互不约束的布尔值。

### 4.2 作用范围与引用

- 输入附近展示有意义的空间／对象名称，不把 Harness、Session ID 或协议状态堆给用户。
- 当前可见对象不等于已经允许读取该对象的全部私密数据；实际上下文提交遵守授权与引用规则。
- 选区、PDF 页码、对象版本和附件以可查看、可移除的引用呈现。发送时固定实际提交的引用，后续翻页不能改变已发送请求。
- 模型可调整，但模型不是另一个 Agent 身份。默认值属于空间或应用策略，运行中变更必须说明影响哪项工作及何时生效。
- 输入框的可见高度上限是布局约束，不是文本长度、录音时长或可阅读书籍的业务上限。

### 4.3 并发、跟进和消息组织

不能只把所有并发输出按时间交错铺开，再显示“正在处理三条消息”。用户需要知道每条进度和结果属于哪项工作。

- 按输入／事项／执行链建立明确关联。同一项工作的进度可折叠，最终结果突出；完整交流的顺序仍保留。
- “另做一项工作”与“补充正在进行的工作”必须区分。支持从具体工作附近发起补充，输入处显示跟进目标；多个任务并发且指代不清时轻量澄清，不静默猜测。
- 默认不要求用户理解线程或调度策略，也不能把所有输入一律当作独立并发任务。
- 单项停止、取消排队和失败重试放在该项旁边；全局停止必须另行明确。重试不能重复已发生的外部操作。
- 当前回复协议缺少显式输入／执行链关联，需要先补充可靠标识，再做分组；不能通过回复到达时间猜归属。

### 4.4 滚动与回执

用户在最新位置时跟随回复；向上阅读后保持当前位置，显示“有新内容”并允许返回。只有用户主动发送、展开或点击返回最新时，才按明确规则定位对应内容。后台其他任务输出不能强制滚动当前阅读区。

区分已保存未发送、发送中、已接收／排队、执行中、等待人、完成、失败和已请求停止。状态依据真实回执；短暂提示不代替持久状态。人类的回应、拒绝、修改和交付也显示署名及其实际影响。

## 5. 弹窗、搜索与检查器

### 5.1 按用途选择容器

| 用途 | 容器 | 原因 |
| --- | --- | --- |
| 搜索并打开内容 | 快速搜索面板 | 输入和结果是主体，不是表单填写 |
| 改名、保存为项目、简短确认 | 小型对话框 | 有明确开始和结束的单一动作 |
| 模型、排序、外观的少量选项 | 菜单或锚定弹出层 | 保留选择发生的位置 |
| 批注、关联、属性、当前理解 | 对象／空间检查器 | 需要边看内容边操作，不宜遮住内容 |
| 导入多个文件、接入来源 | 明确的导入流程；长任务进度可留在工作区 | 关闭界面不应让人不确定导入是否继续 |
| 写文章、编辑小说、剪视频 | 应用主画布 | 长时间创作需要空间，不能装进“新建文档”表单 |
| 重要授权或不可逆动作 | 范围明确的确认对话框 | 明确由谁、对什么、允许做什么，保留取消方式 |

同一时刻一个主要模态任务。不要在搜索上叠导入、再叠编辑；先完成或退出当前步骤。标题说明任务，主按钮描述动作，避免所有按钮都叫“确定”。

### 5.2 搜索面板

- Cmd+K 或可见搜索入口打开，焦点必须进入输入框，不能落在关闭按钮。
- 搜索框置于面板最上方；不要先用大标题和大段说明挤占空间。范围筛选采用紧凑控件。
- 全局搜索默认显示全部有权访问的内容；局部搜索明确标出当前范围，两者不混淆。
- 空查询显示少量最近打开或搜索记录；尚无数据时提供简洁引导，不造假结果。
- 边输入边反馈；结果优先显示名称、类型、所属空间及必要摘要。版本、技术来源等细节按需展开，不给每条结果套一张大卡片。
- 上下键选择、Enter 打开、Escape 返回原位置。打开结果进入正确空间与对象；“引用”必须说明将放入哪个输入，不能暗中改变发送范围。
- 搜索失败不显示成零结果。请求竞态、输入法候选确认、翻页及范围变更均有测试。
- 未来项目、应用、对象、事项可以统一检索，但当前未接入的类型不在占位文字里声称支持。

### 5.3 焦点与取消

依据 [WAI-ARIA Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)，真正的模态需要聚焦内部、约束 Tab 路径、提供关闭操作，并在退出后恢复触发位置或合理的下一操作位置。仅声明 `aria-modal` 不算完成。

关闭搜索应返回原输入焦点、编辑选区和滚动位置。关闭有未保存内容的界面，应保存草稿或明确提示；不能无声丢弃。录音与设备采集必须始终有清晰状态和停止能力，界面收起的行为不能让用户误以为已停止但仍在采集。

## 6. 视觉与布局基线

以下是 Morphz 的首版工程基线，不是 Apple 规定的尺寸。必须在真实桌面窗口里验证；用户缩放、文本长度、窗口大小和专业应用需求优先于固定像素。

| 项目 | 建议基线 | 约束 |
| --- | --- | --- |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 CSS px | 用共享 token，不逐页凑数字 |
| 导航侧栏 | 默认 280，可调约 240–360 | 空间不足可收起；不持续挤窄字体和内容 |
| 顶部工具栏 | 约 48–56 高，加平台安全区域 | 避让真实系统窗口控件；次要动作按顺序收纳 |
| 列表行 | 约 36–44 高，按内容适配 | 不靠加大外边距冒充舒适；多行摘要另用内容行 |
| 文字 | 系统字体；导航／控件约 13–14，正文 15–16，标题 20–24 | 辅助文字通常不低于 12；长文、代码由应用设定阅读排版 |
| 消息与输入阅读列 | 最大约 760，左右至少 24 留白 | 随可用空间收缩；专业画布可全宽 |
| 快速搜索 | 默认约 640 宽，最大不超过窗口减 48；上方约留 12–18% 窗口高度 | 初始紧凑，结果增长时上边缘稳定；最大高度约 65% 可用高度，内部滚动 |
| 简短对话框 | 约 400–480 宽；中型约 560–640 | 高度由内容决定，不强行所有弹窗同一比例 |
| 检查器 | 约 300–360，可收起 | 在窄窗口只展示必要辅助区，不同时挤入多个面板 |
| 图标／点击区域 | 图标通常 16–20，常用图标按钮点击区域至少 32×32 | 图形大小和点击面积分开；兼顾键盘和触控 |
| 圆角 | 控件约 6–8，面板约 12 | 由层级决定，不为每个图标再画一个圆角框 |

展开交流时先按主区约三分之一高度验证，允许调整；当主内容没有足够空间时，不硬塞三层窄区，而由用户选择交流的聚焦态，并能准确回到原应用。窗口 760×540 的现有桌面下限也必须覆盖；不能只验证大屏截图。

### 6.1 颜色与材质

保持 Dashboard 四组主题：电光青、鸢尾紫、暖珊瑚、纯单色。复用实际主题 token，亮暗分别检查，不凭截图重新取一个“类似的青色”。中性背景、清晰层次、少量强调色；不把全页染成品牌色，不靠大面积玻璃、阴影或渐变增加装饰。

当前主题源是 `apps/web/src/styles.css`，后续抽取为共享设计 token；不要在认知应用中各自复制一套宿主配色。危险、警告、成功有独立语义，不随品牌主题变成任意颜色。正常连接和自动保存不必长期占据整条状态栏；异常与尚未同步必须清楚可见。

普通文字以 WCAG AA 的 4.5:1、大号文字 3:1 为检查基线，包含辅助说明与占位文字；不能为了“高级灰”让信息难读。控件目标按 WCAG 2.2 的 24×24 CSS px 或相应间距／例外要求检查，Morphz 常用图标按钮采用更宽裕的 32×32 基线。不能把桌面一律写成 Apple 要求 44×44。[对比度依据](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；[目标尺寸依据](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

### 6.2 文案与可访问性

- 面向用户统一使用自然中文：事项、项目、工作台、资料、引用、执行记录。保留 Morphz 品牌和用户选择的模型名；不混排无必要的 Inbox、Workspace 等英文菜单。
- 控件有明确可访问名称、键盘路径及可见焦点。图标提示不是无障碍名称的替代品，关键行为也不能只有 hover 才可发现。
- 应用启动支持双击与键盘 Enter；选中、已打开、正在运行和等待处理是不同状态。
- 正文与控件支持缩放。长文或代码的横向滚动只发生在内容区，导航与普通表单不产生整页溢出。
- 状态变化不能只靠颜色。流式输出不要每个 token 都打断读屏，使用合适的状态播报粒度。
- 遵守系统减少动态效果偏好；交互不能依赖动画结束。这里只约束原则，本轮不新增品牌动画。

## 7. 认知应用界面的共同契约

GUI 是可选、可按平台适配的界面扩展。当前格式仍是 MorphzWork 实验扩展，成熟后再讨论纳入 Morphz 标准；本轮 UI 优化不修改 HNS 标准。

宿主统一导航、空间身份、主题 token、输入与交流、权限确认、错误与异步状态。应用自主决定工作画布和领域工具，例如章节、大纲、Git、时间线。主题接入不强制所有专业应用长得一样。

领域内容和运行状态属于中心或授权的对象存储；选区、面板尺寸、滚动和布局属于视图状态。关闭界面不取消已提交的任务，安装或打开界面不授予额外权限。人可以直接编辑，Agent 的修改需基于有效版本；冲突有可理解的处理路径。

专业编辑器替换可以逐项推进，但禁止宿主层再次建立“所有内容都用一个弹窗文本框编辑”的惯例。

## 9. 实施顺序与交付方式

### 第一轮：工作现场与交流的关系

覆盖空间导航、输入／交流状态、草稿和选区、消息回执、并发来源、未读与滚动。先补所需数据关联，再改界面；不要仅隐藏对话按钮，留下旧的发送跳转逻辑。首轮同时包含无消息、生成中、并发、失败、跨空间和恢复场景。

### 第二轮：窗口层级与公共组件

统一设计 token、顶栏和侧栏规则；提取搜索面板、短对话框、检查器、菜单、异步状态的公共组件。搜索先作为公共层代表完成；之后所有弹窗按用途迁移，不继续各写一份 CSS。公共层必须覆盖不同长度、错误、空态和键盘，不只做漂亮的空弹窗。

### 第三轮：页面减法与对象协作

逐项检查工作台、项目目录、项目空间、事项、资料与对象详情。按页面职责表删掉重复内容，保留真实操作。事项分派、回应、时间／优先级、模型调整和版本冲突是工作体验的一部分，不藏进日志。

### 第四轮：专业应用逐项打磨

在稳定宿主上分别处理写作、代码、阅读、剪辑等应用。不是本轮一次承诺做完所有编辑器；选择已经具备基础的应用先完成真实使用体验，其他应用保留明确的未实现边界。

每轮交付：简短变更清单、对应状态的截图、真实 Electron 验证和自动化结果、未解决项。由实施者完成逐页检查，不要求用户把每个缺陷都列出来；用户主要评审交互选择与整体感受。不以一个孤立模拟流程替代真实应用，也不把临时半成品作为完整交付。

## 10. 验收清单

- [ ] 无新建对话入口，无独立聊天一级导航；用户仍能找到、阅读和检索完整交流记录。
- [ ] 任意工作页面都能调用输入；输入目标明确，选区、附件、草稿、版本不串空间。
- [ ] 边编辑边发送不丢光标、内容或位置；回复不自动替换正在编辑的对象。
- [ ] 两项并发工作可以分别跟进、停止和重试；状态归属可靠，旧消息不被猜测性绑定。
- [ ] 用户向上阅读时新消息不拉走页面；切空间后迟到回复不抢焦点。
- [ ] 搜索输入自动获得焦点；上下键、Enter、Escape、输入法和退出焦点返回正确。
- [ ] 搜索具备空查询、结果、无结果、失败、范围切换、大量结果和长标题状态。
- [ ] 弹窗外部不可交互时才使用模态；不能 Tab 逃逸，不能关闭后丢草稿。
- [ ] 桌面 760×540、1024×768、1380×920 和较大窗口均可用；200% 缩放下关键操作仍可达。
- [ ] 四主题的亮／暗模式均检查实际对比度、焦点、选中和禁用状态。
- [ ] 事项能完整表达 Human → Agent 与 Agent → Human；已读不等于已处理。
- [ ] 保存为项目保留原空间工作，打开新工作台不重放任务；关闭应用与后台执行相互独立。
- [ ] 开发术语、示例说明和调试控件不进入正常页面；未实现能力不以假按钮代替。

上述清单是完整目标，未逐项宣称全部验收。尺寸与交流区默认展开程度属于可调整的设计参数，不能用“规范规定”阻止后续根据实际使用修正。

## 11. 公共 UI 首轮落地

已实施并有回归覆盖：

- `hidden / input / recent / history` 为同一交流区的四种布局状态，按工作空间保存。移除顶栏内容／对话切换；发送就地展开紧凑交流，完整记录由用户主动展开。应用保持挂载，正常显示输入时不抢占主体。
- 交流阅读位置按空间保留；追随最新、向上阅读、未读提示和主动返回最新分开。用户收起后，迟到的发送回执不重新打开界面。回复带真实 `inputId/rootId`；无来源的旧记录、没有唯一归属的合并回复不猜测绑定。
- 搜索独立为快速打开面板，默认聚焦输入，空查询显示最近修改的授权对象；支持上下键、回车和 Escape。共享模态钩子恢复触发焦点与编辑选区，菜单关闭后回到菜单触发器。
- 顶栏将导入与当前理解收入空间菜单；批注只在对象存在时显示；移除侧栏最近对象与未使用的旧 Workbench。正常连接不再常驻整条状态栏，操作回执与断线状态仍可见。
- 文档创建移到主画布，文档草稿按中心、身份、窗口、空间保存；取消、切换与刷新后可以继续。项目等短动作继续采用小型对话框；不将当前 Markdown 文本编辑器称为专业写作应用。
- 事项有待我处理、进行中、等待、已完成、全部筛选，显示负责人、优先级和截止时间；项目目录有名称／最近更新排序与区分查询无结果的空态。
- 新的公共样式层集中阅读宽度、间距、圆角、搜索与弹窗布局。四个品牌强调色不变；小字和主要按钮使用可读性更高的既有深色阶，中性辅助文字提高对比度。

尚未实施的目标明确留待后续，不做假入口：运行中工作的定向补充／线程路由、完整消息全文检索、可拖拽交流高度和侧栏宽度、固定项目、将当前理解改为非模态检查器，以及专业写作／代码／剪辑界面。当前普通输入仍沿用已有 Runtime 并行发送策略；本轮的消息归组不等于已实现定向 steering。

规范不止存放在文档中：仓库 `AGENTS.md` 要求后续 UI 改动先读取本规范与实施记录，避免旧导航和弹窗习惯回流。

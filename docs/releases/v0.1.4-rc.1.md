# Morphz v0.1.4-rc.1

This is a **release candidate**, not a stable release. It is intended for
explicitly opted-in evaluation of the changes since v0.1.3. The default stable
installation and update paths must continue to use the latest stable release.

This tag distributes Morphz Runtime and morphz-edge, not a separately versioned
Desktop application or a hosted Cloud service. Related application fixes are
included in the source branch but are not a Desktop installer in these assets.

## Task and model reliability

- Preserve ordinary chat as plain text through native Session IO. Native work
  calls keep their actual tool schemas and execution receipts; no mandatory
  JSON envelope is imposed on ordinary conversation.
- When response annotations are enabled, strongly request useful work titles,
  intent and progress, but tolerate missing display metadata. Invalid business
  arguments remain rejected and are returned to the Agent for correction rather
  than terminating an otherwise recoverable evaluation.
- Recover from output-token limits without executing incomplete tool arguments
  or presenting truncated output as a completed answer.
- Keep inherited model settings live at request boundaries while preserving
  explicit task selections and already-sent requests. Provider recovery retains
  the request's real identity; missing credentials and exhausted quota are
  reported distinctly.
- Correct no-reply control validation, owned child-work waits, maintenance
  handoffs, cancellation and durable terminal-state attribution.
- Use `max_tokens` for the official DeepSeek Chat endpoint. Compatible gateways
  may explicitly select their token-limit parameter; model names alone do not
  select a protocol dialect.

## Execution and inspection

- Add Runtime-owned terminal sessions with real PTY input, authorization,
  persistent execution provenance and native sandbox enforcement.
- Expose actual child work, model settings, public output and bounded execution
  records without inventing activity from display annotations.
- Correct SQLite transaction contention, PostgreSQL execution boundaries and
  related durable recovery paths.

## Linux sandbox requirements

Linux command protection now uses the administrator-installed policy service
and restricted native launcher in addition to Bubblewrap. Long-running commands
must remain unable to read protected files created after command admission.
Bubblewrap alone is not a supported fallback.

Read the archive's `linux-sandbox/INSTALL.md` before installation, upgrade,
rollback or removal. Installation requires an explicitly approved, immutable,
root-owned Runtime image. The Agent and its work still run as a non-root user.
Do not deploy the service automatically on existing production machines or
weaken protection to bypass an admission refusal.

## Related application source fixes

- Keep a submitted message visible across the local-to-Runtime history handoff,
  including pending acceptance and delivery errors.
- Correct Markdown autolinks that swallowed adjacent emphasis or Chinese text;
  continue using mature Markdown/link parsers and improve scoped message layout.
- Correct shared composer model settings, source quotations, provider-account
  management and the presentation of active child work and execution progress.

## Compatibility and upgrade cautions

Although this candidate uses the requested 0.1.4 version line, the cumulative
changes since 0.1.3 include new capabilities and changes to development-time
SDK, Harness and model-facing contracts. **Do not infer source/API compatibility
from the patch number.** Recompile integrations against this source and review
the current request schemas. Stored identities and execution receipts are not
permission to replay retired tools or rewrite historical work.

Before replacing a Runtime, stop it normally and take a verified backup of its
configured data. Keep that backup and the previous binary. Database migrations
are not reversed by installing an older executable; rollback to older storage
contracts requires the corresponding pre-upgrade backup. Never replay work
with possible external effects merely because an earlier response failed.

The RC does not claim arbitrary-model compatibility. DeepSeek official Chat
wire tests and real-provider acceptance are distinct. The official Chat
output-limit probe passed after the account quota was restored: one synthetic
request generated exactly 32 output tokens and ended with `length`, correctly
classified as an output limit rather than normal completion. It sent no user
Context and invoked no tools. Qwen, Kimi, GLM and quantized-model acceptance
remain separate future work.

## Explicit RC installation

Select the exact candidate rather than the default stable channel:

```sh
MORPHZ_VERSION=v0.1.4-rc.1 sh install.sh
morphz update --to 0.1.4-rc.1
```

Use the installer from this verified release, or the documented stable
installer with an explicit version. Archives include checksums and license
records. The Linux user-level installer does not install the privileged sandbox
service; its administrator setup remains an explicit, separate operation.
Edge signed-manifest distribution is a separate channel: an RC must not replace
the default stable manifest. A separately hosted and verified RC manifest also
requires explicit `--allow-prerelease` opt-in; this release does not imply such
a manifest has been hosted.

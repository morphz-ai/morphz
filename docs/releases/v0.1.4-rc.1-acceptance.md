## Official DeepSeek Chat output-limit acceptance

On 2026-10-23 (Asia/Shanghai), the existing official account was replenished by
the user after its earlier quota refusal. One bounded, synthetic request was
then sent through the production Chat adapter to `https://api.deepseek.com`,
model `deepseek-flash`, output budget 32 tokens. It produced the synthetic
integer sequence, reported exactly 32 output tokens and ended with `length`.
The adapter classified `OutputLimit`, did not report normal completion and
did not time out. No user Context was sent, no tools ran and production
configuration was not modified. The private native-credential probe report is
retained locally; credentials and user storage are not repository artifacts.

The freshly built `0.1.4-rc.1` probe subsequently passed the same 32-token gate.
Its preflight was corrected to resolve the configured credential's native alias
rather than mistake the catalog ID for the secret alias; a new pure unit test
covers that distinction. The failed preflight sent no provider request and did
not change or replace credentials. Both successful probe invocations are kept
as separate evidence rather than counted as one request.

This verifies the documented official Chat token-limit dialect. It does not
claim acceptance for arbitrary compatible gateways or other model families.

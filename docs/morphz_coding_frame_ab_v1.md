# Morphz 外生 Coding Frame A/B v1

> 状态：首轮真实验证；结论为“可求值、未证明增益”
> 日期：2026-07-15
> 主测模型：`gemini-3-flash-agent`
> System Prompt：`semantic_sexpr_vm`
> 相关实现：[`../morphz-evals/frames/coding_discipline_v1.sexpr`](../morphz-evals/frames/coding_discipline_v1.sexpr)、[`../morphz-evals/src/coding_frame_eval.rs`](../morphz-evals/src/coding_frame_eval.rs)

## 1. 要验证的命题

本实验不验证“把一段编码建议追加到用户 Prompt 是否有帮助”，而验证更强的架构命题：

> 一个原本通用的 Morphz Agent，在 Mind 中植入一份外生 Coding Frame 后，能否把它作为可复用认知纪律激活和执行，并因此提高编码任务的严谨性、正确性或效率。

这对应 Frame VM 路线的第一个现实样本：模型权重、Runtime、工具和任务都保持不变，只改变 Agent 挂载的认知 Frame。

## 2. Coding Frame v1

`coding-discipline-v1` 是一份 3,867 字节的通用 SExpr Frame，不包含本次 fixture 的文件名、函数名、缺陷答案或测试答案。

它规定六类稳定不变量：

- 任务边界优先；
- 证据先于判断；
- 测试是现实证据，不能通过修改测试制造成功；
- 实施最小充分修改；
- 保留用户已有工作；
- 现实结果优于叙事和计划。

它还定义一条编码过程：建立任务契约、修改前检查、建立失败基线、诊断根因、实施最小变更、在最后一次变更后重新验证、基于真实证据收口。

Frame 明确说明：它是身份之上的可复用 Coding 认知扩展，不用于保存单次任务状态；具体任务进度应由 Agent 自己创建独立任务 Frame。

## 3. 对照设计

两组使用完全相同的：

- 模型、Provider 与输出预算；
- SExpr VM System Prompt；
- Runtime、工具、权限和沙箱；
- 初始代码 fixture；
- 用户任务和修改范围；
- 公开测试与 Agent 不可见的隐藏测试。

唯一自变量是：

- **Fresh**：空 Mind 开始；
- **Coding Frame**：在用户消息到达前，通过正常 `context_tx` 将 `coding-discipline-v1` 创建并保护，使其从第一轮起出现在 Context Encoding 中。

用户任务只说明要修复重试状态机、允许修改的三个文件和禁止项，没有要求“先测试、读哪些文件、如何诊断、最后如何验证”。这些过程纪律只存在于候选组的 Coding Frame 中。

正确性由两层证据判断：

- Agent 可见的 5 个公开状态机测试；
- Agent 不可见、只在隔离验证副本中注入的 6 个隐藏测试。

## 4. 评测器修正

首轮运行发现了一项与 Agent 无关的评测框架漂移：新版 `exec` 返回结构化 JSON `exec_result`，旧评测器仍通过中文展示文本 `退出码: 0` 判断成功，导致两组已经通过的隐藏测试都被误报失败。

评测器现在同时识别结构化 `exit_code/output` 和旧展示文本，并增加了回归测试。修正后对原轨迹重新运行独立验证，两组均真实通过公开 5/5、隐藏 6/6。

另发现旧 evaluator 启动子 Agent 时仍使用已经移除的 `--config` 参数，现已改为当前 CLI 的 `--config-file`。参数错误产生的运行不计入 A/B 样本。

## 5. 两个有效配对样本

| 配对 | Arm | 公开 / 隐藏 | 过程纪律 | 工作轮次 | 物理工具 | 重复物理调用 | 时长 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | Fresh | 5/5 · 6/6 | 9/9 | 5 | 10 | 1 | 42.95s |
| 1 | Coding Frame | 5/5 · 6/6 | 9/9 | 12 | 12 | 2 | 91.33s |
| 2 | Fresh | 5/5 · 6/6 | 9/9 | 5 | 10 | 1 | 58.66s |
| 2 | Coding Frame | 5/5 · 6/6 | 9/9 | 7 | 11 | 2 | 69.93s |

“过程纪律 9/9”要求同时满足：

- 首次修改前观察到真实失败；
- 首次修改前读取足够的相关实现和测试；
- 最后一次修改后取得真实测试成功；
- 独立隐藏验证通过；
- 修改范围干净；
- 最终回复引用实际文件和测试证据。

第二个 Fresh 样本还自主创建并维护了任务 Frame，候选样本没有创建任务 Frame。它说明通用 Agent 本身已经能够形成部分编码工作纪律；不能把候选组的外生 Frame 计作 Agent 自主维护得分。

## 6. 可以确认的结论

### 6.1 Frame 的确被模型理解和执行

候选组中的 Coding Frame 在结束时仍处于 active、protected 状态。候选轨迹遵守了 Frame 中的主要语义：建立失败基线、检查相关代码、基于失败继续诊断、实施限定范围内的修改、在最后修改后验证并引用证据回复。

因此，首个问题得到了积极答案：

> 把通用 Agent 挂载一份外生 Coding Frame，在当前 Morphz SExpr VM 上是可行的；它没有让模型失灵，也没有造成任务质量退化。

### 6.2 这项任务没有证明 Coding Frame 提高能力

两个 Fresh 样本已经达到公开、隐藏和过程纪律满分，存在明显的天花板效应。Coding Frame 没有额外的正确性空间可以提升。

更重要的是，候选组两次都用了更多工作轮次、物理工具和时间。第一组差距很大，第二组差距缩小但方向不变。因此当前证据不能表述为“Coding Frame 提高了编程能力”。

更准确的表述是：

> **Coding Frame v1 可被正确求值，但在强模型已经能稳定完成的中等任务上，只复述了模型已有纪律，并带来一定认知与执行开销。**

### 6.3 `seq` 可能产生了不必要的机械串行化

Frame 的外层过程使用 `seq` 表达阶段依赖，文本也明确允许并行读取独立文件。候选模型仍倾向逐步读取和验证，而 Fresh 更紧凑地组合了独立动作。

目前只有两个配对，不能断言根因一定是 `seq`。但下一版 Frame 应认真区分：

- 必须保持因果顺序的阶段；
- 可以并行收集的独立证据；
- 只在风险出现时才需要的检查；
- 不应在简单任务中机械展开的完整流程。

通用纪律 Frame 不应把“严谨”错误地等价为“每一步都串行、每个检查都必须显式调用”。

## 7. 下一轮应该怎样验证

当前结果不支持立即把 Coding Frame 作为所有 Agent 的默认认知，也不支持否定外生 Frame 路线。更有区分度的下一轮是：

1. 增加三类不同缺陷：跨模块状态错误、模糊需求下的范围控制、缺少公开测试但有隐藏不变量；
2. 使用至少 5 个 seed 做配对，分开统计最终正确性、过程纪律和成本；
3. 加入更弱或更小的模型，测试 Frame 是否能补足其容易遗漏的基线、范围和验证步骤；
4. 设计负向样本，确认 Coding Frame 在普通聊天和非编码任务中不会错误激活；
5. 设计 Coding Frame v2，把刚性 `seq` 改成“因果门槛 + 可并行证据收集 + 风险触发检查”；
6. 比较外生 Frame、普通自然语言附加 Prompt、Skill 文档三种载体，隔离收益究竟来自内容还是 Frame 机制。

只有当候选在多个任务族或较弱模型上持续提高隐藏正确性、减少遗漏，且成本可接受，才能声称“给通用 Agent 植入 Coding Frame 会提高编程能力”。

## 8. 架构意义

虽然首轮没有出现质量增益，它仍然验证了一个关键前提：领域化可以是 Mind 层的认知装载，而不必立即训练新模型或复制一套 Coding Agent Runtime。

```text
通用 Frame VM
      +
Coding Discipline Frame
      +
当前仓库、任务、工具与现实证据
      ↓
本次 Coding Evaluation
```

这证明路径是通的；现在需要优化的是 Frame 的内容、激活条件、过程弹性和适用任务，而不是重新证明模型能否读取并遵循一份外生认知结构。

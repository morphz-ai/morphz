# Morphz Provider Conformance Suite

## 目的

Provider Conformance Suite（Provider 协议一致性测试集）验证的是 Morphz 与模型服务之间的物理协议，不评价模型回答质量。

它需要回答以下问题：

1. 请求是否发往正确端点，并使用正确鉴权与字段结构；
2. 普通响应和流式响应是否被无损归一化为 Morphz 的文本、工具调用和 usage 事件；
3. 工具调用 ID、参数分片和工具结果能否跨回合保持对应关系；
4. 限流、服务错误、截断、非法数据和连接中断是否会显式失败，而不会伪装成成功；
5. 新增 Provider 或协议版本后，是否可以复用同一组行为契约进行验证。

## 测试分层

### L1：请求契约

- 原生端点路径；
- 鉴权 Header；
- 模型、输出预算、System Prompt 和工具声明；
- 工具调用与工具结果的 ID 对应关系；
- Provider 不得根据模型名称猜测协议。

### L2：响应归一化

- 文本；
- 单个与并行工具调用；
- 交错到达的参数分片；
- usage；
- Provider 原生结束原因与错误原因。

### L3：流式传输

- 任意字节边界分片；
- LF 与 CRLF；
- SSE 注释、心跳、多行 `data`；
- 明确的协议终止事件；
- 终止事件前断流必须失败；
- 未知的前向兼容事件不得破坏已知内容。

### L4：恢复与重试

- 在接收任何流事件之前，429 和 5xx 可以按配置重试；
- 一旦开始消费流事件，不得自动重放请求，以免重复正文或工具调用；
- 非重试错误必须保留 HTTP 状态和 Provider 错误正文。

### L5：真实端点冒烟测试

确定性测试不访问互联网。真实 Provider 通过显式命令验证：

```bash
morphz provider test <provider-id>
```

该命令分别验证模型目录、流式正文和一次标准工具调用。真实测试产生的响应在脱敏后可以沉淀为确定性回归夹具，但核心测试不得依赖远端额度和服务稳定性。

## 当前入口

运行全部确定性 Provider 测试：

```bash
cargo test -p morphz provider::
```

只运行协议一致性套件：

```bash
cargo test -p morphz provider::conformance
```

测试实现位于 `morphz/src/provider/conformance.rs`。新增协议事件时，应先加入一个经过脱敏的最小夹具，再修改解析器。

## 已知边界

以下能力尚未达到完整一致性，不能因为基础测试通过就宣称支持：

1. Gemini 3 `thoughtSignature` 的跨回合持久化与原样回传；
2. Anthropic extended thinking 的 `thinking_delta` / `signature_delta` 持久化；
3. Provider 模型目录的分页；
4. 流已经开始之后的可恢复传输。默认策略是显式失败，不能无条件重放；
5. 图片、音频、文件、结构化输出以及 Provider 内建工具；
6. 各家最新状态化接口，例如 Gemini Interactions API。

其中前两项需要在 Provider 中立的消息模型中增加“不可解释但可持久化、可原样回传”的协议状态，不能把私有字段混入正文、工具参数或 Context Frame。

## 新增 Provider 的准入规则

新的 Provider 不应直接复制一套客户端实现。优先判断其属于哪一种线协议：

- 完整兼容现有协议：复用适配器，只增加端点和鉴权配置，并运行全套契约；
- 对现有协议有方言差异：以显式 capability/quirk 描述差异，并加入最小夹具；
- 新协议：实现新的协议适配器，同时至少覆盖 L1 至 L4。

只有确定性套件通过，并且至少一个真实端点完成 L5 冒烟测试，才能把该 Provider 标记为“已验证”。

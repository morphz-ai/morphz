# Product reads: bounded, indexed and demand driven

These user-confirmed rules apply to Runtime, Dashboard and Desktop.

- Collection APIs and database queries have an enforced page/row/byte budget and a stable continuation cursor. Apply scope, authorization, ordering and the limit in the database. Do not fetch an entire registry/history and then filter, sort or slice it in memory, or drain every page to paint one screen.
- Page bounds extend to related rows. Selecting 50 parents does not authorize all of their lifetime dependencies, Activations, Jobs, Signals or payloads. Use current-generation projections, independent child pages, indexed aggregates/EXISTS and explicit completeness boundaries. Preserve authoritative state and invariant diagnostics; truncation must not become false completion or false absence.
- Use indexed keyset seeks. A LIMIT after a lifetime scan/window/sort is not sufficient. Verify the actual SQLite and PostgreSQL query plans and adversarial large-history fixtures. Single-object reads are exact authorized point reads; large content is opened or chunked only when requested, never prefetched as directory metadata.
- Every product read has a concrete owner and trigger: first visible page, requested continuation/source jump, a relevant committed invalidation, a transport reconnect gap, or an explicit retry/refresh. Hidden pages do not read their data. Healthy idle does not run periodic network/database refreshes. Presentation-only clocks perform no I/O.
- Subscribe before closing the initial/reconnect gap, preserve accepted cursors, coalesce relevant invalidations and retain changes received while busy. Failed-transport recovery is bounded recovery, not an excuse for a healthy scanner. Background task execution must not depend on a visible page subscriber.
- A confirmed mutation publishes its validated native receipt. Background read reconciliation does not delay or change that command's result, and an older in-flight read cannot overwrite it. Preserve authorization, CAS, durable command identity, unknown outcomes, drafts and live work.
- Migrations, recovery and integrity checks must also bound materialized batches; use indexed predicates/aggregates for complete checks. Do not weaken integrity checks or silently hide records to satisfy a page budget.
- Test actual request counts, cursor advancement, unrelated-page/healthy-idle silence, late invalidations, permission changes, completeness and query plans. Static source guards supplement behavioral tests. Build Rust in release mode unless debug is specifically necessary. Original-app inspection preserves the user's tasks, models, drafts and profile; isolated fixtures never count as manual original-app acceptance.

# Morphz application work

Before changing desktop UI or interaction, read `docs/16-ui-design-standard.md` and the current implementation notes in `docs/13-implementation-status.md`. For application hosting and workspace/Session routing, also read `docs/15-cognitive-application-host.md`.

The current Web/Desktop hosting target is `docs/24-shared-application-host.md`: share plain application logic, embed it in Desktop, and expose it through HTTP only for Web/remote clients. Desktop must not require a local application HTTP server or Vite. Runtime remains separate; its local object-tool callback must not reintroduce that HTTP dependency. Preserve existing data and authorization when changing transports.

- Product and current engineering names use **Morphz**; the application package is `morphz-application`, distinct from Morphz Runtime. New configuration uses `MORPHZ_APP_*`. Old names are compatibility inputs only: preserve existing profile/data paths, authentication, immutable Session formats and tool-call idempotency. Never rename live storage or re-sign a compatible installed launcher merely to remove legacy text. The checkout folder is not a product name or an implicit repository merge request.
- Work and objects organize the product. The first sidebar navigation item is one fixed global 对话 space; do not add global new-chat actions or a global conversation list. Each project row has a direct SquarePen action for a new conversation, not a plus or a toolbar dropdown. Project-local conversations nest under their project; their own menus handle rename, archive and restore. Conversation management is optional, never a prerequisite for working.
- Personal default conversation spans 对话, 事项, 工作台 and projects without a named conversation. Named project conversations stay separate. Read `docs/17-continuous-conversation-and-execution.md` for current routing. Preserve old Sessions and in-flight requests without rewriting or replaying them; team Context permissions do not merge.
- Clicking a project itself selects the default continuous conversation; only explicitly created Sessions appear beneath it. Do not render a synthetic “持续对话” child or restore a named Session on an explicit project click. Session selection and page reload may retain a named Session; project disclosure only expands/collapses and never changes routing. Keep legacy default records and messages intact.
- New conversation actions only prepare a local draft. Persist a named conversation atomically with its first valid submitted input, never on navigation or repeated clicks. Empty records stay out of the sidebar; unsent content is a recoverable draft, not a started Session. Preserve legacy records and attachments; failed or uncertain first sends retain a stable command identity for safe retry.
- Navigation, artifact ownership, conversation identity and execution scope are distinct. Shared-Session Host tools must resolve the persisted input from the Runtime's actual thread/root; never trust model arguments or the currently selected page for project authority. Drafts, input pinning and layout remain scoped to the work surface.
- Sidebar 内容 lists authorized non-task artifacts across spaces; tasks belong in 事项 and are excluded from content lists, counts, type filters and creation shortcuts. Both use the same object store; task-linked documents and relations remain intact. Workbench/project content stays local and also excludes tasks. Do not restore a generic 资料 application tile or create a Session for the content catalog. Preserve the entry and return path when opening objects.
- Publish main messages chronologically, with stable first-visible identity/time for a streamed reply. Keep causal links without grouping late replies under old inputs. The right execution inspector shows actual threads, tools, approvals and results; opening it must reuse the exchange's streaming prefix and must not retarget the composer.
- Delivery links come from persisted Host receipts with exact object/version/input provenance, never inferred from reply text. Navigation restores the work surface without selecting another conversation. Use actual Runtime model catalogs and distinguish next-input selection from task execution settings.
- Preserve the current application while exchanging messages. Hiding input, opening history and switching applications do not stop background work or discard drafts.
- Human and Agent are equal participants. Keep identity, authorization, object revisions and actual execution receipts visible where relevant; never simulate success.
- Agent-first: creation shortcuts must use the shared intent input, not a required form. The Agent persists artifacts through real tools. Keep direct result editing and explicit authorization; never interpret a shortcut click as permission to send or execute.
- Use the shared interaction model, modal focus hook and UI tokens. Keep the four Dashboard accent palettes; use accessible foreground shades rather than inventing new brand colors.
- A page has one integrated title/action bar, continuous with the content background. Never stack a small shell title above a large page heading or use large decorative header spacing. Dialog titles and controls share a compact row; preserve necessary permissions and error information.
- Dialog space is a regression requirement, not a final cosmetic pass. Media previews size to image proportions and available workspace; short forms stay compact. Put retry/refresh actions in the title row and short names beside confirmation actions when space permits. Shared widths use `--ui-dialog-width`, not competing later fixed-width rules. Run geometry regressions for wide/tall/small media, narrow windows, errors, keyboard access and 200% desktop zoom; don't refresh away an unconfirmed screenshot to demonstrate a fix.
- Validate changed behavior with automated tests and real Electron inspection. Existing fixtures must follow current navigation, but do not remove assertions to hide product regressions. The current Morphz app is the user-designated test environment: manual acceptance must use that same app, profile and center, with clearly named test content. Do not launch a second manual-test app, profile or center. Correcting this same app's mistaken Electron bundle/system identity to Morphz is authorized, not a second test environment. Automated regression fixtures may remain isolated; do not report their screenshots as acceptance of the user's current window.
- Own corrective work in this designated test environment: implement fixes, build, verify and perform necessary normal restarts directly, preserving existing data, credentials, drafts, Sessions and in-flight work. The user explicitly confirmed this on 2026-09-12; do not repeatedly ask for authorization for these already-approved actions, including the Morphz system-identity correction. Explain material effects briefly and proceed. An OS permission prompt may still require the user's actual interaction; do not substitute another assistant confirmation question. This does not authorize unrelated destructive actions, publishing, purchases or changes to other apps' permissions.
- The UI standard includes future targets. Check implementation status before claiming a feature exists. Professional application interfaces and the experimental UI package must not be described as a stable Runtime standard.

User direction takes precedence over these product defaults. Numerical layout baselines are adjustable design decisions, not mandatory Apple dimensions.

# 统一选文评论

同一条操作链用于消息、文档、阅读器、剧本、网页及应用内其他正文：

1. 选中文字，点击「评论」，光标直接进入选文旁的评论框。
2. 评论随写随存为本地草稿。完成、关闭或点击别处只收起编辑器，不发送。
3. 可继续选择其他段落。输入框按顺序汇总，支持重开编辑、移除；内置正文旁显示同编号标记。
4. 使用原有全局输入框统一发送，仍是当前 Morphz Session。发送失败保留原文、评论、正文和重试标识。
5. 已发送引用展示来源、原文和对应评论；点击定位来源。来源变化或暂不可读时保留快照并明确提示，不改指另一段。

参考操作逻辑：Dashboard `SelectionQuotePopup` → `addQuote` → `inlineCommentQuoteId` → 全局输入框；定位使用来源版本与文本锚点，不保存屏幕像素作为原文位置。Codex 是用户指定的交互参照，未直接操作其界面验收。

## 数据与边界

- `TextQuote`：用户选中的文本快照、评论、来源、定位锚点；编辑中的文字明确标为草稿。
- 来源按消息、对象版本、阅读位置、剧本版本/候选、网页或普通工作界面区分。应用只描述来源；真实输入身份、Session 和权限不由引用决定。
- 多处选文存在原来的本地输入草稿存储中，以当前对话汇总；正文、附件与执行绑定仍按原工作现场保存。切换命名对话不串草稿。未发送评论不对 Agent 可见。
- 新输入保存结构化引用用于界面回跳；通过既有 Session IO 文本字段传输原文、来源和评论，不改写已发送输入、格式注册或 outbox。
- 原文属于外部资料，不是新增操作授权。服务端核对来源权限、对象版本和实际源消息所属会话；引用不附加目录、浏览器控制或写入权限。
- 阅读标注与选文评论不是同一数据：高亮、书签和批注仍由阅读器管理，评论不隐式增加或删除这些记录。
- 网页仅在用户选择动作后读取所选文本，经隔离 world 返回；不安装网页 preload，不暴露宿主 IPC，不自动抓取整页或调用模型。

## 应用接入

内置应用在可选文本的根元素提供 `quoteSource(source)`；宿主统一处理选文、就地编辑、编号、草稿与发送。需要保留专业选文工具栏的阅读器、PDF 和文档，使用 `data-quote-menu="local"`，由其「评论」按钮调用同一控制器。

沙箱 UI 使用现有 `input.compose` 权限，通过 `commentText` 提交 `text`、可选 `comment`、`artifactId/revision`、`anchor` 和 iframe 内的 `point`。宿主核对来源窗口、channel、活跃实例及对象读取权限，仅准备可见评论，不代发。无固定对象的界面只标注应用来源，不伪造精确历史位置。

### 适用边界

- 内置正文、阅读器、剧本编辑字段、消息及 Desktop 浏览器已接入。第三方沙箱应用须调用 `commentText`；宿主不越过 iframe 隔离去注入任意页面脚本。
- 网页选文在输入框中编号汇总，并可回到网页选择原文；不向外部网页插入永久标注节点。网页内容变化后若不能唯一定位，会保留原引用快照并提示，不跳到相似的另一段。
- 编辑中的原文按草稿引用，不暗中保存或覆盖对象；原草稿改变后不会伪装成可精确恢复的历史版本。
- 图片本身不是可选文本；已有 OCR 提取出的阅读文本可走同一选文流程。本功能不会因选文而重新 OCR、扫描文件或抓取整页。

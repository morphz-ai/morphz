# Morphz UI 设计规范与优化方案

状态：已采纳的设计基线，公共 UI 首轮已实施。下文同时保留完整目标与初次审计；不表示每个目标都已实现。实际完成范围见本文末尾与实施记录。产品统一使用 Morphz；应用工程包为 `morphz-application`，位于主仓库 `application/`，与 Morphz Runtime 保持独立模块边界。

2026-10-01：用户确认「左侧导航、中间内容、右侧 Morphz 信息、底部输入与应用 Dock」的整体设计，以及工作台作为完整应用管理入口。线程活动、单底栏输入、应用 Dock 和主体信息图标页已分阶段实施；完整验证与实际能力边界见实施记录。下文「三栏分工与底部交互区」和 4.1 节的新规则取代旧的工具 Dock／混合右栏目标，不把历史结果改写成完整主体档案已经完成。

## 1. 规范依据与适用范围

以 Apple Human Interface Guidelines（HIG）作为当前桌面体验的主要依据，用 W3C 的键盘、焦点和可访问性要求补充 Electron/Web 的实现规则。官方规范解决平台惯例，Morphz 的产品原则解决工作如何组织；不能把自己的交互设想或像素值说成 Apple 的规定。

已经核对的官方依据：

- [Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos)：利用桌面空间、减少不必要的层级与模态打断，支持键盘、窗口调整和持续工作。
- [Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：按当前内容选择和分组动作，定义窗口变窄时的收纳顺序。
- [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)：导航的层次、显隐、空间适配与可定制性。
- [Modality](https://developer.apple.com/design/human-interface-guidelines/modality)：只有明确收益才采用模态，任务应清楚、简短，避免多层弹窗，并保护未保存内容。
- [Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields)：明确搜索范围、及时反馈、简化结果，并提供适当的范围筛选。
- [WAI-ARIA APG：Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：打开后的焦点、模态内 Tab 循环、Escape 和关闭后的焦点返回。
- [WCAG 2.2：文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：文字可读性和控件可操作性。

HIG 不要求跨平台应用照搬所有 Apple 材质。当前使用 Electron，保留真实系统窗口控制、系统字体及平台快捷键，不绘制假系统窗口按钮，也不把 CSS 模糊效果宣称为原生 Liquid Glass。未来其他平台遵守各自惯例，共享产品语义，不强求像素一致。

本文件是 UI 优化的目标规范；与早期界面草案冲突时，以这里的设计原则为准。实际已实现情况仍看 [实施记录](./13-implementation-status.md)，应用宿主协议仍看 [应用与工作空间](./15-cognitive-application-host.md)。

## 2. 产品原则：围绕工作，而不是围绕会话

### 2.1 工作和对象是组织单位

用户来到 Morphz，是为了写作、开发、阅读、处理事项或继续思考。输入是参与工作的方式，消息是交流记录，Artifacts 是可继续使用、编辑、关联的工作对象。普通交流也可以只留下消息，不强迫每句话变成事项或文档。

不要求先建立聊天才能开始工作。侧栏首位提供固定“对话”，承载不隶属于项目的长期交流，但没有全局“新建对话”按钮或聊天列表。项目默认可直接输入；需要独立会话时，点击侧栏项目行右侧的方框笔形按钮直接开始，不用加号，也不先打开顶栏选择器。已有会话嵌套在所属项目下，条目菜单负责重命名、归档和恢复。完整消息记录仍保留、同步；Session 仍是底层概念。

项目行本身就是默认持续对话入口，不另列自动生成的“持续对话”子项。明确点击项目（含项目目录）回到默认，点击子会话才进入该会话；刷新保留当前选择，展开／折叠箭头只控制列表。项目与子会话不能同时表现为当前选中。此规则不删除已有默认历史，也不按名称隐藏用户自己命名的会话。

点击新建只准备本机草稿，不创建空会话；同项目反复点击复用尚未确认首发的草稿。只有首条有效文字或附件被中心接受时，才原子建立会话和输入记录。未输入内容不增加侧栏子项；写了但未发送的内容以明确的“草稿”入口保留，刷新与切换可恢复。旧空会话不占列表，原数据不删除；失败或回执丢失保留草稿，重试不重复首发。提交成功后在输入框恢复可用时聚焦，不能抢走后续导航。

### 2.2 能力对应的体验

| Morphz 能力与产品关系                  | 用户的真实需求                           | UI 必须体现的结果                                                     |
| -------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------- |
| 一个持续的 Agent，在授权范围内共享认知 | 换工作现场不想反复解释背景               | 切空间自动接续；不展示重置记忆或切换 Agent 的假象                     |
| 持续默认会话与可选命名会话             | 切换工作现场仍能接续交流，必要时分开话题 | 个人默认历史贯穿各入口；项目命名会话保持独立；Session 不进入导航      |
| 多条工作并发推进                       | 等待一项工作时继续做其他事               | 新输入仍可用，进度归到具体工作；停止一项不停止全部                    |
| Human 与 Agent 都是 Actant             | 人能主动创作，也能接到 Agent 的安排      | 事项与对象按能力提供直接操作，不把所有事都变成“让 AI 帮我”            |
| Artifacts 与版本、关联关系             | 找到真正的文件、结果、来源和后续工作     | 消息中的交付能打开对象；人编辑后 Agent 使用正确版本，不只显示文本副本 |
| 认知应用有可选的平台界面               | 不同工作需要不同工具                     | 应用决定主体界面，宿主保持导航、权限和输入的一致性                    |
| 中心与 Edge 分离                       | 关窗口、切应用不应中断后台工作           | 界面显隐不等于运行启停；状态、任务和消息以中心回执为准                |

共享认知始终受 Principal 和工作空间授权约束；“同一个 Agent”不意味着任何人或应用能读取所有资料。

### 2.3 元素取舍规则

每个常驻元素都应回答：它帮助用户在当前场景完成什么？使用频率如何？离开这一层以后还能从哪里找到？

- 高频且属于当前场景：直接可见。
- 低频但必要：放进相关对象菜单、检查器或设置，不散布于所有页面。
- 当前不可用：优先不显示；若用户确实需要知道缺了什么能力，显示原因和恢复方式。
- 只是重复说明、开发诊断或占位：移出日常界面，不用装饰填满空间。

减少元素不能以隐藏失败、未发送、权限限制或人的待办为代价。

连接状态必须区分应用数据可访问、运行服务可达和模型配置可用；不以“工作中心已连接”替代智能体状态，也不要求普通用户理解内部部署层。未连接、凭据失效与模型未配置给出各自可执行的设置或恢复入口；远端无权限时明确找谁处理。重试检查只核验状态，不自动重发、停止或重启工作。配置操作保留草稿和原会话绑定；机密只在本人明确保存后进入主机私有配置，不回显、不进入浏览器存储或设置链接。桌面业务继续内嵌调用／IPC，此类 UI 不得重新引入应用 HTTP 服务。

登录、启动、语音、文件读取、编辑冲突与浏览器错误同样使用实际对象和可执行动作，不再要求用户“连接／更新工作中心”。登录凭据与智能体运行服务的连接凭据明确区分，沿用既有身份认证，不新增登录方式。模型设置必须区分正在加载、读取失败和服务未提供能力；没有返回结果不等于需要升级。旧存储路径、身份标识和远端 HTTP 兼容接口保持不变。

模型设置留在 Desktop 的同一个对话框内，不打开 Dashboard、不嵌入其网页。普通流程只展示默认模型、真实账号与添加账号；服务商登录入口来自 Runtime 注册能力，不拿适配器冒充已登录账号，不要求用户填写内部 Provider／Account／Route ID。API Key 和 OAuth 凭据仍由 Runtime 保管，桌面业务层只封装有界操作；只有第三方授权打开系统浏览器。保存后更新模型选择器，不丢弃草稿或覆盖本次已指定模型。默认模型影响后续未单独指定模型的请求，不重新发送消息。账号目录刷新若附带模型探测，必须明确标注「读取并测试」及后果，不在登录成功后自动触发。

「添加账号」使用独立步骤标题及单个返回入口，不能同时出现返回连接详情和返回模型设置两行。账号登录／API Key 用有清楚选中态的分段控件；服务商各占一个完整按钮行，显示名称和「登录并连接」，整行可点击，不用一排裸名称代替操作入口。仅实际点击才发起授权，切换方式和返回不触发；请求期间显示正在连接并阻止重复操作，失败后可重试。保留实验性提示、键盘焦点、窄窗换行及缩放时的滚动可达性。

设置中的读取、重试、取消使用同一套次要按钮样式，确认保存使用主按钮；独立动作按内容定宽，不因 Grid 默认拉伸而变成整行横条。长账号名与模型标识最多占两行，保留完整可访问名称和悬停提示，不能挤掉操作；窄窗操作自然换行，内容在弹窗内滚动，保存和关闭仍可到达。

### 2.4 外部原文件与 Agent 产物的边界（2026-09-13 修正）

外部文件不是选中后就归 Morphz 管理的 Artifact。将文件交给 Agent 处理使用既有消息附件；不另建通用“打开文件／打开文件夹”入口，也不把正在查看的文件自动附到后续每条消息。附件保存消息所提交的副本，不因此创建 Artifact 或加入全文索引。

全文索引仅覆盖 Agent 创建、且非外部导入的 Artifact；Human 后续编辑不改变其产物来源。现有人工文档、导入副本、图片／PDF、版本和批注继续从内容列表与历史链接访问，不因退出搜索范围而删除或断开附件权限。旧来源自动同步停用，已保存的副本保留。

用户明确允许新增的是“授权 Agent 读写目录”。它位于输入工具中，系统选择器明确读写后果；额外授权的目录图形与数量在输入设置入口可见，名称、路径及撤销操作留在该入口的工作目录详情，不在每条消息卡片里重复目录权限。权限限定于当前 Human、中心、工作空间和对话，不跨对话或工作空间自动继承，不因选择目录而创建会话、发消息或展开文件浏览器。每次输入固定当时的授权引用；Agent 在实际输入的范围内按需列举、读取及修改原文件，不复制仓库、不同步或索引外部文件。撤销阻止进行中工作的后续目录调用，但不抹除已读内容或已完成修改。

目录写入目前为 UTF-8 文本的新建／修改：先读后写，旧版本冲突不可静默覆盖；写入有持久幂等回执。授权不含删除、执行命令、凭据路径或绕过符号链接边界。旧只读授权不自动升级。Web／远端中心不展示本机目录授权入口。原文件阅读器的历史输入、引用与草稿保留兼容，不再自动恢复阅读器或隐式引用。

未来若确需托管副本，必须先确认归档、共享、脱离原路径继续工作等具体需求，再定义副本所有权、更新和删除规则。不能因后端已有导入、索引或同步能力而自动添加入口；暂不提供的格式明确说明，不伪装支持。此节取代下文历史条目中通用“导入／接入来源”的默认设计。

## 3. 窗口与页面职责

主窗口采用稳定的职责分工：左侧导航、中间内容、右侧 Morphz 主体信息；底部提供统一输入与应用快捷入口。右栏不再作为通用内容容器，输入收起也不改变内容属于中间画布的原则。

### 三栏分工与底部交互区（2026-10-01 确认，待实施）

Morphz 是跨工作场景持续存在的同一主体，有自己的名字、执行状态、活动历史和设定。个人助理与专业工作不是两套产品：切换应用改变工作场景，不切换 Morphz 身份。个人默认交流保持连续，项目内可选命名会话的既有规则不变；同一主体仍受身份与工作空间权限约束。

| 区域                               | 核心职责                                                                                   | 不承担的职责                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 左侧导航                           | 整体入口：对话、事项、内容库、工作台、项目及项目内会话                                     | 不堆放应用启动、执行日志或人格设置来争夺主导航位置       |
| 中间内容                           | 随应用和场景变化的工作画布：交流、剧本、网页、文档等；应用自己的目录、批注、属性和编辑工具 | 不因输入或交流浮层展开而被挤出；不把专业内容迁往宿主右栏 |
| 右侧 Morphz 信息                   | 同一主体的真实状态、活动、授权、安排与设定                                                 | 不混入文档编辑、对象批注、独立录音转文字或另一套聊天输入 |
| 底部输入                           | Agent-first 主交互入口：向 Morphz 表达意图，围绕当前工作交流                               | 不要求先选择应用才能发起工作，不因切场景而换助理         |
| 应用 Dock 与应用选择器（Launcher） | 快速启动／切换认知应用；用户固定常用应用                                                   | 不替代工作台，不建立独立安装、设置或应用目录             |

认知应用提供工作的能力与可选界面。用户可以直接输入「帮我写剧本」，也可以通过 Dock 打开剧本工作室；打开应用不是使用该能力的前置条件，也不是执行授权。输入工具与应用快捷入口可以相邻，但须在视觉和交互上分组，不能将浏览器、附件、编剧、固定、听写混为一排等价动作。

**工作台是完整应用管理入口。** 它负责应用浏览、安装、设置和管理，也保留已打开应用与继续工作。安装与设置只展示实际支持且有权限的能力，不据此宣称应用市场、自动安装或新权限系统已经实现。Dock 是固定快捷入口，弹出的应用选择器是快速选择入口；两者与工作台使用同一份授权应用目录和固定偏好。用户可从应用选择器固定／取消固定常用应用，完整管理进入工作台，不另维护第二套应用状态。

应用选择器采用 macOS Launchpad 式图标网格，而不是纵向命令列表：图标在上、应用名在下，足够留白；窄窗减少列数并在弹层内滚动，不扩大为另一张管理页面。点击图标打开原应用；固定／取消固定只在悬停、键盘聚焦时显露，触控仍可达，不与应用启动混为同一点击。图标来自现有应用目录，不虚构品牌资源或安装状态；完整管理仍进入工作台。

2026-10-02：打开选择器时焦点先留在面板，不自动聚焦第一应用，否则 `focus-within` 会让首项图钉常显。主动 Tab 进入具体应用／图钉后才显示对应操作；触控无悬停设备仍直接可达。关闭返回原 Launcher，固定偏好及草稿不变。

选择器水平居中于整组 Dock，而不是沿最后一个「全部应用」按钮右对齐；固定数量改变时仍跟随同一中轴，窄窗与实际 CSS 缩放先按此中轴定位，再限制到视口安全边界。保留原独立悬浮按钮材质。鼠标打开不产生原生蓝色粗焦点框；主动键盘进入时保留细中性焦点提示。

悬浮 Dock 保留既有独立小按钮材质与尺寸：32px 点击区、现有 raised 底色与细内描边，不因把输入工具换成应用入口而新增整排胶囊背景、外框或阴影。分组由位置与职责表达；Launcher 网格的弹层不是重画悬浮按钮的理由。

右栏围绕 Morphz 组织信息，而不是给原来的工具菜单加头像：状态说明正在做什么／等待什么，活动说明实际动作与结果，授权说明需要本人允许什么，安排说明之后要做什么，设定说明这个主体的配置。具体页签、头像尺寸和设定编辑方式仍须整体验证，不照搬参考产品的「SOUL／记忆」卡片或提供无实际数据的入口。

活动记录首轮采用真实 Runtime 执行线程及终态，按持久 root 关联来源，保留确切调用、审批、失败和结果。不能只把用户请求列表改名为「活动」就声称完成角色活动历史；未知来源与有界历史仍明确披露。旧公开理解机制是显式发布的目标／约束／事实摘要，不是实时或完整记忆，也不是 Profile。2026-10-02 移除其设定页入口，不迁到其他菜单；保留旧 API／存储机制不表示用户中心已有摘要数据。独立录音转文字不属于主体信息，既有输入听写与未来录音类认知应用分别讨论，不在本次实施中新增应用。

当前 Logo 保持撤回试验后的左侧位置；本次设计确认不恢复被否决的顶栏头像按钮或另行移动 Logo。Human 身份与客户端设置、Morphz 主体设定、单个应用设置须各自表达，不能因人格化而混为一个个人菜单。

- **一个页面只有一个宿主标题／操作层。** 页面可以保留醒目的标题，但名称、筛选、新建和其他主要操作必须与已有顶栏集成，不再叠“小标题栏 + 大标题 + 工具栏”。事项、项目目录、应用启动台、对象查看与新建文档遵守同一规则。文档正文中的内容标题不是宿主标题，不因合并窗体层级而删除。
- 顶栏与内容使用同一底色，不用横向分隔线、独立卡片背景或大段顶部留白将它们切成两块。下方直接开始实际内容。窄窗口将筛选切为紧凑选择器、操作收成带名称的图标，仍保持单行，不另加第二层标题。
- 桌面窗口上沿、顶栏空白和非交互标题可拖动窗口；按钮、搜索、选择器、菜单及实际应用标签保留点击与滚动。不可把整块弹性布局容器设为不可拖动；拖动区也不额外占用一行标题栏。

- 侧栏底部只保留一个个人按钮，将原「更多」的搜索、外观、通知、设置合入同一菜单，删除独立省略号和重复设置齿轮。展开态显示真实身份，收缩态显示同一入口的头像；菜单内保留名称、实际连接状态和未读提示。即使没有账号操作，真实应用工具也使该菜单有用；退出登录仅在宿主实际支持时出现。它管理用户与客户端，不承载 Morphz 主体设定。输入附近保留异常提示与恢复路径，不虚构用量、邀请或订阅入口。

### 3.3 内容目录的操作边界

内容目录顶栏只提供内容创作，主动作明确为“起草文档”，不将“工作台”等位置名拼成看似导航的按钮。选择具体范围后，新输入、智能体起草和手动写文档都属于该范围；输入框显示实际目标，不能看着项目 A 却写到别处。全部范围仍展示所有授权内容，未选具体范围时新内容归入“未归项目”，并保留原草稿，不把“全部”解释为跨项目执行授权。打开已有内容后以其实际归属及版本为准，返回目录保留筛选。切换范围保留各自未发送文字、附件及目录授权，不移动旧内容、不重定向在途输入；个人默认会话保持连续，团队权限不合并。

保留共享输入起草和手动写文档，不再提供“制作表格或报告”混合入口，也不要求用户先选择内部对象类型；点击起草只展开输入，不跳转工作台、不创建空对象或发送消息。卡片和列表保持同一组对象、筛选与排序；目录和打开对象之间往返保留位置。

书面报告、分析、说明和一次性比较默认交付 Markdown 文档，必要时包含 Markdown 表格。需要持续维护、逐项编辑或交互筛选的记录才使用既有可编辑表格，继续编辑旧表格仍保留原类型。所有旧交互对象在目录中统一称“表格”，内部视图为“表格／记录／统计”；兼容的 `table/form/report` 数据键不变，统计仅表示已存数值的计数、合计与均值，不冒充书面报告，也不为视图创建额外对象。保留旧标题、ID、数据、版本与草稿。

用户明确要求文件格式或交互页面时，智能体先核实实际工具能力；不支持则说明限制，不能用内部表格冒充 Office 文件或可执行 HTML。不因此引入 Office 套件、新 HTML 执行能力或外部文件导入／索引。

预览使用真实原文、PDF 首页和表格记录，不用内部类型、原始 PDF 页头或虚构摘要替代。来源表达原始创建者／旧导入身份，人工后续修改不伪造新来源；事项关联只取真实交付关系。版本仍可在对象详情读取。

重命名和归属调整使用共享的元数据命令，保留正文与旧版本，处理陈旧版本冲突并提供撤销。不同成员范围或有关联的内容不能直接移动，不能静默拆掉关联。智能体使用同一命令与权限校验，不模拟点击，也不借接口扩大当前执行作用范围。内容旁的继续处理只引用所选对象并展开原输入，不能覆盖其他草稿、发送消息或切换会话。

继续处理当前版本不等于查看历史：输入保存确切引用版本，但正文正常跟随同一对象的后续更新。仅在用户主动查看历史，或恢复基于旧版本的未发草稿时保持那一版；不能出现“回复说已更新，正文仍无提示停在旧版”的默认路径。

全文查找只连接现有智能体原生产物索引，外部文件仍不进入应用索引；旧副本和人工内容可按标题找到。错误时如实说明可用的标题匹配与重试，不能把服务失败显示成没有内容。

### 3.4 浏览器收藏与成果分开（2026-09-14 修正）

公开“当前理解”是工作状态，不在普通内容列表、计数、最近成果和成果索引中展示；原检查器、显式读取与历史版本保留。旧网页内容对象保留访问与历史，不再新建，也不保留“网站”创作／分类入口。图片、PDF 和后续认知应用的编辑扩展保留，当前并未因此新增图片编辑器。

浏览器收藏属于浏览器的基础功能，不能因撤掉“网站”内容类型而一并取消。地址栏提供收藏当前网址与收藏列表；列表可查找、打开、编辑、移除和撤销。Human 和智能体共用版本化操作和持久回执；智能体可以按用户要求收藏给定网址，不需要先获得页面控制权限。收藏只保存名称／网址，不访问网页、不复制网页正文、不创建 Artifact 或全文索引；真正打开网页仍走已有浏览器安全边界。

收藏按当前用户保存在中心，跨该用户的工作空间共用，不因共享项目暴露给其他人。智能体的所有者由实际发起输入解析，不能指定另一个人的收藏库；没有实际输入的后台调用不能借共享 Agent 身份读取个人收藏。重复保存同一规范网址复用原收藏，不覆盖旧名称；修改与移除检查当前版本，冲突不静默覆盖；移除保留可恢复记录。旧网站对象不自动迁移为个人收藏，以免改变旧数据归属。此节取代历史条目中把浏览器“保存”解释为创建网站内容对象的做法。

## 4. 输入框与消息列表：一个交互区域

### Agent-first：表达需求，直接得到工作对象

用户表达要完成的事，Agent 负责整理和写入事项、文档、表格等对象；网页收藏通过浏览器书签接口完成，界面展示实际结果。不能把“新建事项”设计成必填表单，或只在对话中生成一份要求用户再复制录入的安排。

- 直接输入可以发起工作，不必先选择类型。创建快捷入口仅聚焦同一个输入框，并提供可移除的意图提示，不覆盖草稿，不自动发送，也不先创建空对象。
- 作用空间、当前应用、对象版本、选区和输入意图一起保存；空间之间不串用。意图不是新增 Session，也不改变已有 Harness 与权限。
- Agent 使用真实对象工具，创建和修改后以实际回执为准。缺少关键条件时只问必要的问题；失败、未连接或仅排队均不能显示为已创建、已完成。
- Human 可以直接编辑、阅读、批注和操作已有结果。“自己写文档”是明确的次要创作路径，不是所有人的必经步骤。文件导入、授权确认、执行审批仍保留直接控件；Agent-first 不等于取消用户控制权。
- 命名项目和已开始会话的整理接入类型化智能体接口，与用户界面共用权限、版本和持久回执。项目所有者取实际发起输入的用户；跨项目只允许相同成员边界内的管理，既有成员权限撤销后不能重放旧回执。普通讨论不等于组织授权；新会话仍由首条有效用户输入创建。GUI 与智能体共用“设置项目”操作，只整理选中内容；新建项目可同时完成。不借共享智能体身份改变其他人的内容。

以下规定输入区的目标行为。基础展开、隐藏、历史、滚动及显式定向补充已实施；尚未验收的目标在文末单列。

### 4.2 作用范围与引用

- 输入附近展示有意义的空间／对象名称，不把 Harness、Session ID 或协议状态堆给用户。
- 当前可见对象不等于已经允许读取该对象的全部私密数据；实际上下文提交遵守授权与引用规则。
- 选区、PDF 页码、对象版本和附件以可查看、可移除的引用呈现。发送时固定实际提交的引用，后续翻页不能改变已发送请求。
- 在输入框粘贴文件或图片时，直接复用消息附件列表与上传校验，不另加入口或自动发送；普通文字保持原生粘贴与撤销。只接收本次粘贴实际携带的文件，不轮询剪贴板，不把文字路径或图片网址当作读取授权。附件随原草稿保存，异步完成不串到其他工作现场；超限和失败在输入处明确提示。
- 模型可调整，但模型不是另一个 Agent 身份。默认值属于空间或应用策略，运行中变更必须说明影响哪项工作及何时生效。
- 输入框的可见高度上限是布局约束，不是文本长度、录音时长或可阅读书籍的业务上限。

### 4.3 并发、跟进和消息组织

普通消息只用位置区分：本人在右，Agent 在左，不重复显示“我”、Morphz 名称或头像。时间与复制按钮放在正文下方，鼠标悬停消息或键盘聚焦时显示，无悬停能力的设备保持可用。复制只取该条正文，不混入时间、姓名或执行状态；成功与失败按真实结果反馈。多人协作时只补充其他参与者的身份。未发送、失败、取消等必要状态保留，不把“已完成”重复标在每条正常消息上。

正文与工具参数按实际流事件更新，工具执行状态以 Runtime 回执为准；不能把参数生成完毕当作执行成功。工具详情默认折叠，结果到达后就地更新，不追加重复回复。断线恢复用持久记录校准，缺失前缀的增量不拼成假完整消息；不展示模型隐含推理。

不在人的消息里重复显示“排队中／正在发送／正在处理”，也不在列表末尾另放全局处理状态横条。首字前必须有反馈：在对应输入之后的回复区域，以轻量呼吸点和短文案展示实际投递状态；首次可读正文或交付到达后撤下等待提示。它不是消息、不持久化、不参与复制或未读计数，也不因不支持停止而消失。断线改为静态“连接中断，等待恢复”，停止确认、失败、取消和审批按真实回执呈现；不猜测“思考／检索”等未观测阶段、不展示假进度。减少动态时保留静态点和文字。用户向上阅读时不抢滚动。

仅当 Runtime 的最新有效快照确认为 `kind=execution` 且生命周期仍为 `open`，才对对应的整个人类消息显示沿边缘运行的光晕；普通 `dialogue_turn`、投递、旧协议未知类型、结束或失联状态均不显示。移除绿点加箭头，不从“已发送／running”猜测后台线程。光效不挡住文字选择和附件操作，减少动态时保留静态边缘。停止入口归属对应用户消息，与时间、复制按钮放在同一个消息操作区，悬停或键盘聚焦时显示红色方块图标，不随输出移位；触控直接显示。仅在实际支持停止时提供，每项并发请求独立停止；后台执行分支仍在执行面板独立停止。停止待确认或断线时禁用，不冒充已经取消。

流式正文的新增文字本身做约 520ms 的淡入与轻微去模糊；末尾显示清楚可见的主题色三点提示，暂时没有新文字时继续运动，正在生成参数的工具名称旁保留轻微呼吸光标，不增加重复状态行。按新到内容的原始偏移及到达时间定位，不重播历史、重连前缀、已有文字或整段 Markdown；Markdown 重建时沿用片段原时间，不闪回。代码和数学结构保持原样，不为动画延迟、缓冲或重写真实文字。动画只跟随有效连接下的真实流状态，结束或断线撤下提示，减少动态偏好将三点静态呈现。验证正文、列表、引用、代码及表格末尾。参考 [Streamdown 的文本节点动画设计](https://streamdown.ai/docs/animation)，在现有安全 Markdown 渲染器内实现，不引入另一套完整渲染依赖。

待审批请求在原输入下就近展示，并在执行概览前部跨工作可见；切到别处仍保留顶栏提示，不自动打开面板或抢焦点。先展示真实操作和新增权限范围，再提供“拒绝／仅允许这一次”，完整请求可展开核对。界面只使用持久输入／根／线程绑定的作用域，后端重新校验审批原文指纹；断线、过期和未知结果禁止伪装成功。主消息、右栏和详情共享已提交决定的保护，同一请求不因切页或重复点击再次发送；不自动授权、不扩大到线程／Session 永久权限。

本人消息气泡采用当前主题色的淡色底面，只包裹正文与必要状态，不为隐藏的时间和复制按钮保留内部空行。点击发送后立即显示同一 ID 的本机待提交气泡并清空输入框，后台回执不得清掉新草稿。未提交成功时保留原气泡，旁边显示重试图标；重试沿用冻结的请求 ID 和载荷。权威历史确认后原位去重，本机展示不冒充已接收或已执行。可选操作悬浮于气泡外，悬停和键盘聚焦不改变气泡高度。

主消息流按发布时间排列，不能把迟到的最终交付插回旧问题下面。流式正文首次可见时固定位置，后续增量和终结回执就地更新；独立交付另行追加。通过来源引用保留因果关系，工具细节移到右栏。用户向上阅读时不抢滚动。

按读者本地日期分隔连续历史，日期带年份；分隔不改写消息时间或归属。同一真实输入的相邻回复／交付保持紧凑，不同工作之间增加间距，不按时间猜测缺失的因果关系。交付入口显示“交付内容”、当时标题及准确版本；历史消息中的对象引用同样打开保存的版本。中文标点强调与 GFM 表格由解析扩展处理，代码、转义、复制正文和存储原文不改写；表格与代码在各自内容区横向滚动，HTML 与远程媒体安全限制保留。

- 按输入／事项／执行链建立明确关联。同一项工作的进度可折叠，最终结果突出；完整交流的顺序仍保留。
- “另做一项工作”与“补充正在进行的工作”必须区分。支持从具体工作附近发起补充，输入处显示跟进目标；多个任务并发且指代不清时轻量澄清，不静默猜测。
- 普通对话直接继续发消息，不设独立“补充”入口。只有明确的后台工作（`kind=execution`）才提供“补充要求”：点击后将原输入框定向到这项工作，显示可移除的“补充给”目标。只在连接有效且实际线程仍开放、支持补充时显示，消息与执行详情使用同一边界。查看执行详情、切换页面和只剩一项执行都不能暗中选择目标；同一输入有多个可补充分支时先选择具体分支。保留现有悬浮 Dock 和普通发送行为。
- 定向补充使用原输入、Thread／Objective 的精确身份和代次，沿用原模型、Harness 与权限；不把当前页面、目录选择或模型选择带入原执行。送达只显示“补充已送达”，不等于已经采用或执行成功。已发生的操作不撤销、不重放。
- 目标已结束或暂停时保留草稿；明确选择“作为后续请求继续”后，再由用户发送一项有历史关联的新请求。未知回执冻结同份投递，仅允许核对原命令；刷新和重启也不能换 ID 重发。旧 Runtime 未声明支持或未安装相应输入格式时不提供假入口。
- 默认不要求用户理解线程或调度策略，也不能把所有输入一律当作独立并发任务。
- 单项停止与取消排队留在对应用户消息旁，失败重试也留在原输入旁；后台执行分支在执行面板操作。不因操作输入框或切换界面停止工作。全局停止必须另行明确。重试不能重复已发生的外部操作。
- 回复通过真实输入、根执行与线程标识建立关联；发布时间只用于阅读顺序，不用于猜测归属或决定工具权限。

### 4.4 滚动与回执

消息列表隐藏滚动条外观，仍支持滚轮、触控板及键盘滚动，不禁用滚动容器或移除“返回最新”。只要离开底部就显示“返回最新”，不以有未读内容为前提；随后收到新内容时改为“有新内容 · 返回最新”。用户在最新位置时跟随回复；向上阅读后保持当前位置。只有用户主动发送、展开或点击返回最新时，才按明确规则定位对应内容。后台其他任务输出不能强制滚动当前阅读区。

“返回最新”贴近可见阅读区底边，并位于悬浮 Dock 上方；底部安全空间只计算一次，不因按钮显示而增加滚动高度。鼠标或键盘激活后，在按钮消失前将焦点移回原输入；普通滚动与新内容不抢走其他控件的焦点。移除附件和撤销目录权限等会移除当前控件的动作，同样应将焦点交还稳定的输入或原工具，异步返回不得抢走后续输入或其他范围的焦点。验收必须包含未固定的事项／工作页、近期和完整记录、Enter／空格、真正离开后仍自动收起、长草稿／窄窗和真实 Electron 200% 缩放；只在纯对话或固定输入上通过不算覆盖自动收起路径。

底层保留已保存未发送、发送中、已接收／排队、执行中、等待人、完成、失败和已请求停止的区别；不意味着要把每个中间状态都写在消息里。需要人处理的异常与结果依据真实回执展示，短暂提示不代替持久记录。人类的回应、拒绝、修改和交付保留作者归属及其实际影响。

“有新回复”只依据当前展开范围内可显示的回复、错误或交付；后台进度、工具状态、空正文和快照重排不能触发。已读按中心与身份在本机持久保存消息身份及正文变化指纹，不保存另一份正文；流式正文转为相同正式回执不重复提醒。首次没有已读记录时把已有历史作为基线，不宣称历史都是新消息。只在前台、没有模态遮挡且读到最新时确认当前范围，打开旧阅读位置不清除下方的新回复；收起、刷新和切换对象不清除真正未读。

内部 infer 的流式中间结果不冒充用户回复；主交流中的流式文字须有实际输入归属，内部执行仍在执行检查器查看。已经显示给用户的正文不因工具选择、assistant_call 或短暂断线而撤掉；断线停动画、保留已读到的前缀，不能拼接未知的重连后缀。正式回执按同一次发布原位替换，保持首次显示身份与时间；快照与流重放按持久事件顺序合并，早期错误不能覆盖最终错误而触发假未读。后台进度不能占用正式回复的展示身份。

长历史下输入和流式更新不能反复解析未变化的历史正文；正文解析缓存与权限／对象可见性分离，撤权和对象更新仍立即生效。宿主同一同步发布批次只读取一次新工作空间快照，不逐条读库；下一批必须重新校验，不用跨批次缓存替代授权。性能回归包含长正文和表格、连续输入、流式增量、主线程长任务，以及撤权后同一正文链接更新；另在原 Desktop 复验滚动、返回最新与展开／收起，不以隐藏历史、丢草稿或改变既定 Dock 换取速度。

正常关闭应用由页签消失和工作区切换表达，不另外生成“应用已关闭”的常驻提示，也不以固定文案宣称后台存在运行中的任务。移除全局底部状态栏：普通保存、排队、同步、安装成功由实际内容或回执表达，不额外提示。发送失败在原范围的输入框旁保留，断线与重连放在侧栏连接入口，输入区同时标出离线并保留草稿；其他必要异常用不参与页面布局的紧凑提示，不挤动整个页面。不能删除失败或把未发送显示成成功。

## 5. 弹窗、搜索与检查器

### 5.1 按用途选择容器

| 用途                                | 容器                                   | 原因                                       |
| ----------------------------------- | -------------------------------------- | ------------------------------------------ |
| 搜索并打开内容                      | 快速搜索面板                           | 输入和结果是主体，不是表单填写             |
| 改名、设置项目、简短确认            | 小型对话框                             | 有明确开始和结束的单一动作                 |
| 模型、排序、外观的少量选项          | 菜单或锚定弹出层                       | 保留选择发生的位置                         |
| 批注、关联、对象属性                | 中间应用内的详情或就近辅助区           | 属于当前内容，不占用 Morphz 主体右栏       |
| Morphz 状态、活动、授权、安排与设定 | 主体右栏                               | 围绕同一个助手，不随应用切换身份           |
| 导入多个文件、接入来源              | 明确的导入流程；长任务进度可留在工作区 | 关闭界面不应让人不确定导入是否继续         |
| 写文章、编辑小说、剪视频            | 应用主画布                             | 长时间创作需要空间，不能装进“新建文档”表单 |
| 重要授权或不可逆动作                | 范围明确的确认对话框                   | 明确由谁、对什么、允许做什么，保留取消方式 |

同一时刻一个主要模态任务。不要在搜索上叠导入、再叠编辑；先完成或退出当前步骤。标题说明任务，主按钮描述动作，避免所有按钮都叫“确定”。

现实现的执行、当前理解和对象批注共用宿主检查器，同一时刻只显示一种；这属于迁移前的状态。2026-10-01 新目标以第 3 节的 Morphz 主体右栏为准，对象辅助内容归中间应用，不能继续将所有检查功能叠进右栏。右栏仍贯通窗口可用高度，标题与显隐控件保持可达，宽度、停靠／覆盖与焦点基线继续复用；本次文档确认不新增认知应用扩展协议，也不宣称对象面板迁移或主体设定编辑已经实现。

按宿主实际可用宽度选择停靠或临时覆盖，不只判断总窗宽。停靠时中央画布至少保留 640 CSS px，检查器共享 280–520 px 的首选宽度，默认 340 px，可拖动或用方向键调整；自动收缩不覆盖用户首选值。容不下 640 + 280 px 时，检查器覆盖主区右侧，最多 340 px、不超出可用范围，没有模态遮罩，未覆盖的画布仍可操作。浏览器遵循同一布局：临时覆盖不缩小网页，明确停靠才按主画布实际宽度排版；不重开页面、不改变协助权限。

标题和关闭始终可见，长记录在检查器内部滚动。关闭与 Escape 使用同一规则，回到对应入口，不让之前被替换的面板重新弹出。固定执行只固定检查范围，不能跟随当前页面改写原输入／线程、Session、草稿或授权。仍需模态的授权与输入弹窗继续遵守主内容区居中规则。

所有宿主弹窗共用紧凑标题行，当前基线为约 32 CSS px 高、14 px 标题字，标题和关闭按钮同行，顶部及标题后的间隔各 4px。对象范围等短信息可同行排列，长信息移到实际相关内容，不用顶部大留白撑高。通知的标题、提醒范围和关闭按钮直接在同一行，取消设置说明的常驻大块区域；说明由控件提示及可访问描述提供。底部确认操作不另铺突兀的浅色长条；长表单固定操作区沿用弹窗材质，滚动内容不能穿过按钮。权限、隐私、失败与执行边界属于必要内容，不能借压缩标题隐藏。

弹窗的单行输入、选择框与表单动作共用 32 CSS px 高、13px 字号和一致圆角，触屏保留 44px 操作目标及 16px 输入字。新建／改名的同行输入和确认按钮顶底对齐，主次动作不能因按钮类或是否套在 `form` 内而高矮不一。字段聚焦以贴合边界的 2px 内描边表示，不再叠加灰框与有间隙的彩色外圈；按钮保留独立键盘轮廓。正文、多行文本、图片与包含多项信息的账号连接行不套单行高度，搜索保留其专用布局。收藏及嵌入设置中的步骤标题也复用标题对齐规则，不能因为 DOM 多包一层就失去样式。

只有一个名称字段的新建／改名弹窗采用两行：标题与关闭一行，输入与现有操作按钮一行。名称提示放在输入框内，并保留独立可访问名称；不再用“名称”“项目名称”另占一行，也不为这类短表单另起底部按钮行。标题结束到输入框最多 4px，窄窗按实际可用宽度换行，而不是一到手机断点就强制堆叠。保存范围、错误与多字段表单的可见标签仍保留；不能靠缩小字体或隐藏必要信息实现紧凑。回归须直接检查这两行的实际位置和整窗高度，不能只检查输入与按钮等高。

弹窗空间利用属于必须回归的功能要求：通用容器只负责边界，短表单、资料导入、转写和图片预览通过同一 `--ui-dialog-width` 选择合适宽度，不让后加载的短表单样式把媒体预览压窄。重新选择、检查连接等常用动作与标题同行；截图名称与确认操作共享紧凑底栏，窄窗按控件宽度换行，不另叠标题字段、大间距和装饰分隔层。图片按自然比例与可用高度定宽，大图获得阅读空间，竖图不套宽大空壳，小图不强行拉伸；没有图片或失败时不保留空预览占位。权限、错误、取消、草稿和确认前不上传的边界保持。

验收必须检查实际渲染几何而不只断言按钮存在：横图、竖图、长横图、小图；320px 至桌面宽度；长名称与错误；键盘焦点及真实 Electron 200% 缩放。正常宽屏截图的标题／名称／操作总占高应保持紧凑，预览成为主体；窄窗的关键操作始终可见、无横向溢出。当前未确认的截图不得为刷新或展示新布局而丢弃。

### 5.2 搜索面板

- Cmd+K 或可见搜索入口打开，焦点必须进入输入框，不能落在关闭按钮。
- 搜索框置于面板最上方；不要先用大标题和大段说明挤占空间。范围筛选采用紧凑控件。
- 搜索面板按主内容区水平居中，不把展开的侧栏计入可用宽度；侧栏收起或改为顶部导航时，跟随实际内容区居中。窄窗口下宽度也受内容区约束。
- 搜索不显示关闭叉号。点击面板外部或按 Escape 关闭，恢复原焦点与选区；面板内操作和从内部拖选到外部不误关闭，外部点击也不穿透触发底下的页面。
- 搜索面板使用中性色层次：不叠加输入外框、彩色分隔线与选中竖线。输入以光标和轻微加深的分隔线表示焦点，结果用中性底色区分选中；范围筛选与行内 AI 入口保持中性。键盘切换到控件时保留可见焦点描边。
- 全局搜索默认显示全部有权访问的内容；局部搜索明确标出当前范围，两者不混淆。
- 空查询显示少量最近打开或搜索记录；尚无数据时提供简洁引导，不造假结果。
- 边输入边反馈；结果优先显示名称、类型、所属空间及必要摘要。版本、技术来源等细节按需展开，不给每条结果套一张大卡片。
- 空白分隔的多个关键词按 AND 字面匹配，不要求用户记住完整连续原文；单个词的符号不擅自解释为查询表达式。权限、PDF 原文与页码、稳定分页必须保留。
- 结果标题、归属、摘要和具体来源共享打开区域；无具体来源时不重复显示“工作空间内容”。文字拖选不误导航，引用按钮独立且不自动发送。摘要仍最多两行，命中词高亮不是必需元素。
- 搜索中的引用是围绕原文与 AI 交互的上下文入口，不预设只能提问。采用 A 的行内方案：引用气泡图标（气泡内含引号）＋“AI”，与结果行垂直居中；默认无彩底、无描边，悬停／聚焦时给中性底面和清晰反馈。桌面只显示当前选中行的入口，鼠标进入与键盘聚焦同步选择，保留动作占位防止文字跳动；无悬停设备直接显示入口并保留 44px 触控目标。可访问名称使用“AI 交互：具体对象”，悬停提示仅标明“引用《具体对象》”，不复述内部流程或“不自动发送”等实现约束。不得把独立预览描述为实际应用已经生效。
- 最近修改与搜索结果的空间归属、页码及具体来源放在标题同行的右侧，不为“工作台”等短标签或路径新增一行；长标题与元信息各自省略，保留完整提示和可访问文字，标题至少保有主要宽度。摘要在下一行开始，引用仍为独立操作。
- 搜索预览优先从最早命中词所在句子的边界开始；PDF 中与可见页码一致、且非查询目标的尾部页码标记可在预览里省略。原文、版本与实际引用不变。与标题相同的单个文件名不再重复常驻，完整来源仍在提示及对象来源视图。此规则不是中文语义检索或通用 PDF 页眉页脚识别。
- 上下键选择、Enter 打开、Escape 返回原位置。打开结果进入正确空间与对象；AI 交互入口可通过原生 Tab 到达，带入引用后在现有输入区显示原文及作用对象，不能暗中改变发送范围。
- 搜索失败不显示成零结果。请求竞态、输入法候选确认、翻页及范围变更均有测试。
- 未来项目、应用、对象、事项可以统一检索，但当前未接入的类型不在占位文字里声称支持。

2026-09-11 当前搜索审计与未解决的中文分词／容量／数据库边界见[产品流程与视觉体验审计](./23-product-experience-audit.md)，不得把多关键词修复称为海量文档方案已经完成。

### 5.3 焦点与取消

依据 [WAI-ARIA Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)，真正的模态需要聚焦内部、约束 Tab 路径、提供关闭操作，并在退出后恢复触发位置或合理的下一操作位置。仅声明 `aria-modal` 不算完成。

关闭搜索应返回原输入焦点、编辑选区和滚动位置。关闭有未保存内容的界面，应保存草稿或明确提示；不能无声丢弃。录音与设备采集必须始终有清晰状态和停止能力，界面收起的行为不能让用户误以为已停止但仍在采集。

系统截图分为选区和确认两个阶段。点击截图入口直接进入选区，不先打开需要再次点击开始的弹窗。开始选区前，截图弹窗、遮罩及输入／半开交流浮层暂时隐藏，画布尺寸与网页滚动位置保持不变。完整对话页的消息本身就是画布，不能一并隐藏，只暂时移走输入。等待网页可见／授权状态同步与绘制完成再打开系统选择器，不能截到旧的遮罩。完成后显示确认预览；初次取消直接返回输入区，先恢复显示再恢复焦点；失败显示真实错误并等待明确重试，不自动重复采集。重新选择失败或取消保留旧预览，输入草稿不变。确认前不上传，不自动发送；添加到消息与保存到内容仍是两个独立动作。

按住 macOS Option 或 Windows／Linux Alt 点击截图入口时，本次选区前隐藏整个 Morphz 主窗口，读取选定范围后恢复窗口与预览；取消、失败也恢复。普通点击仍保留工作画布，重新划区按本次点击的修饰键处理，不记成永久偏好。已关闭的窗口不能被迟到截图重新打开，窗口隐藏不停止后台工作或丢弃草稿。提示放在按钮 tooltip，不新增常驻教学。修饰键语义跨平台统一，不表示 Windows／Linux 的原生截图后端已实现。

图片附件的缩略入口与放大预览使用不同尺寸规则。缩略图样式不能通过祖先选择器影响模态中的原图；放大后在可用视口内按原比例展示，窄窗口不溢出、不拉伸，关闭后恢复到原附件入口。

## 6. 视觉与布局基线

以下是 Morphz 的首版工程基线，不是 Apple 规定的尺寸。必须在真实桌面窗口里验证；用户缩放、文本长度、窗口大小和专业应用需求优先于固定像素。

| 项目             | 建议基线                                                     | 约束                                                              |
| ---------------- | ------------------------------------------------------------ | ----------------------------------------------------------------- |
| 间距             | 4 / 8 / 12 / 16 / 24 / 32 CSS px                             | 用共享 token，不逐页凑数字                                        |
| 导航侧栏         | 默认 280，展开可调 200–360；图标栏 80                        | 拖到 160 以下切为图标栏；移动端保留顶部导航                       |
| 应用标签栏       | 单行约 48 高，加平台安全区域                                 | 与窗口工具栏合并，避让真实系统控件；多应用横向滚动，不折成第二行  |
| 列表行           | 约 36–44 高，按内容适配                                      | 不靠加大外边距冒充舒适；多行摘要另用内容行                        |
| 文字             | 系统字体；导航／控件约 13–14，正文 15–16，标题 20–24         | 辅助文字通常不低于 12；长文、代码由应用设定阅读排版               |
| 消息与输入阅读列 | 最大约 760，左右至少 24 留白                                 | 随可用空间收缩；专业画布可全宽                                    |
| 快速搜索         | 默认约 640 宽，最大不超过窗口减 48；上方约留 12–18% 窗口高度 | 初始紧凑，结果增长时上边缘稳定；最大高度约 65% 可用高度，内部滚动 |
| 简短对话框       | 约 400–480 宽；中型约 560–640                                | 高度由内容决定，不强行所有弹窗同一比例                            |
| 检查器           | 约 300–360，可收起                                           | 在窄窗口只展示必要辅助区，不同时挤入多个面板                      |
| 图标／点击区域   | 图标通常 16–20，常用图标按钮点击区域至少 32×32               | 图形大小和点击面积分开；兼顾键盘和触控                            |
| 圆角             | 控件约 6–8，面板约 12                                        | 由层级决定，不为每个图标再画一个圆角框                            |

展开交流时先按主区约三分之一高度验证，允许调整；当主内容没有足够空间时，不硬塞三层窄区，而由用户选择交流的聚焦态，并能准确回到原应用。窗口 760×540 的现有桌面下限也必须覆盖；不能只验证大屏截图。

2026-10-01：左栏拖动时只更新布局，松手保存本机视图偏好，Escape、失焦或指针取消恢复原宽度。图标栏复用对话、事项、内容、工作台、项目五个原导航入口；项目入口仍打开原项目目录，按名称选择项目或新建，不另加文件夹图标列。底部个人菜单收纳搜索、外观、通知、设置，保留身份状态和未读提示；按用户后续要求移除独立「更多」。展开侧栏保持原完整导航。隐藏图标栏不清除其宽度偏好，恢复按钮始终留在主区并避让 macOS 原生红绿灯；重新显示恢复图标栏。左右拖动边界共用连续的 1px 中性细线，悬停、拖动和键盘焦点仅轻微加深，不出现主题色粗线、焦点矩形或阴影；命中范围独立保持 8px。Mac 原生按钮坐标使用逻辑像素 `(8,16)`，80px 图标栏在原生按钮组与分界之间留白；拖动命中从分界左侧 4px 开始，顶部仍避让不随页面缩放的原生控件。展开宽度与收缩阈值不受此定位修正影响。

图标栏五个一级导航使用 24×24 SVG、至少 44px 高的点击区；品牌标记为 32×32，和导航图标光学居中在同一轴线上。底部个人工具入口保留 20px 图标，不与主导航争夺层级。展开态仍使用原 17px 导航图标和 23×25 品牌标记；移动端不套用窄栏放大规则。实际路径轮廓与 SVG 外框不是同一个尺寸，不能只统一外框而忽略视觉重量。

当前通用界面图标采用 [Lucide](https://lucide.dev/guide/) SVG，品牌标记和五个核心导航使用 Morphz 专用矢量；只有窗口红绿灯等系统控件由操作系统绘制。图标设计按作用区分：成熟通用操作优先复用统一图标库，独有的产品概念才需要专门选型或定制；定制也须遵守同一网格、笔画、圆角、光学对齐及可访问名称。早先的尺寸修正不等于图形重设计，随后确认的核心图形替换见下段。对照 [Apple SF Symbols](https://developer.apple.com/design/human-interface-guidelines/sf-symbols) 的通用／自定义符号原则和 [Microsoft Fluent](https://fluent2.microsoft.design/iconography) 的界面／产品／文件图标分工，而不是把“大厂图标”理解为全部取操作系统默认值。

五个核心导航的图形参照见 [核心导航图标](design/core-navigation-icons.svg)。2026-10-01 用户确认后已替换正式界面：目录入口名称为「内容库」，工作台选择 B 分区三卡；项目名称保持，暂用 A 简洁文件夹，待实际界面观看后再定。项目夹与叠放项目夹只留作设计候选，不进入运行组件；被排除的工作包及节点连线图形已移除。气泡表示交流、勾选与待办清单表示事项、错位内容卡片表示成果；内容库不局限书籍，工作台同时表达开始与继续工作，项目文件夹表示工作集合而非真实磁盘目录。五个符号由 `NavigationIcon.tsx` 统一绘制，使用透明 `currentColor` 线稿、24×24 网格、2px 圆头线；后卡只绘制露出的线段，不能用白色填充遮挡以致暗色主题穿帮。核心图形独立设置2px笔画，避免通用SVG的1.65px规则覆盖；保留原导航按钮、17／24尺寸、点击区和中文可访问名称，工作空间的全局内容入口同步「查看内容库」，项目入口仍为「查看项目内容」。Logo保持现有品牌轮廓，通用操作仍用 Lucide，不因定制一级导航而更换整个图标库。

图标栏底部只有一个个人工具菜单，不保留独立「更多」及第二个点击区。底部按内容高度占位、不被 flex 压缩；导航区承担小窗的滚动。验证覆盖完整控件边界、容器包含及真实鼠标命中，不能只检查 SVG 尺寸或元素在窗口内。无退出能力时仍可打开真实应用工具，但不虚构账号操作；菜单切换、关闭和设置返回不丢输入草稿及焦点。

迟到或跨输入回复以原消息单行短引文和中性引用线表达关联，不使用“关于”标签、回折图标或尾部箭头。引用保持中性、可点击与键盘可达，仍按确切输入 ID 打开原消息的执行记录；不按短引文匹配、不改变消息发布时间顺序，也不重复显示同一来源的连续回复。

### 6.1 颜色与材质

保持 Dashboard 四组主题：电光青、鸢尾紫、暖珊瑚、纯单色。复用实际主题 token，亮暗分别检查，不凭截图重新取一个“类似的青色”。中性背景、清晰层次、少量强调色；不把全页染成品牌色，不靠大面积玻璃、阴影或渐变增加装饰。

四种强调色源保留在 `apps/web/src/styles.css`；共享中性色、材质、边界、阴影与动效 token 位于最后加载的 `apps/web/src/visual-system.css`。不要在认知应用中各自复制宿主配色。危险、警告、成功有独立语义，不随品牌主题变成任意颜色。正常连接和自动保存不必长期占据整条状态栏；异常与尚未同步必须清楚可见。

2026-10-01 用户确认：底面白净、主题浅色清透、减少立体装饰，保留现有布局和操作。亮色主画布及顶栏使用纯白 `#ffffff`；侧栏使用亮色 `#fafafa`、暗色 `#242424` 的不透明实底，不绘制渐变或侧栏阴影。正文、输入周围及侧栏收起后的主区始终保持实底，四组品牌强调色源、尺寸、间距及命中位置不变。

主导航、项目和子会话共用平面选中底面：`--accent` 占 12%，与 `--paper` 混色；窗口失焦后占比减为 8%，选择仍保留。选中项悬停时保持自己的底色，不能被普通灰色悬停面覆盖；键盘焦点独立显示，增强对比度时保留清晰的 1px 状态边界。默认选中态不叠加亮边、光泽或投影，不因绘制状态改变行高或按钮位置。

本人消息气泡使用独立的 `--human-message-fill` 面色：亮色保留现有主题色相，饱和度 90%、明度 88%，不再由深色前景简单混白；纯单色使用中性 `#f0f0f0`，不能把它染成浅蓝。暗色仍使用 25% `--accent` 与 `--paper` 混色。品牌按钮／链接前景及导航选中态不随气泡面色改变。气泡内引用来源小字在实际叠色底面上保持至少 4.5:1，亮色用辅助正文色，暗色用正文色。气泡不加描边或阴影。普通控件采用平面底色，不以立体投影增加装饰；弹窗、菜单和悬浮交流等覆盖层仍保留必要的层级投影。消息操作、输入与悬浮 Dock 的布局、焦点和交互规则保持原样。

本轮覆盖 2026-09-11 的侧栏透明罩色、渐变、细亮边和失焦光泽视觉规范。桌面壳仍保留 Electron 原生外观及辅助功能协议，包括跟随系统／亮色／暗色同步、窗口活动态、减少透明和增强对比度；前端以不透明侧栏底面绘制，不再通过 CSS 透出其材质。这不表示移除了原生 `sidebar` vibrancy，也不把 CSS 绘制或热更新描述为主进程材质验收。

通知弹窗使用紧凑标题，设置按钮进入统一设置的「通知」分类，「全部提醒／不提示」两项原生单选控件不再夹在通知列表里。通知按实际事件时间排列，不再使用高／普通／低优先级排序、标签或筛选；事项顺序与通知已读互不影响。旧已读及待补记回执继续有效，旧「仅高优先级」偏好不静默扩大提醒范围，暂不提示并要求本人重新选择，不能把兼容兜底伪装为用户已经选择了「不提示」。中性色表示选中，键盘焦点另行标识；打开通知先聚焦标题，不自动进入设置。未读状态使用小标记与可访问名称，空态不保留多余高度。

外观模式的持久选中态不能复用与底槽相同的表面色。按用户反馈，选中项只使用独立中性底块与稍重文字，不加白色描边或环形阴影；亮色底槽也与选中面拉开明暗。移开鼠标或聚焦另一项后仍能辨认，悬停和键盘焦点不冒充当前选择；键盘操作时保留独立焦点框。“跟随系统”仍表示所选模式，不随系统亮暗变化而改成选中“亮色”或“暗色”。

普通文字以 WCAG AA 的 4.5:1、大号文字 3:1 为检查基线，包含辅助说明与占位文字；不能为了“高级灰”让信息难读。控件目标按 WCAG 2.2 的 24×24 CSS px 或相应间距／例外要求检查，Morphz 常用图标按钮采用更宽裕的 32×32 基线。不能把桌面一律写成 Apple 要求 44×44。[对比度依据](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；[目标尺寸依据](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

暗色侧栏的 `#242424` 实底保持 RGB 通道相等的中性烟灰，不额外加入蓝／紫冷色偏移；主题浅色用于明确的选中项及本人消息，侧栏底色不随品牌强调色变化。

桌面壳的原生材质与窗口透明背景必须在窗口创建阶段一并配置，不能先创建不透明绘制表面再事后转换；前端的实底配方不改变这一原生配置边界。系统外观通知按实际变化应用，重复通知不重设材质、广播或重写相同 DOM 属性；窗口焦点变化仅更新活动态。验收包含菜单关闭后无残影、侧栏无异常分块和亮暗切换，不能只凭 CSS 数值或静态单帧判断连续闪烁已解决。

### 6.2 文案与可访问性

- 日常界面只呈现当前内容、状态和操作，不把设计理由、内部处理过程、重复操作教学或安全承诺写成常驻段落。标题和按钮已说明的内容不再解释一遍；空态只说明当前没有什么。简短提示描述动作，格式／容量／服务详情按需展开。首次权限、实际费用、数据丢失、版本冲突与错误仍在发生处明确呈现，不能作为精简文案而被隐藏。
- 文字采用语义层级：`--ink` 用于标题与操作；`--text-secondary` 用于摘要及辅助正文；`--muted` 用于空间归属、版本、时间和计数。不能把整块容器调低透明度来弱化文字，也不能把正常控件染成禁用态。默认搜索选中面上的三层小字均按至少 4.5:1 检查，不能把该抽样视为全部产品已经完成无障碍审计。
- 次要动作共用 `secondary-action` 的中性底色、边界、字号、间距和焦点规则；用易识别图标加简短动词，不堆“让某某做某事”的长句，也不一律改为无提示的纯图标。导航、筛选、窗口图标和正文链接有不同职责，不批量套成按钮墙；搜索引用气泡是行内交互入口，遵循 5.2 节，不套用常驻底面和边界。完整操作语义留在可访问名称和提示中；完成、删除、授权等后果必须在用户可见文案里明确，不因追求简短而隐藏。
- 搜索、通知、设置／确认等信息密集弹窗采用约 98% 不透明的厚实中性材质；外观、空间、输入等轻量菜单与选中文字工具使用约 95% 不透明的同族材质。只让底面轻微透底，文字／控件不整体降透明度；暗色底面、选中行和内部次要填充不主动染蓝／紫。弹窗与菜单分别统一细边界、近处投影和柔和远影，模态遮罩轻于旧版，尺寸、排版与命中区域保持。CSS 模糊不称为原生 Liquid Glass；原生网页上方、减少透明和增强对比度时回退到实色并关闭模糊，增强对比度保留清楚的边界与控件。半展开交流沿用自身材质。四种品牌强调色保持，强调色不用于装饰每个次要动作。
- 面向用户统一使用自然中文：事项、项目、工作台、资料、引用、执行记录。保留 Morphz 品牌和用户选择的模型名；不混排无必要的 Inbox、Workspace 等英文菜单。
- 控件有明确可访问名称、键盘路径及可见焦点。图标提示不是无障碍名称的替代品，关键行为也不能只有 hover 才可发现。
- 应用卡片单击即打开，使用原生按钮语义，键盘聚焦后按 Enter 或空格打开；不再用双击启动或附加的“打开应用”按钮。打开中的禁用、已打开页签、正在运行和等待处理是不同状态。
- 正文与控件支持缩放。长文或代码的横向滚动只发生在内容区，导航与普通表单不产生整页溢出。
- 状态变化不能只靠颜色。流式输出不要每个 token 都打断读屏，使用合适的状态播报粒度。
- 遵守系统减少动态效果偏好；交互不能依赖动画结束。参考 Apple HIG 的目的性、连续性和可打断原则：控件反馈 110ms，临时面板 180ms，空间展开 220ms（Morphz 产品基线，不是 Apple 指定尺寸或时长）。消息增量不做假打字，普通导航不整页重播入场；原生截图立即隐藏浮层，不残留退出动画。
- PDF 不套文档标题、作者日期和独立分页栏；分页与朗读等并入现有顶栏，页面与顶栏间只留 8px。文件信息按需展开，选区提问与批注就近显示，不为禁用按钮常驻另一行。

## 7. 认知应用界面的共同契约

GUI 是可选、可按平台适配的界面扩展。当前格式仍是 Morphz 应用层的实验扩展，不是 Runtime 稳定标准，成熟后再讨论标准化；本轮 UI 优化不修改 HNS 标准。

宿主统一导航、空间身份、主题 token、输入与交流、权限确认、错误与异步状态。应用自主决定工作画布和领域工具，例如章节、大纲、Git、时间线。主题接入不强制所有专业应用长得一样。

领域内容和运行状态属于中心或授权的对象存储；选区、面板尺寸、滚动和布局属于视图状态。关闭界面不取消已提交的任务，安装或打开界面不授予额外权限。人可以直接编辑，Agent 的修改需基于有效版本；冲突有可理解的处理路径。

专业编辑器替换可以逐项推进，但禁止宿主层再次建立“所有内容都用一个弹窗文本框编辑”的惯例。

事项默认是阅读与行动界面，不是禁用的字段表单。正文直接呈现，负责人、优先级、时间等以紧凑属性展示；人工事项不展示无意义的模型框，低频安排与元数据按需展开。手动编辑仍是明确可选动作。移除外层大卡片套输入框、无内容占位高度及大段内外边距；事项利用主内容区宽度，不套文档的窄版纸张。事项目录内打开详情时，标题进入现有工具栏，不在正文重复。

事项补充和结果提交都复用主输入框。普通输入不自动等于完成；现有 `respond-task` 会完成事项，因此必须明确显示“提交结果并完成”，保留本人身份、事项版本与服务端权限校验。失败和版本冲突保留草稿，不能静默使用新版本重试。已提交结果作为紧凑内容展示，不再常驻第二个回应表单。

事项清单默认“我的＋未完成”，负责人和执行状态独立筛选，不把“我的”与“进行中”并列为互斥范围。按截止日期分组；“今天到期”不是“今天计划做”，不能混用安排日期。本人普通事项提供直接完成、撤销和重新打开；有后续依赖的人工事项必须提交结果。Agent 工作只展示真实状态，不能用勾选冒充完成。筛选、搜索、新建共用现有顶栏，窄窗合入显示当前条件的筛选弹出层。详见[事项清单调研与取舍](./25-task-list-design.md)。

应用画布使用标签栏下方的完整可用空间。固定工具与滚动内容分开：内置资料应用将创建、筛选和搜索压缩为工具区，资料列表独立滚动；自定义应用 iframe 填充画布，不再以固定最小高度挤出窗口。输入及当前交流覆盖画布，不减少可用高度，不卸载应用。明确展开完整记录时可暂时隐藏工作内容，返回后恢复原现场。

## 9. 实施顺序与交付方式

### 第一轮：工作现场与交流的关系

覆盖空间导航、输入／交流状态、草稿和选区、消息回执、并发来源、未读与滚动。先补所需数据关联，再改界面；不要仅隐藏对话按钮，留下旧的发送跳转逻辑。首轮同时包含无消息、生成中、并发、失败、跨空间和恢复场景。

### 第二轮：窗口层级与公共组件

统一设计 token、顶栏和侧栏规则；提取搜索面板、短对话框、检查器、菜单、异步状态的公共组件。搜索先作为公共层代表完成；之后所有弹窗按用途迁移，不继续各写一份 CSS。公共层必须覆盖不同长度、错误、空态和键盘，不只做漂亮的空弹窗。

### 第三轮：页面减法与对象协作

逐项检查工作台、项目目录、项目空间、事项、资料与对象详情。按页面职责表删掉重复内容，保留真实操作。事项分派、回应、时间／优先级、模型调整和版本冲突是工作体验的一部分，不藏进日志。

### 第四轮：专业应用逐项打磨

在稳定宿主上分别处理写作、代码、阅读、剪辑等应用。不是本轮一次承诺做完所有编辑器；选择已经具备基础的应用先完成真实使用体验，其他应用保留明确的未实现边界。

每轮交付：简短变更清单、对应状态的截图、真实 Electron 验证和自动化结果、未解决项。由实施者完成逐页检查，不要求用户把每个缺陷都列出来；用户主要评审交互选择与整体感受。不以一个孤立模拟流程替代真实应用，也不把临时半成品作为完整交付。

## 11. 公共 UI 首轮落地

已实施并有回归覆盖：

- `hidden / input / recent / history` 为同一交流区的四种布局状态，按工作空间保存。移除顶栏内容／对话切换；发送就地展开紧凑交流，完整记录由用户主动展开。应用保持挂载，正常显示输入时不抢占主体。
- 交流阅读位置按空间保留；追随最新、向上阅读、未读提示和主动返回最新分开。用户收起后，迟到的发送回执不重新打开界面。回复带真实 `inputId/rootId`；无来源的旧记录、没有唯一归属的合并回复不猜测绑定。
- 搜索独立为快速打开面板，默认聚焦输入，空查询显示最近修改的授权对象；支持上下键、回车和 Escape。共享模态钩子恢复触发焦点与编辑选区，菜单关闭后回到菜单触发器。
- 顶栏将导入与当前理解收入空间菜单；批注只在对象存在时显示；移除侧栏最近对象与未使用的旧 Workbench。正常连接不再常驻整条状态栏，操作回执与断线状态仍可见。
- 文档创建移到主画布，文档草稿按中心、身份、窗口、空间保存；取消、切换与刷新后可以继续。项目等短动作继续采用小型对话框；不将当前 Markdown 文本编辑器称为专业写作应用。
- 事项有待我处理、进行中、等待、已完成、全部筛选，显示负责人、优先级和截止时间；项目目录有名称／最近更新排序与区分查询无结果的空态。
- 新的公共样式层集中阅读宽度、间距、圆角、搜索与弹窗布局。四个品牌强调色不变；小字和主要按钮使用可读性更高的既有深色阶，中性辅助文字提高对比度。

执行右栏的固定、收起与宽度调整已实施。当前理解已改为非模态检查器：阅读公开摘要、版本和来源；纠正／更新仍通过统一输入准备草稿，由用户确认发送，不增设第二个输入或自动提交。空间菜单统一使用顶层弹出菜单，键盘与焦点返回沿用共享组件。对象编辑的取消／保存放在已有工具栏，长内容不要求滚到底；表格的筛选、计数和新增记录就近放置，可选设置折叠。

尚未实施的目标明确留待后续，不做假入口：完整消息全文检索、固定项目，以及专业写作／代码／剪辑界面。2026-10-02 普通输入改为默认打断当前会话思考中的回复，Option/Alt+Enter 或按住该键点击显式并发；仅在发送按钮提示中说明，不增加一层工具栏，保留用户 Enter／Mod+Enter 偏好及输入法守门。Runtime 已进入工具执行的工作、目标与安排不取消；旧消息重试模式保持。定向 steering 仅由明确补充目标触发，沿用原授权与路由，不做自然语言猜测。逐场景复查与验证边界见[体验复查记录](./20-experience-review.md)。

规范不止存放在文档中：仓库 `AGENTS.md` 要求后续 UI 改动先读取本规范与实施记录，避免旧导航和弹窗习惯回流。

## 12. 交付、导航与操作语义

- “内容”是固定侧栏入口，展示当前身份有权访问的各工作空间中的成果与素材，提供空间筛选并在条目标注归属。事项仍是底层 Artifact，但界面统一在“事项”入口管理；全局及项目内容列表都排除事项、事项分类、计数和创建入口。事项关联的文档、图片等成果照常显示，关联不删除或复制。旧“事项”内容筛选自动恢复为“全部”。导航保留入口与返回路径，不因对象创建于对话而跳到对话。
- 原通用“资料”不再作为启动台中的应用卡片。工作台的内容入口进入统一目录，项目内容是它的过滤视图。应用打开原对象。旧个人内容归属一次性纠正，原文和执行历史保留，不留旧内容创建路径、不重放工作。
- 内容目录选定具体项目或“未归项目”后，新内容及下一条输入使用该范围；“全部内容”只汇总授权阅读，新内容仍归入“未归项目”，不授予跨项目执行权限。输入关联和按钮提示明确显示归属；打开对象后下一次输入关联该对象与所属项目。全局目录与工作台分别保留草稿、筛选及输入显隐状态，不改 Session 或在途请求。局部空列表不能伪装成整个中心没有内容。
- 交付入口来自真实持久回执，包含准确对象与版本；不能由回复标题猜测。结果在交流中出现时就能打开，无来源旧记录不补造关联。
- 高频操作放在对象或项目旁。进入、退出、返回组成完整路径；返回恢复阅读现场，不切换会话或重放工作。新导航意图优先于旧保存／打开回调。

- 使用 Runtime 实际可用模型，不要求用户填写内部 ID。输入模型只作用于本次提交；事项模型作用于后续执行，不能悄悄改动正在运行的任务。
- 点击通知先确认当前访问权限；已读同步失败不阻止阅读，失败待补记可重试。减少操作步骤不等于绕过身份、对象权限或发布确认。

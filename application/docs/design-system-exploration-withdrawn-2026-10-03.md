## 1. 产品调性：精密的工作现场，有生命感的协作者

Morphz 不应像后台管理系统，也不应像霓虹仪表盘。内容是主体，操作清楚，工作发生时出现局部而有方向的信号；结束后界面安静下来。品牌感来自一致的比例、光学重量、材质和运动语法，而不是每页一张大卡片。

| 原则                         | 可观察的设计决定                                   | 不允许的替代                             |
| ---------------------------- | -------------------------------------------------- | ---------------------------------------- |
| DS-01 内容优先               | 页面第一眼看见正文、对象或当前工作；标题与操作同层 | 欢迎语、大装饰标题、空卡片占掉主体       |
| DS-02 按语义分层             | 导航入口有稳定表面；局部动作轻；权限及危险动作明确 | 所有按钮同尺寸、同胶囊、同强调色         |
| DS-03 事实先于表现           | 状态标记有确切数据来源；语义描述可以缺席           | 为使画面完整补写阶段、成功或百分比       |
| DS-04 连续而不干扰           | 面板变化保留节点、焦点、草稿、阅读位置和工作现场   | 全页入场、迟到回复重新开面板、重建输入   |
| DS-05 有生命感而非躁动       | 工作信号局部、可停、能收束；品牌存在感不等于执行   | 所有地方都呼吸、整页发光、空闲仍显示忙碌 |
| DS-06 同一产品，多种工作画布 | 共享宿主和基础控件，专业编辑器保留自己的结构       | 所有业务强塞同一表单或同一种卡片         |

### 1.1 整体一致不等于全部相同

一致的是间距体系、字体层级、图形家族、反馈方式和状态语义。不同的是职责带来的视觉重量：应用 Dock 是去另一处工作的入口，交流控制是当前面板的局部动作；文档需要阅读宽度，事项需要信息宽度，浏览器需要完整画布。不能用“协调”作为批量缩小或批量套框的理由。

### 2.3 交流区：已确认交互与实现数值样本

保留已确认的交互关系；下列偏移及断点只是对应实现的样本，仍须 §8.5 评审，不能由“用户认可对齐方向”推导“所有数值已获审美认可”。

- 四种布局只有 `hidden / input / recent / history` 一个模型。焦点进入只恢复输入，不自动展开用户已关闭的历史。
- `input`：完整输入卡片；上方无空标题栏、拖柄或按钮占位高度。Dock 居中，交流控制靠右，两组底边对齐；当前代码使底边离输入上缘 8（[application-dock.css:1–25](../apps/web/src/application-dock.css#L1-L25)、[visual-system.css:537–548](../apps/web/src/visual-system.css#L537-L548)）。不是图形中心线对齐，也不是和输入底栏对齐。
- `recent / history`：局部交流控制在阅读面板右上，当前偏移上 8、右 12（[visual-system.css:550–554](../apps/web/src/visual-system.css#L550-L554)）；半透明中性组材质用于避免正文穿过时看不清控件，同组节点保持稳定。Dock 仍在输入附近，不移到阅读标题栏。材质存在不等于遮挡效果或观感已验证。
- 阅读与输入当前生产为分体表面。旧“一体外框”条款已被覆盖；用户曾质疑该变化，本提案不将它重新评价为已认可，也不擅自改回。后续若重新选择衔接形式，须单列视觉决策与回归范围。
- 仅输入控制默认无外框；阅读态材质是明确 variant，不由祖先选择器碰巧覆盖。缩放须验证布局和命中，但不改变材质偏好；减少透明、增强对比度及原生网页上方回退为实底。
- 断点按交流面板容器而非全窗判断：不超过 620 时收纳完整记录／固定到更多（[ExchangePanel.tsx:121–145](../apps/web/src/ExchangePanel.tsx#L121-L145)）；不超过 440 且启用 `compactWithExchange` 时 Dock 收为 Launcher（[ApplicationDock.tsx:36–51](../apps/web/src/ApplicationDock.tsx#L36-L51)），当前仅非专用对话画布且输入可见时启用（[App.tsx:3437](../apps/web/src/App.tsx#L3437)）；不超过 360 且无阅读面板、有右侧交流控制时 Launcher 左移（[application-dock.css:59–66](../apps/web/src/application-dock.css#L59-L66)）。这些是局部实现条件，不能泛化为所有页面的统一断点。保持实际触控目标与焦点交接。
- 对工作应用是覆盖层，不挤小或重载画布；专用对话页是消息和输入常驻的例外。面板显隐不停止任务，后台新内容不抢展开、滚动或焦点。

### 2.4 密度与视觉构成

SHOULD：正文、对象、行内动作构成主要秩序。只有确实存在独立边界的内容才套容器，例如模态、弹出层、媒体预览、输入及对象集合；禁止“页面卡片 → 区块卡片 → 表单卡片 → 每个图标框”层层套娃。

空态不用填满剩余高度；错误就近出现，不为错误新增永久工具行；长正文必须完整可达。列表摘要可以两行截断并展开，正文不能沿用摘要的截断样式。引用短显且可用 hover、键盘与触控展开；展开内容不得重复生成正式消息空行。

### 3.2 外观是独立维度，不是两套主题皮肤

现有 `InterfacePreferences` 已分开 appearance、accent、textSize、motion。继续保留：

- 明暗：跟随系统 / 亮色 / 暗色。
- 强调色：电光青 / 鸢尾紫 / 暖珊瑚 / 纯单色。
- 辅助偏好：阅读字号、减少动态；宿主系统提供减少透明与增强对比度。

一套布局、图标与运动规范同时适用于这些组合。颜色变化不带来另一套导航、组件尺寸或业务行为。不要新增“澄光／墨白”模式枚举或第二份持久状态。

MUST：材料属性由统一 token 提供。减少透明、增强对比度、原生网页上方回退为实底且无 blur。普通内容不加阴影；覆盖层的阴影仅说明深度。圆角按层级使用：控件 6–8，常规面板约 12，交流表面沿用现有 16；同角色不逐页猜值。

### 3.4 可读性

普通文字（含占位、提示与辅助正文）按至少 4.5:1，大文字按至少 3:1；实际判断必须在合成后的表面上进行，不能只测 token 单色。[WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。必要控件边界与状态图形需另检查非文字对比度，不拿文字阈值替代整套无障碍审计。

图形尺寸和点击面积分开。WCAG 2.2 最小目标条款是 24×24 CSS px，含间距等例外；本产品通常采用 32，局部动作 28，粗指针 44，不谎称全部尺寸来自平台强制要求。[WCAG 目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

## 4. 图标与控件语法

### 4.1 角色登记（不能全都缩小）

| 角色              | 图形／点击区                   | 表面与视觉重量                   | 语义             |
| ----------------- | ------------------------------ | -------------------------------- | ---------------- |
| navigation        | 展开 17；图标栏 24／至少 44 高 | 定制核心线稿；平面选中           | 去哪里           |
| application-entry | 14／32；粗指针 44              | 稳定按钮面、轻边界、当前应用标记 | 去哪个应用       |
| panel-action      | 13／28；粗指针 44              | 默认轻、透明；阅读覆盖时有组材质 | 改当前面板       |
| input-action      | 通常 16／32；粗指针 44         | 行内轻按钮；发送是显著动作       | 给当前输入做什么 |
| status            | 16–20；无操作则不伪装按钮      | 图形＋必要短标签                 | 已知发生了什么   |
| brand             | 图标栏 32，其他沿用现有比例    | 专有标记，不充当通用 busy 图标   | 同一主体身份     |

MUST：SVG 网格、笔画与光学重量登记在统一组件；核心导航保持现有 24 网格／2px 圆头定制轮廓，通用动作继续用 Lucide。小图标采用同一通用笔画基线，不能粗暴把 24px 符号压到 13px 而忽略路径可辨性。默认 `currentColor` 透明线稿，不用白色填充挡后层；品牌和有证据的特殊符号另列例外。

### 4.2 语义注册表

| 概念           | 图形或登记名                 | 不能混用                       |
| -------------- | ---------------------------- | ------------------------------ |
| 交流记录       | 含文字横线的气泡             | 时钟回溯、任务完成             |
| 应用入口       | 对应应用图标；Launcher 网格  | 附件、停止任务                 |
| 侧栏显隐       | 统一 panel toggle，左右镜像  | 运行状态或关闭应用             |
| 新项目会话     | SquarePen                    | 通用加号；全局新会话           |
| 补充原工作     | quote / follow-up 语义入口   | 普通发送；自动猜测目标         |
| 询问批准       | ShieldUser                   | 空盾牌、问号代替人审批         |
| 自动审批       | 勾选盾牌                     | 无条件放行                     |
| 完全访问       | 开锁＋可见风险语义           | 禁止访问的划线盾牌             |

### 4.3 控件状态契约

共享控件必须分别支持 `default / hover / pressed / selected / focus-visible / disabled / pending / error`；这些不是互斥枚举，选中可以同时聚焦，pending 可以同时禁用重复提交。

MUST：hover 不抹掉 selected；focus 不冒充 selected；disabled 说明为何不能操作；pending 不冒充成功。开关可点击时无外圈装饰，键盘焦点仍可辨；有父级总开关时保留子值，呈现“暂不生效”的中性 variant，不批量清值，也不靠整页 opacity 假装状态已关闭。

动作文字通常是短动词；原位编辑不常驻“完成／不设置”等多余一行。字段若需要显式保存、版本冲突或权限确认，不因视觉精简取消真实事务边界。

## 5. 动效系统：反馈、连续性、工作信号分别设计

### 5.1 统一运动语法（提案）

110 / 180 / 220ms 是已存在的时长 token（[visual-system.css:43–45](../apps/web/src/visual-system.css#L43-L45)），不是本轮从审美验证得出的值，也不代表每个场景已统一采用。具体运动方式、数值适用性及收束效果仍待实机运动对照和整体评审。

| 类别       | 视觉方式及数值                                                   | 源码证据／候选状态                                                                                                                                                                                                                                                                         | 绑定与限制                                                |
| ---------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| 即时反馈   | 色面／笔画变化，110ms；必要的 1px 光学校正                       | 时长 token 已存在；1px 统一校正规则为候选，未证实共享实现；审美未验证                                                                                                                                                                                                                      | 实际 hover、press、focus；不移动命中区                    |
| 临时表面   | 沿触发方向展开、透明度进入，180ms；位移最多 4px                  | 时长 token 已存在，dialog 入场使用它（[visual-system.css:1246–1247](../apps/web/src/visual-system.css#L1246-L1247)）；统一位移上限 4 是新候选，当前 dialog 为 4、inspector 为 8、exchange 为 6（[visual-system.css:1216–1244](../apps/web/src/visual-system.css#L1216-L1244)）；审美未验证 | 菜单／弹层开合；可中断，焦点不等动画结束                  |

| 真实运行   | 状态 mark 内短弧或轨迹扫描，2400ms 循环候选；不扫整段正文        | 现有活动轨迹周期为 2.4s（[execution.css:350–355](../apps/web/src/execution.css#L350-L355)）；新短弧造型及其适用节律仍为 `EXP`，不能由周期重合宣称实现或审美通过                                                                                                                            | 仅确知活动运行；不是百分比，不模拟各阶段                  |

共享进入曲线 `cubic-bezier(0.2, 0.75, 0.25, 1)`、退出曲线 `cubic-bezier(0.4, 0, 1, 1)` 已有 token 定义（[visual-system.css:46–47](../apps/web/src/visual-system.css#L46-L47)）；未证实所有进入／退出路径已统一使用，更不据此宣称节奏合适。新组件沿用还是调整需运动评审。光效只占自身小区，不覆盖正文、不发出高频闪烁；禁止弹簧抖动、全页浮动、导航反复入场、假声波与假打字。新增时长必须进入具名 token，不能散落组件，也不能先把经验时长写成已验证规范。

“短弧收束”为 `EXP`：这是可由真实状态驱动的运动方向，不是本轮已交付的动画。最终轮廓、亮度及节律需要用生产状态组件做运动样本评审；不能仅凭文字规范宣称审美已通过。现有工作边缘信号保留到独立评审，不因写这张表擅自更换。

### 5.2 动效必须有启动和停止依据

| 场景               | 来源                           | 可以运动                                   | 必须停止／静态呈现                                                                            |
| ------------------ | ------------------------------ | ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 输入投递中、首字前 | 对应 input delivery            | 轻量等待信号，不是正式回复                 | 回复／交付出现、失败、取消、连接失效                                                          |
| 后台活动运行       | 最新授权 Thread + 执行状态投影 | 对应活动 mark；已有明确 Execution 边缘信号 | 对应工作已静止的等待／暂停、定时等待、结束、失联／未知；暂停后仍执行的当前 Job 保留自己的信号 |
| 模型流式输出       | 同次 publish 的有效流事件      | 新增文本与流尾标记                         | 结束、断线；重连不重播旧前缀                                                                  |
| 工具运行           | 真实 Job 与相关线程            | 工具步骤自己的状态标记                     | 参数生成完成不算成功；以 Job 回执停止                                                         |
| 录音               | 已开始真实采集                 | 实测音量                                   | 停止、隐藏取消、失败；不得播放合成声波                                                        |
| 主体 Logo          | 品牌装饰或明确状态角色         | 仅已登记形式                               | 装饰无业务含义；减少动态时静态                                                                |

MUST：运行状态没有语义进度正文时，mark 仍可显示；不能为动画而调用模型。不可用时停止业务动效并显示未知，不能冻结一个看似还在运行的旧动画。

减少动态不是把周期加长：移除循环、位移、动态去模糊和逐字运动，保留静态图形、状态文字、真实更新。静态 backdrop blur 仍归减少透明／增强对比度策略，不能混轴。系统减少动态必须作用于 CSS 与 JS，不只一个文件；交互完成不依赖动画。[W3C 交互动画说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)提供安全依据，以上具体节律仍是产品选择。

## 6. 展示事实契约：没有回复也能有活动

### 6.1 两条数据链，不凑齐一个“理想画面”

当前源码中，回复正文来自真实 reply／outbound／合法主流式发布；活动来自授权 Thread、Job 与已验证注解。二者独立。`no_reply`／wait 合法，工具阶段 progress 可缺失。不能把注解强塞为 assistant message，也不能把主消息内部 infer 输出当成回复。

| 展示槽         | 合法来源与回退                                          | 缺失时                           | 禁止                                       |
| -------------- | ------------------------------------------------------- | -------------------------------- | ------------------------------------------ |
| 活动身份／状态 | Runtime Thread、同范围 family、真实 lifecycle／控制状态 | 读不可用则未知                   | 根据标题／模型口吻猜成功                   |
| 活动标题       | 有效 title → 实际 Thread intent → 原输入 → “后台执行”   | 使用事实回退，允许详情展开       | 新增一次 LLM 调用只为标题；由标签猜归属    |
| 语义进展       | 同代、已验证 progress                                   | 零正文，状态 mark 保留           | “正在对齐人物动机”固定填充；根据时长推阶段 |
| 步骤描述       | 已验证 intent；否则实际工具名及确定性请求描述           | 如实保留技术名，详情按需         | 在执行前写“已完成”；泄露凭据／私密参数     |
| 结果描述       | 真实终态及同代 Outcome 绑定的 result                    | “执行结束”等机械状态，零语义摘要 | ended＝任务完成；取消沿用旧结果            |
| 补充状态       | 实际送达回执                                            | 待核对／原草稿保留               | 送达＝已采用、已执行或任务已完成           |
| 交付           | 持久对象／版本回执                                      | 不画交付卡片                     | 按回复标题制造对象链接                     |
| 百分比         | 已有确切完成量与可靠总量                                | 不显示                           | 用工具调用数／动画时间估计 2/4 或 60%      |

`progress` 是最近一次有效语义观察，不是实时心跳；详情保留可用来源及观察时间。Thread 更新时间不是注解产生时间；只有权威实际提供时才显示注解自身时间，缺失不补造。失联时按现有边界撤下 open 的缓存 progress，终态历史可继续静态阅读。标题截断／记录未全加载时不能冒充全量历史。

复用现有注解链不会增加独立 UI 模型请求，但生成注解本身有 token 成本，业务协议重试仍可能有请求；不能宣称所有情况下绝无额外模型费用。

### 6.2 按真实状态构成页面

1. **后台运行，没有 assistant 正文**：原输入保留，必要输入反馈是非消息 UI；右栏活动有真实标题、状态 mark 和详情入口。没有语义进展就不占两行空位置，不制造“正在…”回复。
2. **后台运行，有有效 progress**：活动摘要槽显示该 progress；消息区仍只显示真实发布的回复／交付。
3. **父活动 + 子 Thread**：按真实 parent 关系／授权 family 成树，root 仅用于来源绑定，不能仅因同 root 合并为父子。各子项显示自己的事实和可选 prose；无 child title 时用事实回退。主活动仍运行、某子项失败／完成可并存，不能全部涂同一状态。
4. **暂停、审批、定时等待**：对应已静止项使用静态符号及就近操作，无假 running；暂停可能只限制后续，当前 Job 仍执行，审批也可与其他工作并行，仍运行项保留各自信号。要求本人处理时优先提示，但不自动切当前右栏。
5. **执行结束但事项未完成**：活动静态终态；事项保留自身状态。执行勾不是人工完成 checkbox。
6. **断线、截断、权限撤销**：保留获允许的历史与草稿；当前状态明确未知／不可用，权限撤销内容及时失效；不显示“0 项＝空闲”。

事实依据：[Runtime 注解协议](../../morphz/src/response_annotations.rs)、[注解投影](../../morphz/src/runtime/response_annotation_projection.rs)、[Platform 字段投影](../packages/application/src/response-annotations.ts)、[真实活动适配](../packages/application/src/runtime.ts)、[前端活动摘要](../apps/web/src/execution-activity.ts)、[交流展示](../apps/web/src/Conversation.tsx)。这些是当前源码事实，不是实机全场景验证。

## 7. 从规范到组件：不能只要求开发者“注意审美”

### 7.1 Token 三层

| 层        | 内容                                                     | 使用规则                                     |
| --------- | -------------------------------------------------------- | -------------------------------------------- |
| primitive | 原始色阶、间距、字级、圆角、时长、曲线                   | 只有 foundation 定义；领域页面不直接取色阶   |
| semantic  | canvas、ink、muted、selected、danger、running、popover   | 明暗／强调色／辅助模式在此映射，不改页面结构 |
| component | dock.hit、panel-action.glyph、exchange.gap、dialog.width | 组件角色引用语义及基础 token；页面不能复刻   |

提案可采用 DTCG token 类型及别名格式，但不需要先加入设计工具依赖或生成器。三层角色是本产品治理选择，不是 DTCG 规定；DTCG 2025.10 是社区组稳定格式，不是 W3C Recommendation。[DTCG 2025.10](https://www.designtokens.org/tr/2025.10/format/)。

### 7.2 必须共享的构件

- 基础：Button / IconButton（明确 role）/ Toggle / Field / Menu / Tooltip / Dialog / Surface / FocusReturn。
- 宿主：Navigation、PageHeader、PanelToggle、ApplicationDock、ExchangeFrame、Composer、ScopeReference、ErrorNotice。
- 事实展示：StatusMark、InputDeliveryFeedback、ActivityRow、ThreadGroup、StepRow、ApprovalRequest、DeliveryLink。
- 内容：SafeMarkdown、对象预览、引用缩略／展开；复用真实权限与版本，不缓存第二份未授权正文。

共同控件解决键盘、状态、材质、密度和命中；领域组件解决领域信息。不能把 ActivityRow 塞进基础 Button，也不能让基础 Surface 读取 Runtime。具体依赖约束见架构提案。

## 8. 设计交付与审查门禁

### 8.1 每个新组件必须交付一张契约

必须包含：职责／明确不负责什么；role／variant；数据来源及缺失处理；状态组合；布局收纳；键盘与触控；运动启动／停止／减少动态；失败与回执未知；一处样式所有者；测试场景和完整页面使用位置。缺一项就不能仅凭截图进入生产。

### 8.2 五种证据，不互相代替

| 等级       | 可以证明                                 | 不可以宣称                   |
| ---------- | ---------------------------------------- | ---------------------------- |
| 设计提案   | 规则、信息架构、明确权衡                 | 用户已接受；功能存在         |
| 组件实现   | 生产代码有契约及状态组件                 | 数据链与实际原窗口都正确     |
| 隔离验证   | 测试场景的交互、几何与语义成立           | 真实后台任务结果或实机效果   |
| 原应用验证 | 同一 profile／中心下实际链路、命中与恢复 | 全产品都完成；未测平台也支持 |
| 设计评审   | 对整页和运动样本的层级、比例、节奏接受   | 自动化通过等于审美接受       |

### 8.3 必验矩阵

| 维度     | 最小覆盖                                                                                                                              |

### 8.4 例外与变更

新增视觉值、图形或状态必须写：规则 ID、确切作用域、为什么共享 variant 不够、会影响什么、验证证据和移除条件。例外登记是有期限的迁移债，不是在新 CSS 末尾加更强选择器。修改尺寸／布局先改契约再实现；规范正文只保留现行答案，已撤回方案留历史，不参与优先级。

### 8.5 数值规范的冻结门槛

尺寸、字号、间距和动效时长只能在真实状态的跨场景对照及用户整体评价之后冻结。实施者须提供同一原应用／profile 的完整页面实图，覆盖对话、事项正文、工作台、专业画布及主体活动；对照亮暗、阅读字号、不同窗口／容器宽度和缩放，包含长中文、空态、错误及运行／等待组合。候选和现状使用可比较的内容；动效另交连续片段及减少动态对照，静态图不证明节律。

先自行检查层级、比例、密度、遮挡、可读性、命中与焦点，再请用户评价整体效果及取舍，不要求用户逐像素指定。源码、几何测试、文档／原型展示或窗口恢复成功均不代替这项审美评审。通过后记录确切数值、适用角色／条件和证据；未通过仍标候选／审美未验证。此前保留生产值只是避免未经授权的改动，不意味着现有值已经好看。

## 9. 采纳后的次序与本轮边界

1. 评审本规范与架构，冻结职责、状态槽及样式所有权；不先换全页皮肤。
2. 用生产基础组件制作“角色＋状态＋运动”样本，而非全静态示例 App；先覆盖错误、无回复、断线和窄窗。
3. 收敛 token、IconButton role、StatusMark 与 Exchange 样式；保持既有模型／授权／草稿行为。
4. 对话与主体活动完成一条真实纵向迁移，再逐页迁移事项、内容库、工作台与专业应用。
5. 每批同时通过工程门禁、原窗口交互与视觉评审，才能称该批完成。

本轮已完成的是源码事实审计与待评审提案，不是数值审美验证；尚未实现新 token 系统、运动候选、统一组件门禁或前端拆分。原型不升级为生产，生产布局及尺寸不因本次提案被更改。需评审的是体系、边界及真实整体效果，不是要求用户指导每个像素。

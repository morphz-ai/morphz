# 认知应用与工作空间

认知应用定义一类工作的执行方式，GUI 是可选、可按平台适配的界面扩展。Morphz 提供界面宿主，不要求 Morphz Runtime 渲染 GUI，也不把写作、代码和剪辑都塞进同一个固定编辑器。

当前 `morphz-app/v1` 是工程内的实验界面扩展，不是 Morphz 底层标准。先验证和打磨，成熟后再讨论标准化。以下章节记录当前宿主协议；下一轮 UI 优化方案见 [Morphz UI 设计规范](./16-ui-design-standard.md)，不应把方案描述误作已实现行为。

本文件取代早期文档中的“工作台跨项目聚合”和“按对象创建 Session”设计。现有资料组件仍保留；专业认知应用在这个框架上另行建设。

## 工作空间与项目

- **工作台**是尚未命名为项目的持久工作空间，不是临时内存。可以同时打开多个应用。
- **项目**是已经命名、可恢复的工作空间。可以直接创建，也可以从工作台保存而来，不绑定某一类应用。
- **事项**汇集分派给当前 Human 的工作。打开事项保留当前导航入口，审批、回应和后续调度仍指向对象所属项目及原任务。
- **内容**是授权成果与素材的全局目录，不是新的工作空间或 Session。事项与文档、图片等仍共用底层对象模型，但内容列表排除事项；事项集中在独立入口管理，相关成果及对象关系保留。
- **对话**是侧栏首位的固定交流空间，每个 Human 各有一处。它不隶属于当前工作台，保存工作台为项目不会移动或清空这里的交流。它没有“新建对话”入口。

保存为项目是一条原子命令：保留工作空间 ID、对象及版本、输入、应用实例和视图状态，只变更其类型和名称；随后创建一个新的空白工作台。重试同一命令不会再创建一个项目。旧工作不会被复制、重启或删除。

当前持久格式沿用 `projects` / `projectId` 字段，以保持对象、来源授权和历史执行引用稳定；它们现在表示工作空间容器与容器 ID。容器有明确的 `kind: project | desk | inbox | dialogue`，缺省只用于兼容旧项目。只有 `project` 出现在项目目录中。不要把工作台伪装成目录里的一个“临时项目”，也不要在保存为项目时更换这个 ID。

## Session 与执行

个人中心的事项、工作台、固定对话以及未选择内部命名会话的项目，共用一条持续默认会话。项目可按需要新增命名会话，每条对应独立 Session。应用和对象不另建 Session。旧记录缺少 conversationId 时仍按原项目默认会话解释，默认消息视图兼容汇总，不修改历史。详细规则见[持续会话与并发执行](./17-continuous-conversation-and-execution.md)。

项目对话存于中心，带名称、修订与归档状态；其成员权限继承项目，不另外建立私有认知边界。各对话分开保存消息、输入草稿和阅读位置，仍可围绕同一组应用与对象工作。新增对话不是创建 Agent，也不是创建某条执行 Thread。侧栏项目行右侧用方框笔形按钮直接新建，已有会话嵌套在所属项目下，点击即可切换，条目菜单负责重命名、归档和恢复。移除项目顶栏的会话选择器，不建立全局会话列表。

“新建会话”只准备本机草稿并聚焦输入，不立即写入中心。第一次提交有效文字或附件时，`record-input` 的可选 `newConversation` 与首条输入在同一事务中落库；验证失败不留下空会话。首发命令 ID 在草稿期间固定，回执丢失后重试不重复创建或发送。中心通过 `conversationOnFirstInput` 声明此能力，旧中心明确提示更新并保留草稿，不退回提前创建。空白草稿不显示子项；有内容的草稿以“草稿”入口恢复，不冒充已开始的 Session。旧空记录不删除，有文字、引用或附件的旧草稿仍可恢复。

个人中心仍将这些 Session 挂载到同一个 Context，共享认知。团队模式保留已有的授权隔离：不同私有工作空间仍是不同 Context；不能用“共享认知”绕过 Principal 的信息边界。

项目目录是导航页，不另建 Session。尚未打开项目时，其输入明确归到当前工作台，不沿用某个先前项目的应用或对象。

输入框的关联跟随当前工作现场：打开具体事项或文档就关联该对象，停在事项列表就关联事项视图，对话和工作台也各自显示对应范围。关联随下一次输入一起固定，只影响该次 activation，不切换持续默认 Session，也不修改已有执行的作用范围。

每次发送保存当前应用的确切版本、Harness 引用，以及对象版本和选择内容。Harness 通过 Runtime 的消息级 `harness: {id, version}` 传入，而不是修改 Session 的全局 Harness。新输入显式使用 `parallel` 调度，避免打断另一个应用的执行；它不是对某个正在执行线程的隐式插话。事项回应继续走原来的持久调度与依赖接口。

旧对象及空间 Session 不删除、不重放；已经排队或发送的输入保留原路由。新的持续默认会话使用单独、稳定的传输 Session，不把旧空间 Session 强行改绑。每次输入保存真实工作项目，Host 工具通过 Runtime 的 thread/root 与该输入对应，写入原项目。独立命名会话、事项持久安排和浏览器回执保持各自既有路由。执行查询与审批进一步限定到输入根或具体分支，不能因为切换界面而重定向。

归档只整理项目对话列表，不取消请求、关闭应用、删除对象或解绑 Session。归档历史仍可阅读，迟到回复仍归原处；恢复后保留草稿继续输入。默认对话不可归档，确保进入项目即可工作。Agent 生成事项记录来源对话，持久安排与来源变化接续保持同一归属；旧任务沿用既有默认路由。

## 应用生命周期

应用拥有稳定 ID、确切版本、名称、图标和界面入口。启动台卡片单击即打开，键盘聚焦后按 Enter 或空格也可打开；不保留“先选中、再打开”的中间步骤。应用页签用于切换，关闭页签只关闭界面，不取消工作、不删除对象。

同一工作空间内，同一应用版本只保留一个实例。重新启动恢复原实例和已保存状态。不同版本并存，不静默升级正在工作的实例。活动页签属于终端偏好；应用实例及其状态属于中心数据，其他终端能恢复这些实例。

原内置“资料”的通用浏览职责已提升为侧栏“内容”：浏览当前身份有权访问的非事项对象，按所属空间筛选。工作台／项目工具栏提供本空间内容入口，复用同一目录组件，仅展示本空间且同样排除事项；不再提供“资料”应用卡片。内部 `morphz.objects` 实例继续承载阅读、编辑与批注，不改 ID 或存储协议，旧导入对象与视图状态仍可打开。处理外部文件使用输入附件或明确的目录授权，不恢复通用资料导入与自动同步入口。

2026-09-16 修正：全局内容目录选定具体范围后，新输入、智能体起草和手写文档都使用该范围；起草只打开同页输入，不跳转工作台。全部范围的默认工作台目标及旧草稿保留；打开已有内容后关联其实际所属空间与版本。范围切换不搬移旧对象或草稿，不重定向已发送输入，也不另建 Session；目录授权按真实输入范围读取，不随筛选搬移。此规则取代此前“筛选只影响显示、仍一律写到工作台”的设计。第三方应用仍只能通过宿主协议访问本空间授权对象，不继承全局目录权限。`examples/applications/scratchpad.json` 是可安装的宿主协议示例，不是专业写作应用，也不是对未来工作台布局的限制。

界面包需要完成首帧后与宿主握手。隐藏到另一个应用或对话视图时，宿主向应用通知非激活状态，并拒绝它继续发起界面命令；已提交给 Runtime 的工作不受界面隐藏影响。

所有认知应用共用底部交流浮层：展开、固定或收起输入及近期消息，不改变应用画布尺寸；固定只控制失焦收起。收起后仍有「向 Morphz 输入」入口。内置浏览器使用独立 guest 进程并参与宿主合成，不再裁切网页给交流区腾位置；保持原会话分区、登录隔离、网页表单和滚动位置。只允许宿主已经授权打开的确切页面接入，网页不能取得 Node、preload、宿主 IPC 或默认协助权限。完整记录仍是用户明确选择的阅读态，不新增会话或消息副本。

## 自定义 UI 包 v1

这是 Morphz 的 UI 宿主扩展，不修改或声称替代 HNS 标准，不占用尚未定稿的 `.coa` 格式。

应用包为 JSON：

```json
{
  "format": "morphz-app/v1",
  "id": "author.application",
  "version": "1.0.0",
  "title": "应用名称",
  "description": "简短说明",
  "icon": "book",
  "permissions": ["artifacts.read", "artifacts.write", "input.compose"],
  "harness": { "id": "installed-harness", "version": "1.0.0" },
  "ui": { "type": "sandbox", "html": "<!doctype html>…完整独立界面…" }
}
```

`icon` 支持 layers、document、globe、code、book、film，也可以附带 PNG data URL 的 `iconImage`。`harness: null` 表示使用 Runtime 默认执行方式；指定的 Harness 必须已经安装在 Runtime，不能用提示词假装安装成功。界面包的安装不会执行任务或提升权限。

界面使用独立、无同源权限的 sandbox iframe。HTML、CSS 和 JavaScript 可以自由组织界面，但资源须打包在界面内。宿主不向它提供 Node、桌面 IPC、网络、凭据、摄像头、麦克风或任意文件访问。第三方网站由现有受授权的桌面浏览器能力打开，不嵌入这个 UI 沙箱冒充认知应用。

安装须由 Human 在确认界面检查来源及权限；Agent 可以列出、启动已经安装且授权的应用，不能安装可执行界面。相同 ID/版本不能覆盖；修订后使用新版本。

## 宿主协议

名称统一后，新包使用 `morphz-app/v1` 与下列 `morphz-app:*` 消息。已安装的 `morphz-work-app/v1` 包继续使用其原 `morphz-work:*` 消息；宿主按包声明选择协议，不改写旧 HTML，不静默覆盖同 ID/版本。更新示例包必须使用新版本。

宿主向指定 iframe 发 `morphz-app:init`，包括专属 `channel` 和 `context`：工作空间、应用实例、视图状态及修订号、活动状态、主题，以及权限范围内的对象目录。没有 Principal 凭据、中心令牌或其他空间的对象内容。

应用请求：

```js
parent.postMessage(
  {
    type: "morphz-app:request",
    channel,
    requestId: crypto.randomUUID(),
    request: { method: "ready" },
  },
  "*",
);
```

宿主验证发送窗口、opaque origin、channel、当前活动实例和权限，返回 `morphz-app:response`，带同一 requestId、result 或 error。应用也必须检查 `event.source === parent` 和 channel，先完成 ready 往返再开放交互。

| 方法           | 作用                                               |
| -------------- | -------------------------------------------------- |
| `ready`        | 获取当前工作上下文并确认连接                       |
| `saveState`    | 带 expectedRevision 保存应用视图状态；冲突不能覆盖 |
| `readArtifact` | 读取本空间对象的指定版本                           |
| `openArtifact` | 在宿主中打开本空间对象                             |
| `compose`      | 将文字放入当前 AI 输入框，由用户检查后发送         |
| `command`      | 经服务端验证后创建、修订、批注或关联本空间对象     |

写入经原有命令事务和权限边界，不是 iframe 直接修改数据库。`command` 不允许代发 Agent 消息、安装应用、修改身份或跨空间写入。写入 requestId 使用 UUID，并作为持久幂等命令标识；回执未知时必须重用原 ID，不可换新 ID 重复创建。

应用可以准备尚未启动的事项，但不能借创建或修订对象设置 `runRequested`，也不能改写已经启动过的事项来改变安排。启动、停止和调整执行仍经宿主的确认与调度接口。当前应用包只固定直接输入的 Harness；事项调度仍使用既有调度契约，不隐式继承当时打开的应用。

视图状态是小型 JSON（如当前章节、面板、选中对象），不是正文仓库。其 64 KiB 上限保护同步消息；长文、书籍和其他产物使用 Artifact。宿主不会猜测并抓取第三方 DOM 来保存未提交内容，应用作者必须明确保存自己的状态与对象，并处理冲突和失败。

## 后续认知应用的建设边界

### 窗口呈现规范（Desktop 试行）

`ui.presentation` 可声明 `workspace` 或 `immersive`，省略为 `workspace`。这只是 Desktop UI 包契约，不是 Morphz Runtime / HNS 的 GUI 要求。

- `workspace`：保留宿主侧栏，用户自行折叠与展开。应用不再重复渲染自己的应用名称、大标题或面包屑，只呈现场景工具和工作内容。浏览器默认使用此模式，以地址工具栏替代外层标签栏，仍只有一行；返回工作空间可切换其他应用。
- `immersive`：应用占满当前 Morphz 窗口，隐藏宿主侧栏与外层标签栏；不自动切换操作系统全屏，不创建或切换 Session，也不增加执行权限。它是可选呈现，不是浏览器默认行为。
- 宿主必须提供不可被应用移除的“返回工作空间”入口。浏览器将它嵌入地址栏一行；沙箱应用使用宿主叠放的紧凑返回控件，通过初始化 context 的 `presentation` 提供避让区域。
- 浏览器仅有一行工具栏：返回工作空间、网页导航、地址、保存、协助授权和 AI 输入。网页内容紧贴其下，不预留已不存在的宿主标题栏。
- 返回启动台不是关闭应用。浏览器在同一工作空间返回/重开时保留页面与未提交表单，但隐藏页面会撤销 Agent 的临时控制授权。关闭应用、切换中心或退出程序仍结束原生页面；已保存的浏览地址可恢复，不承诺恢复未提交表单。
- 使用系统全屏仍由用户决定。通知、文件选择、截图和权限确认继续由宿主负责，沉浸模式不能绕过这些边界。

在这个契约上建设专业界面和对应 Harness：小说的大纲、人物与正文，代码的仓库、Plan 与变更，剪辑的素材、预览与时间线。它们共同使用现有对象版本、身份和执行记录，不各自实现一套聊天、账号或存储。

本轮不包含应用市场、远程自动安装、签名分发、专业编辑器、移动端，或团队跨私有 Context 的认知共享。

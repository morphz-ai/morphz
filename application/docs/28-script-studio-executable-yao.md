## 产品边界

- 进入剧本工作室不等于开始生成。普通输入可以聊人物、结构、方向和试写示例；
  不要求先建剧本、填写简报或选择流程，不写候选、审阅、正式稿或事项。
- 单次输入有人工提交的固定生成范围时，仍判断本次实际意图。说“先聊聊、先别写”
  只回答，不因为存在 `scriptGeneration` 就执行生产工序。
- 真正生成、改写和检查使用现有“准备请求→人工发送”的固定目标与资料授权。
  普通消息不会继承上一条的生成权限；读写不依赖当前选中的页面。
- 讨论里的示例不是已保存候选。正式稿编辑、候选采纳、权利声明、批准、锁稿和导出
  仍走原领域操作，不由模型代替人确认。未授权的原作不会因普通聊天而被整份读取。

## Yao 真正负责什么

源码：[script-studio.hns](../harnesses/script-studio.hns)。顶层是 Runtime 拥有的 `eval`，
内部 `fn` 被链接进持久 Plan；不是应用端另写状态机，再让 `.hns` 看起来像流程。

| 条件/阶段  | 执行者与真实结果                                                           |
| ---------- | -------------------------------------------------------------------------- |
| 取得输入   | Yao `call host_morphz` → `script/read-workflow`；Host 从真实 root 获取输入 |
| 普通消息   | `discuss-script` 无工具 `infer`，直接交流，不进入后续工序                  |
| 固定请求   | 意图 `infer` → JSON → `decode Bool/String` → `if` 讨论或生产               |
| 初稿/意见  | `initial-script` 推理；`script-product` 将 JSON 解码为 `ScriptProduct`     |
| 第一次检查 | `maxReviewPasses > 0` 且未阻塞才进入；先重查授权与版本                     |
| 修订       | `ScriptCheck.revise` 为真才调用修订推理；先重查授权与版本                  |
| 第二次检查 | `maxReviewPasses > 1` 且未阻塞才进入，检查前轮修改与表达质量               |
| 提交       | 只有未阻塞分支调用 `script/submit-workflow`；Host 校验并持久化             |
| 交付       | 根据真实回执报告结果；不重新创作或补交，不把候选说成正式稿                 |

创作判断属于模型，分支、轮数、因果数据流和提交位置属于 Yao。
`infer` 接收完整 BODY 和显式 captures；模型输出普通 JSON，Runtime 的 `decode` 和
名义记录构造负责类型边界。没有在指令后放一个默认记录，诱导模型“执行”占位值。
最多 2 轮额外语义自审；没有具体问题不修订，有硬阻碍立即返回。这个计数不是费用硬预算，
也不是独立的专业质量认证。

所有模型子步骤无物理工具，不能自行跳过检查写入。顶层完成后的模型只解释结果；
通用 Runtime 的 Objective 生命周期结算仍可使用既有 `objective_update`，领域工具不因此重开。

## Host 与 Runtime 的职责

Host 仅增加材料读取与结果提交两个领域适配器，不调用模型或安排创作阶段。
材料包包含确切版本、有效批准证据及授权原文；超过 120000 字符明确拒绝，不静默截断。
每个边界重查取消、成员、模型处理许可、来源权限和版本。审阅命令整批预检后逐条提交，
每条沿用稳定 job/call/index 幂等身份；不把这称为跨命令原子事务。

本版实际联测暴露并修复的通用 Runtime/Yao 问题：

1. `.hns` 注释经两套解析器解释不一致：改为 Yao 解析后投影规范形式。
2. `Map<T>` 的静态键读取无法通过类型检查：支持 `get`，缺键仍为带位置的失败。
3. 私有 `fn` 在入口二次验证时被拒：仅 Runtime 派发的原样 entry 有内部函数权限，
   模型不能用参数伪造；入口接纳失败不再无限派发自身。
4. 子 infer 没有继承包：从持久父 Plan/子 Thread 获取确切版本与 hash，
   继承契约与只读 Mind，不继承未声明工具，也不重新运行入口。
5. 子 infer 的完整程序/captures 被压成消息预览：当前内部 Evaluation 完整保留输入；
   物理请求预算负责拒绝超限，不能剪掉证据后继续生成。

`587794b6d26d4bc65fb87c29b1d250a2349a3de6b6dd2ed916a347808d709a31`。
1.2.0 字节 SHA-256 为 `a224fc7eac41d991bad8eefa7ecccf8964c7aaf6715c510b6b3e01557b7cc12a`。

### 修复前缺陷：Host 工具任务恢复停滞

7 个失败断点都有相同持久状态：重启后的 Runtime 已加载对应 Harness，但原
`ExecutionJob` 保持 `running`，原 `PlanExecution` 保持 `waiting(execution_job)`。
测试从数据库读取真实租约，到约 90 秒租约过期后再观察 30 秒，仍未恢复。
因此不是仅凭最初 60 秒等待超时就判定产品失败。

`host-submit-after` 的真实 Host 已完成领域提交并产生成功回执：候选数是 1，状态为
`pending`，但该回执尚未传回 Runtime 时进程退出。重启后候选仍保留，流程却无法交付结果。
其他 6 个失败断点没有保存候选。全部失败案例均只有原输入、无已完成模型阶段重跑，
正式稿保持不变；没有观察到重复写入，但这不等于安全接续已完成。

代码定位：

- SQLite 使用 `SharedHostLeases`；[启动任务恢复](../../morphz/src/execution.rs)
  会保留仍有效的运行中租约。这里没有像模型 Activation 那样利用同主机旧进程已退出的事实。
- [Runtime](../../morphz/src/runtime.rs) 启动时执行一次普通任务恢复；现有周期性过期任务
  收敛针对 Edge 后台子任务，没有覆盖这些本地 Host 调用。
- [Plan 接续](../../morphz/src/plan_execution.rs) 只消费权威终态，不能凭空把仍为
  `running` 的工具任务当成成功；这层等待本身不能补回丢失的 Host 回执。
- [HostTool](../../morphz/src/host_tools.rs) 默认 `AtMostOnce`。修复不能把所有 Host 行为
  一律设成可重试：应保留稳定 job/call 身份，明确只读／幂等操作的恢复契约，并核对已经
  持久化的领域回执。否则解除等待后仍可能引入重复副作用。

## 恢复修复与重复验收（2026-09-20）

本轮已修复上面的缺陷，保留修复前证据。没有修改已使用的 `1.2.1` 包，其 SHA-256

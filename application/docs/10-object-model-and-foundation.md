# 对象模型与工程基础

状态：早期对象模型与工程基础记录，不代表当前完整产品能力。现行内容、事项、目录授权与检索边界以[应用 README](../README.md)和[实施记录](./13-implementation-status.md)为准；下文的导入与优先级字段等早期约定不能用来恢复已收缩的入口。

## 产品抽象

Morphz 应用围绕 **Actant + InputBox + Artifacts + Views** 组织。

对象可以由人创作、由 Agent 产出或从外部导入。文档、图片和任务属于同一个 Artifact 体系，彼此以显式关系连接。任务看板、收件箱、文档库等是这些对象的视图，不另建相互脱节的数据副本。

打开对象后，可以阅读、观看、编辑、批注，并围绕它继续工作。Human 和 Agent 都是 Actant，都是可以发起、承担和交付工作的参与者。Principal 表达身份与授权来源；两者不能混为角色标签，也不意味着人与 Agent 自动具有相同权限。

所有页面有共用的 AI 输入框，自动关联当前项目、对象、版本与选中原文。对话位于主工作区，Session 是 Runtime 适配使用的底层交互路径，不是主导航。

此前“先以任务交接组织页面”的提案保留为讨论记录。本文件及当前工程以对象为核心的结构为准。

## 工程结构

| 目录 | 职责 |
| --- | --- |
| `apps/web` | React／TypeScript 界面，Electron 与浏览器共用 |
| `apps/desktop` | Electron 窗口、导航限制与隔离配置 |
| `apps/service` | 本机中心 HTTP 接口与 SQLite 持久化适配 |
| `packages/core` | 类型、请求校验、对象变更、身份检查和 Inbox 投影 |
| `tests` | 领域、存储、HTTP、桌面配置及浏览器端到端测试 |

Desktop 连接中心而不是直接读取数据库。Web 也通过同一接口访问。当前服务是本机单用户适配，不是第二个 Agent Runtime；认知与调度仍留给 Morphz。

React、TypeScript、Vite 是本轮界面实现采用的组合，Electron 延续此前决定。Node.js 内置 SQLite 用于本机中心，降低此阶段跨平台原生数据库依赖的构建复杂度；不能据此宣称已完成 Windows／Linux 桌面实机验证。

## 数据与命令

- **Artifact**：稳定标识、项目、类型、标题、当前内容、创建者、时间与修订。文档保存 Markdown，图片引用独立二进制资产，任务保存责任与进度。
- **版本**：每次编辑新增不可变版本，包含内容、操作者与时间；旧内容不被覆盖。
- **关联**：`references`、`uses`、`produces`。界面先提供“关联对象”，其他语义供后续工作流使用。
- **批注**：引用对象标识、具体修订与原文，不把旧批注重新贴到后来改变的文字上。
- **输入记录**：保留项目、对象、版本、选区、发起身份与接收 Actant。当前状态只有 `recorded`，不假设 Runtime 已接受。
- **事项**：分派、执行与交付分开。负责人引用 Actant；模型是执行策略，不是另一个 Agent 身份。Inbox 从事项与成员关系推导，结合优先级和日期排序。

UI 与未来可信 Agent 适配器使用同一领域命令。认证适配器提供 `AccessContext`，命令体不接受自报的 Principal／Actant 字段。本机 HTTP 适配目前固定使用本机拥有者，不能承担团队认证。

每个变更带唯一操作标识。SQLite 在同一事务内保存状态与回执：同标识同请求返回原回执，同标识不同请求拒绝。对象编辑带 `expectedRevision`，旧版本请求返回冲突。客户端保留未确认请求的操作标识，避免网络回执丢失后的重复创建。

草稿按窗口隔离，避免一个窗口保存时清除另一个窗口的内容。冲突后展示中心最新内容供对照，必须显式选择继续使用草稿；不自动覆盖，也不自动合并。

## 本机对话适配

服务端持有 Runtime 凭据，浏览器和 Electron 页面仅请求本机中心。`/api/messages` 保存输入并加入持久发送队列；重试沿用输入标识作为 Runtime 的 `client_message_id`。队列单独保存接受、执行、完成、失败状态，不修改原始输入来冒充执行回执。

Session 的现行划分见[认知应用与工作空间](./15-cognitive-application-host.md)：每个工作空间绑定稳定 Session，空间内的应用与对象不另建对话。发送时固定对象版本与选区，重试不改用后来编辑的内容。新 Session 使用请求审批与 workspace-write，不继承 Runtime 的完全访问模式。

事件从已持久化的 sequence 游标接续读取；普通回复按因果 root 结算，异步交付通过 thread-result 与 covers 对齐，不能用另一条并发线程的回复清除等待状态。当前展示持久进度与完整回复，逐 token 草稿、审批操作与停止执行 UI 尚未实现。

连接恢复不自动发送旧的 recorded 输入，用户可显式补发；已经接受的请求不会生成新的消息标识。配置与验证方式见根目录 README。

## 下一步接入点

1. 将真实产出写入 Artifact，补充审批与执行控制，而不是把聊天文本当成全部产品状态。
2. 对接可信 Principal 与 Session 身份，不把 Operator 令牌下发到普通页面。
3. 对象变更从轮询快照升级为有水位和重放语义的订阅；草稿同步另行处理。
4. 实现隔离的内置浏览器宿主、浏览器配置、人机控制权及动作回执。
5. 扩展文件／对象打开器，逐步支持 PDF、EPUB、音视频等，不让每种格式复制一套工作空间。

这些是后续工作，尚未由当前工程实现。

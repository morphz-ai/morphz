# 开放设计问题

日期：2026-09-06  
状态：设计草案

本页列出影响产品行为、接口和验证的开放问题。评审时应结合具体使用场景，明确不同方案的收益、代价和失败处理方式。

已有[第一条工作流程提案](./08-first-workflow-and-workspace.md)及[Runtime 源码接入评估](./09-runtime-integration-assessment.md)。它们提供交互与实现依据，尚未冻结下列开放问题，也不代表相关端到端验证已经通过。

## 工作事项与协作契约

- Work Item 的最终名称、状态机及其与 Runtime 对象的映射。
- 一般建议何时成为正式事项，自主规划范围如何配置和呈现。
- 团队角色、直接分派权限、接受与验收规则。
- 团队成员与 Principal 的认证映射、邀请和退出流程，以及成员之间委托与转交的有效范围。
- 模型切换的默认生效点，允许怎样的自动回退和预算调整。
- Inbox 的信息架构，以及通知、任务、会话之间的导航关系。

## 多端交互与访问边界

- Edge 与 Session 的创建／复用方式，跨设备和浏览器标签页的关联方式。
- 浏览器页面读取、输入框写入、外部发布分别采用什么授权方式。
- 内置浏览器配置与 Principal 的关联、人机接管、账号退出及登录过期处理。
- 目标网站的登录兼容性，以及内置浏览器与外部浏览器扩展之间的任务接续路径。
- 多人协作时共享认知的可见性及私密内容边界。
- 多个 Principal 同时向同一 Agent 提出冲突要求时，如何结合权限、目标和优先级协调，而非简单采用最后一条消息。
- 离线能力、同步冲突、设备认证、撤销和恢复的具体方案。

## 接口与交付

- 桌面采用 Electron 的方向已确定，见[技术选型](./07-technology-selection.md)。前端框架、移动端原生框架、扩展工具链、首批支持平台和公共 SDK 边界仍需明确。
- Web 发布清单、完整性校验、缓存更新与回滚策略。
- Runtime 接口兼容声明、能力发现和联合集成验证方案。
- 模型不可用、中心暂时失联和版本不兼容时的交互与恢复行为。

## 验证方法

以端到端工作流程标记每一步的行动者、操作位置、输入、授权和预期结果。针对创建、分派、等待、调整和交付制作交互原型，并覆盖拒绝、超时、并发修改和迟到结果。

评估同时关注任务完成情况与人的操作负担。提出方案时应说明适用条件和可验证的预期，不以功能数量代替体验效果。

### 布局判断与机械结果分开

先前的原 App 审查确认：中间内容是主阅读路径，左右导航／工作状态为次，
不应因压缩控件而压扁正文；目标标题、状态、展开和查看属于同一信息组，
过宽动作间距破坏接近性。项目／内容目录重复卡片的固定最小高度造成
同样信息量占位不同，属于结构密度问题，不是颜色或动画能解决的问题。
间距节奏应是组内紧、组间分隔，不是所有区域统一缩放。

长目标保留两行摘要，全文进独立弹窗；原展开关系、DOM 顺序和焦点不变。
390／760／1440px、200% CSS 缩放以及粗指针测试分别核验换行、滚动、
触控与草稿；另发现 320px 设置导航堆叠后挤走表单动作。空目录与内容少的
大画布不自动算缺陷；长文、错误、弹窗和等待状态不能为了紧凑而隐藏。

## 当前实现判断

Desktop 的 `package.json`、组件入口和实际样式中没有 shadcn/ui 接入。
现有系统是 React 原生控件、Lucide、自有 Tooltip／模态钩子及多层 CSS。
shadcn/ui 本身也不会自动决定 Morphz 的信息密度；本轮使用其
[Button 尺寸与变体](https://ui.shadcn.com/docs/components/button)、
[动作分组](https://ui.shadcn.com/docs/components/button-group) 和
[语义 token](https://ui.shadcn.com/docs/theming) 对照职责，未宣称库迁移。

实现一致性未通过：产品已有布局原则和部分共享样式，但尺寸角色不完整，
功能规则仍会被公共规则覆盖；仅验证最小操作面积与不溢出，不能阻止空白
再次扩张。正确方向是共享控件角色、明确尺寸、实际几何上下界与整页目测，
不是给每个问题继续加一条局部宽高。

## 五维检查说明

实施一致性判定：**未通过**，主要证据是尺寸级联冲突与多层配方漂移，
不是把六条边线警告直接算成六个产品缺陷。按 audit 的 0–4 标尺，有界
源码范围中主题为 3、响应布局为 2、实施一致性为 2；可访问性和性能未
完成全量测量，不给分，不计算全产品 20 分总分或评级。

- **可访问性**：保留原生 button、独立名称、模态焦点、Escape 和禁用状态；
  小图标视觉与触控点击区分离。全应用读屏和逐像素对比度没有完整测试，
  不出具 WCAG 全产品通过声明。
- **性能**：没有新增模型调用、列表读取、动画或运行时依赖。构建仍有既有
  主包／OCR 分块体积警告；未录制首屏／滚动性能，不把体积警告直接说成卡顿。
- **主题**：现有中性／强调色语义 token 与亮暗机制应保留；目标本轮不新增色值、
  终端独立主题或偏好。完整硬编码颜色清理尚未实施。
- **响应布局**：紧凑图标仅显式选择的小动作采用 24px，粗指针保持 44px；
  自动检查 390／760／1440px 和 200% 缩放，不以缩小字号换取通过。
- **实现一致性**：共享入口、尺寸声明和实际几何必须相同；本轮只完成目标行及
  显式紧凑配方，不宣称所有目录、设置和专业应用已统一。

有意保留的优点：真实工作与 UI 导航分离；来源／权限不靠标题猜测；输入
草稿和原对象恢复；四主题共用语义色；执行等待、终态和断线不刷成假运行。
不为审美审计破坏这些已确认行为。

## 本轮交付边界与后续顺序

本轮实施：目标行密度修正、共享小图标尺寸、最大间距及触控回归、当前
设计入口。未实施：全量 shadcn/ui 组件接入、目录卡片／设置重构、全产品
无障碍认证、当前 Codex 会话的自动 Hook 接入。Impeccable 手动源码扫描
已实际执行；验证结果另记于实施记录，失败检查也须保留。

后续顺序：共享控件与 token → 项目／内容目录 Item／Card → 设置与弹窗 →
专业应用工具栏。每一消费面验证实际原 App、草稿／焦点／权限、明暗与缩放
后才宣称完成。按 Impeccable 的布局与审计方法复查，最后执行视觉 polish；
不能只装库、跑分或改变文档标题就算完成。

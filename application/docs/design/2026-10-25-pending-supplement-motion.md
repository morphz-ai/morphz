# 待答补充入口：呼吸灯

## 方向

用户否定只有黑点的提醒，随后明确收敛为纯呼吸灯，不用光晕流转。沿用当前主题与原“补充”动作，不增加按钮、徽标、问题正文或弹窗；状态位置明确显示“等待你的输入”，问题仍在原输入区回答。此处遵循 Impeccable animate 的状态提示与可见性边界，用户指定的呼吸光优先于通用装饰禁例。

## 实现与边界

- 原按钮上使用低浓度主题色底、3.2 秒同步明暗的底光与静止细边；没有旋转、扫光或流动路径。图标始终全亮可辨，只让周围的灯光呼吸，避免最低亮度时控制图形对比不足；减少动态效果时保持静态高亮。
- 装饰伪元素不参与布局和命中，保持原按钮尺寸、键盘焦点、标题、可访问名称、禁用状态与精确 Thread 路由。
- 可见性由 IntersectionObserver 和 visibilitychange 事件决定，无定时器、网络请求、数据库读取或任务状态变更。离屏、隐藏和禁用时暂停；组件卸载释放观察器。
- 减少动态效果保留静态主题色边光，高对比模式用系统 Highlight 描边。只有真实待答入口使用此状态；普通补充按钮不发光。
- Desktop 复用原进展行显示“等待你的输入”，Dashboard 复用原状态位置，不加入问题正文。仅使用当前可用、未终结的真实待答事实；已暂停仍显示暂停，不把陈旧快照伪装成当前待答。

## 验证与视觉判断

两端原组件的挂载交互通过，覆盖原输入区、独立草稿、精确投递、未知回执重试、权限失效，以及真实明暗差、离屏暂停、隐藏/卸载释放和 reduced-motion。正式 Desktop shell 的独立浏览器回归已验证状态文案、原按钮呼吸、不预先展开问题，以及状态不新鲜时不冒称待答。两端相关测试、Dashboard lint 和构建记录按最终日志确认。亮暗主题、完整活动视图与窄窗截图已审看：呼吸集中在原按钮，静止边缘不扫动；图标与元信息保持原对齐，中文问题不挤进活动卡，输入区层级不变。fixture 截图不冒充原应用。

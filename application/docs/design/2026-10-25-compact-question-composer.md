# 问题输入区：紧凑的一体式回答

本轮是既有 Operate 输入区的局部修正，不是全产品换皮。用户指出空白过多、
重复说明占位，并要求对新建的控件一起承担设计审查，而非逐个要求人类标尺寸。
采用现有系统字体、亮暗和四强调色；保留选定的中性底柔光补充入口。

## 本次判断与实现

- 原机中的空 textarea、独立说明行和独立发送行形成重复留白；单个短问题只需要
  来源、问题、选项、回答四组，不需要另一张表单卡片或弹窗。
- 问题与选项用 14px 字号，问题字重 550；说明 12px。选项左侧沿用紧凑序号，
  单选不再同时画远端圆圈；原生 radio 与键盘语义保留，焦点落在整行选项上。
  多选保留可见 checkbox，选中态不代替必须的文字与原生语义。
- 删除可见的「补充说明，或直接填写答案」一行，仅保留辅助技术名称。
  短占位在输入内显示；空输入约 32px，不继承普通 composer 的 60px 最小高度。
  单问题的输入与 32px 向上箭头发送同排，正常空底栏不占位；触控目标 44px。
- 关闭、错误、投递结果未知与核对动作保持。核对投递不是普通发送，继续显示
  文字；冻结状态单独禁用答案控件，不把可核对的按钮一起放入禁用 fieldset。
- 没有新增数据请求、轮询、数据库扫描、模型调用或 Runtime 业务逻辑。
  原请求身份、单选自动提交完整批次、多选／自由回复显式发送与草稿边界保持。

## Direction contract

THESIS: 待答工作只强化原有“补充”入口；点击后，问题、选项和自由回答出现在
原输入框内部。活动卡不展开问题，不增加回答按钮，不打开模态或另一套聊天输入。

OWN-WORLD: 保留各端系统字体、现有输入框轮廓、主题色、亮暗模式和图标重量。
来源是紧凑的原补充目标行，问题 14px，选项 13px，次级说明 12px。待答图标增加
实心主题色表面和一层明暗呼吸的反光；没有提示点、色雾、流转或新增按钮。
系统减少动态效果时保留静态主题色入口，离屏与隐藏时暂停动画。

STORY: 找到原任务的补充图标，看到待答提示，点击进入输入区；读完整问题，选择
单选项直接提交完整答案；多选或自由回答由本人确认发送。批次未答齐不提前发送，
包含多选的问题批次始终保留确认发送。关闭则退出问题模式，保留该问题草稿并返回原输入。
切换别的任务不合并表单，不消费别的待答请求。

FIRST VIEWPORT: 输入框内只有一条原任务目标行和退出动作，随后直接是问题、整行
可选项、自由文本及一次发送动作。问题正文最多占 48dvh／420px 并内部滚动；长批次
不把发送和退出挤出可视区域。窄窗长中文可换行，来源截断但可聚焦并查看完整标题。
不再有重复的“来自”来源行，不在活动卡下增加缩进内容。

FORM: 用现有 composer slot 承载真实请求组件，普通输入、引用和附件仍挂载但在
问题模式隐藏；不清空或覆盖原草稿。表单不是 dialog，没有 backdrop、焦点陷阱或
额外任务操作。原工具请求、Thread/generation、权限及幂等投递协议不变。

FINISH: 原应用检查与显式 TEST 挂载测试分开记录。当前修正范围不包含全局状态读取
性能重构、相对图片内联服务、品牌改版或 Runtime 迁移。代码内部保留 UserInputDialog
等旧名称不代表 DOM 或交互仍是弹窗。

## 正确性边界

- 每次点击核对原请求与授权；不可用、旧记录缺少问题正文或权限丢失时如实显示。
- 发送冻结原 command；未知回执只能显式核对同一命令，不自动创建第二份答案。
- 普通草稿、并发问题草稿相互独立；关闭、多选和自由输入编辑不发送，IME 不意外发送。
- 单选触发提交时显式传递本次答案快照，不依赖 React 下一次渲染；复用原发送防重、
  权限／身份校验和不可变投递回执，未知结果不自动重发。
- 支持 Enter 发送、Shift+Enter 换行和 Escape 退出；退出回到原输入，不锁定页面焦点。
- 原 Runtime 已持久化的问题协议继续使用；本次没有更改 Runtime 数据模型或工具。

# Morphz application work

This application now lives at `application/` in the Morphz repository. Run its npm commands in
this directory (or use `npm --prefix application` at the repository root). Runtime stays in
`../morphz/`; use `scripts/runtime-path.mjs` for integration-test binary discovery. Do not rely on
the former sibling MorphzWork checkout. Keep Runtime/Dashboard builds independent of Electron.
The old checkout is historical fallback, not a second development source. The repository root's
license/provenance rules apply; existing data paths and legacy protocol names remain compatible.

Before changing desktop UI or interaction, read `docs/16-ui-design-standard.md` and the current implementation notes in `docs/13-implementation-status.md`. For application hosting and workspace/Session routing, also read `docs/15-cognitive-application-host.md`.

The current Web/Desktop hosting target is `docs/24-shared-application-host.md`: share plain application logic, embed it in Desktop, and expose it through HTTP only for Web/remote clients. Desktop must not require a local application HTTP server or Vite. Runtime remains separate; its local object-tool callback must not reintroduce that HTTP dependency. Preserve existing data and authorization when changing transports.

- Product and current engineering names use **Morphz**; the application package is `morphz-application`, distinct from Morphz Runtime. New configuration uses `MORPHZ_APP_*`. Old names are compatibility inputs only: preserve existing profile/data paths, authentication, immutable Session formats and tool-call idempotency. Never rename live storage or re-sign a compatible installed launcher merely to remove legacy text. The checkout folder is not a product name or an implicit repository merge request.
- Ordinary tests and current documentation must use canonical names; reserve old headers, tools and protocols for explicit compatibility cases. Preserve dated acceptance evidence and explain retained legacy references. Runtime diagnostics remain client-neutral. See `docs/25-repository-integration.md` for the naming boundary; do not treat a zero-match search as more important than data compatibility.
- Work and objects organize the product. The first sidebar navigation item is one fixed global 对话 space; do not add global new-chat actions or a global conversation list. Each project row has a direct SquarePen action for a new conversation, not a plus or a toolbar dropdown. Project-local conversations nest under their project; their own menus handle rename, archive and restore. Conversation management is optional, never a prerequisite for working.
- Personal default conversation spans 对话, 事项, 工作台 and projects without a named conversation. Named project conversations stay separate. Read `docs/17-continuous-conversation-and-execution.md` for current routing. Preserve old Sessions and in-flight requests without rewriting or replaying them; team Context permissions do not merge.
- Clicking a project itself selects the default continuous conversation; only explicitly created Sessions appear beneath it. Do not render a synthetic “持续对话” child or restore a named Session on an explicit project click. Session selection and page reload may retain a named Session; project disclosure only expands/collapses and never changes routing. Keep legacy default records and messages intact.
- New conversation actions only prepare a local draft. Persist a named conversation atomically with its first valid submitted input, never on navigation or repeated clicks. Empty records stay out of the sidebar; unsent content is a recoverable draft, not a started Session. Preserve legacy records and attachments; failed or uncertain first sends retain a stable command identity for safe retry.
- Project directory, sidebar and title share one management menu. Rename uses a project revision; archive hides daily work, and delete moves the whole project to a recoverable deleted scope without erasing objects, messages, assets, Sessions, drafts or external originals. Active/pending/scheduled work blocks archive/delete, never implicitly stops. Restore before new writes. Keep archived conversations in their own collapsed group; discarded unsent drafts remain locally recoverable with original IDs and attachments. Project activity includes actual project inputs/replies, not just Artifact dates. Preserve search/sort/scope and return navigation. Typed Agent management must resolve the actual initiating Human, recheck both memberships and equal cross-space membership boundaries, use revisions and durable receipts; local unsent drafts are not Agent-readable input.
- Navigation, artifact ownership, conversation identity and execution scope are distinct. Shared-Session Host tools must resolve the persisted input from the Runtime's actual thread/root; never trust model arguments or the currently selected page for project authority. Drafts, input pinning and layout remain scoped to the work surface.
- Sidebar 内容 lists authorized non-task artifacts across spaces; tasks belong in 事项 and are excluded from content lists, counts, type filters and creation shortcuts. Both use the same object store; task-linked documents and relations remain intact. Workbench/project content stays local and also excludes tasks. Do not restore a generic 资料 application tile or create a Session for the content catalog. Preserve the entry and return path when opening objects.
- The workspace launcher visibly separates 继续工作 (recently opened content, with its actual type and open time) from 应用 (launchable tools). Recency comes from successful explicit content opens in this user's local center-scoped history, not storage order, background changes, Agent reads, or passive application restoration. Filter against currently authorized content in the actual workspace; empty history stays empty. Preserve original objects, reading state, drafts, application actions and the floating Dock.
- A concrete 内容 scope is also the destination of new input, Agent drafting and manual writing. Do not display project A while silently creating in the desk. 起草文档 opens the existing input, not a workspace page. Open artifacts retain their actual owner/version; switching scope preserves each draft, attachments and directory grants without moving data or retargeting in-flight work. The all-content scope retains the existing default desk/drafts and is never cross-project execution authority.
- Continuing a current artifact keeps its reader live while recording the exact input reference. Do not implicitly open history and leave stale body text after an Agent update. Explicit history viewing and unsent drafts based on an older revision remain pinned to that revision.
- Content delivery follows the user's purpose: written reports, analysis and one-off comparisons default to Markdown documents, with Markdown tables when useful. Existing editable tables serve ongoing records, per-item editing and filtering; all legacy interactive layouts remain one table type, with 表格／记录／统计 views and unchanged table/form/report keys. Numeric statistics are not written reports. Do not restore the mixed 制作表格或报告 shortcut, require internal-type selection, or silently substitute internal tables for requested Office files or executable HTML. Preserve existing content and use only verified delivery capabilities; adding a suite or managed import needs an agreed scenario.
- Publish main messages chronologically, with stable first-visible identity/time for a streamed reply. Keep causal links without grouping late replies under old inputs. The right execution inspector shows actual threads, tools, approvals and results; opening it must reuse the exchange's streaming prefix and must not retarget the composer.
- Browser bookmarks are a basic browser capability, equally operable by Human UI and typed Agent tools. Store personal bookmarks separately from Artifacts; never create content, fetch a page, index a site or grant browser control merely by saving a URL. Ownership comes from the authenticated Human or the Agent's actual persisted initiating input, not model-supplied identity or the selected project. Preserve revision conflicts, durable retries, delete/restore and privacy across identities. Retire new website Artifacts, not bookmarking itself; old website objects and successful receipts stay readable. Public-understanding documents remain state in their inspector and history, excluded from content lists/counts/recents and deliverable search. Image/PDF support and cognition-application expansion remain; no new editor is implied.
- Delivery links come from persisted Host receipts with exact object/version/input provenance, never inferred from reply text. Navigation restores the work surface without selecting another conversation. Use actual Runtime model catalogs and distinguish next-input selection from task execution settings.
- Preserve the current application while exchanging messages. Hiding input, opening history and switching applications do not stop background work or discard drafts.
- Joining message history and input does not authorize changing button semantics. The user-confirmed layout is one continuous frame with an independent floating Dock anchored above the input edge, not a permanent header/footer tool row. Keep input and view controls grouped with stable x/y hit areas across history collapse/expand/pinning and a natural Tab path. Collapsed history leaves only the input frame; expanded messages must scroll clear of the Dock. Native browser bounds must also clear the floating controls without reopening or granting control. Native file/directory pickers must suspend auto-collapse before opening; cancel/error preserves the originating draft and restores valid trigger focus without stealing newer navigation. Test these transitions, not only button presence or static screenshots.
- Human and Agent are equal participants. Keep identity, authorization, object revisions and actual execution receipts visible where relevant; never simulate success.
- Agent-first: creation shortcuts must use the shared intent input, not a required form. The Agent persists artifacts through real tools. Keep direct result editing and explicit authorization; never interpret a shortcut click as permission to send or execute.
- All product operations must be Agent-friendly: expose typed domain operations and readable state, shared by Human UI and Agent tools, with the same authorization, revision checks, durable retry identity and verifiable receipts. Do not make an Agent simulate clicks to access an application capability. Keep human-only confirmations and approvals human-only; API access is not additional authority. New features must include this interface, not defer it as an optional integration.
- Task priority is the persisted order, editable by Agent or Human drag/keyboard controls. Do not add priority numbers or high/normal/low selectors. List and board share that order and the same objects. Arranging dates, order, project or assignee does not itself authorize starting execution. Current assignment supports the existing Human and Morphz only; member management and multi-Agent onboarding remain future scope.
- Adding a task view must preserve the accepted existing view: the list retains its date groups and compact rows; the board is a separate four-status-column projection. Shared order is presented within each view's groups. Do not remove grouping, turn every list row into an expanded form, or invent a table redesign in response to unrelated ordering/API work. Feedback about a regression calls for restoring the agreed interaction, not replacing the design.
- Files sent for Agent processing use the existing message attachment flow. Do not add generic Open File/Open Folder browsers or implicitly attach a visible file to every input. The distinct supported capability is explicit Agent read-write directory authorization: show its persistent scope by the composer, bind it to the human, center, workspace and conversation, and snapshot authorized grant IDs into each new input. Native selection must state read/write consequences; selection never sends a message, scans/indexes/copies content or starts work. Agent tools resolve the actual persisted input, check live grants on every call and operate on original files; revocation blocks future calls even for existing work. Old read-only references never gain write authority. Versioned writes preserve conflict and durable retry semantics; no shell/delete permission is implied. Only Agent-created, non-imported Artifacts enter the app's full-text index; manual edits do not change their origin. Asset visibility and legacy objects, annotations, drafts and history remain independent of search eligibility. Keep old source sync disabled without deleting data. Managed-copy/import workflows require an agreed scenario and lifecycle, not available backend primitives.
- Use the shared interaction model, modal focus hook and UI tokens. Keep the four Dashboard accent palettes; use accessible foreground shades rather than inventing new brand colors.
- A page has one integrated title/action bar, continuous with the content background. Never stack a small shell title above a large page heading or use large decorative header spacing. Dialog titles and controls share a compact row; preserve necessary permissions and error information.
- Preserve the three-column model: the right-sidebar toggle only shows/hides the shared inspector and restores its last view in the current work surface. Keep its icon and position stable; execution status is a separate conditional entry, never a replacement for the universal toggle. The inspector title/menu identifies and explicitly switches contextual content; background state updates never select a different panel.
- Dialog space is a regression requirement, not a final cosmetic pass. Media previews size to image proportions and available workspace; short forms stay compact. Put retry/refresh actions in the title row and short names beside confirmation actions when space permits. Shared widths use `--ui-dialog-width`, not competing later fixed-width rules. Run geometry regressions for wide/tall/small media, narrow windows, errors, keyboard access and 200% desktop zoom; don't refresh away an unconfirmed screenshot to demonstrate a fix.
- Validate changed behavior with automated tests and real Electron inspection. Existing fixtures must follow current navigation, but do not remove assertions to hide product regressions. The current Morphz app is the user-designated test environment: manual acceptance must use that same app, profile and center, with clearly named test content. Do not launch a second manual-test app, profile or center. Correcting this same app's mistaken Electron bundle/system identity to Morphz is authorized, not a second test environment. Automated regression fixtures may remain isolated; do not report their screenshots as acceptance of the user's current window.
- Native title-bar changes require coordinate mouse acceptance, not only DOM/AX button activation: open and close the inspector, use its menu, click outside the open menu to navigate/focus input, and test sibling toolbar controls. Keep drag rectangles physically clear of sibling controls; menus and their full-window `::backdrop` must explicitly opt out of inherited app-region dragging. Renderer-level clicks do not prove OS hit-testing works.
- Own corrective work in this designated test environment: implement fixes, build, verify and perform necessary normal restarts directly, preserving existing data, credentials, drafts, Sessions and in-flight work. The user explicitly confirmed this on 2026-09-12; do not repeatedly ask for authorization for these already-approved actions, including the Morphz system-identity correction. Explain material effects briefly and proceed. An OS permission prompt may still require the user's actual interaction; do not substitute another assistant confirmation question. This does not authorize unrelated destructive actions, publishing, purchases or changes to other apps' permissions.
- The UI standard includes future targets. Check implementation status before claiming a feature exists. Professional application interfaces and the experimental UI package must not be described as a stable Runtime standard.

User direction takes precedence over these product defaults. Numerical layout baselines are adjustable design decisions, not mandatory Apple dimensions.

# Desktop UI：当前设计入口

本文件是日常修改的决策入口，不取代产品交互和数据边界。详细交互见
[UI 规范](docs/16-ui-design-standard.md)，已验证范围见
[实施记录](docs/13-implementation-status.md)。历史探索稿和已撤回方案没有规范权威。

## 使用场景与方向

Desktop 面向普通用户：用自然语言提出需求，在内容画布中阅读／操作，
在右栏查看真实工作状态。工具栏、导航、列表属于 Impeccable 的 Operate
场景，重视紧凑、稳定与可扫读；正文属于 Read 场景，按文稿阅读或密集
详情选择文字角色，不把长文阅读字号套到所有弹窗。
收紧按钮不能演变成缩小所有文字、压扁文稿或隐藏必要状态。

左侧导航、中间内容、右侧主体信息、底部共享输入和 Dock 的分工不变。
保持四套应用强调色、系统亮暗、真实原生窗口控件和现有内容。终端跟随
应用主题，不增加独立配色设置。查看、导航、收起与刷新不启动或停止工作。

## 控件与密度

以 [shadcn/ui Button](https://ui.shadcn.com/docs/components/button)、
[Button Group](https://ui.shadcn.com/docs/components/button-group) 和
[语义主题 token](https://ui.shadcn.com/docs/theming) 作为组件对照；
**当前 Desktop 尚未接入 shadcn/ui，不得把相似外观或下列映射称为已迁移。**

- 先决定动作的角色、尺寸、状态，再使用共享样式。不能先逐页写宽高，
  再靠更高优先级覆盖默认值。尺寸及点击区必须看实际 computed geometry。
- 常用图标按钮保留 32px。密集列表的次级图标动作可显式使用
  `data-size="icon-xs"`：桌面点击区 24px、图形 16px，粗指针点击区 44px。
  配方只由 `ui/controls/metrics.css` 拥有，功能 CSS 不重复指定同一尺寸。
- 不把所有按钮强制拉满容器。主次操作用相同尺寸级别；相关动作紧邻，
  分组间才留较大间隔。正文、列表、表单、工具栏不使用一个全局缩放系数。
- 执行设置中模型是独立的第一行选择器，明确显示「模型」及下拉指示；
  推理强度的名称、英文当前值、重置和滑轨构成紧邻的第二组，不能插入模型
  或权限字段。强度名称／值使用关联到同一原生 range 的 label，点击聚焦
  并可见反馈，不偷偷循环档位或新增选档弹窗。模型 → 滑轨 → 重置 → 权限
  的键盘顺序与操作关系一致；权限和目录继续在底部同行，不扩展执行作用域。
  组内采用共享 4px 间距，模型行／强度组之间 8px；控件文字使用 13px，
  当前值不使用大号居中标题。真实范围及错误说明、触控目标和不兼容选择保留。
- 标题和状态属于同一信息组，组内间距小于相邻组。图标占位、行内 padding、
  按钮点击区不能反复累加空白。列表高度由实际内容和点击区共同决定。
- 目标行保持两行标题和一组状态；独立查看按钮与展开箭头紧邻。展开只展示
  关联执行，不铺开完整长目标；全文进入原有独立查看弹窗。
- 图标按钮必须保留可访问名称、键盘焦点、悬停提示及禁用／忙碌状态。
  删除、权限与未知回执保留确认和错误说明，不能借精简隐藏风险。
- 只读详情按频率分组管理动作，不把两个等权按钮推到弹窗两端。目标
  查看态的补充、复制、暂停／恢复、更多、关闭集中在标题右侧；编辑、
  执行记录和删除收进更多，阅读态没有常驻底栏。删除只在明确确认时
  使用危险实底和取消动作。按钮沿用共享 32px／触控 44px。
- 目标阅读态可点击弹窗外空白关闭并归还查看入口焦点，不穿透触发背景
  操作；内部点击及向外拖选不误关。编辑、删除确认和处理中保留误关保护。
- 全文阅读弹窗在中间画布内定位，但不能为了不越过画布而变成两三个字
  一行。声明最小可读宽度的模态在画布过窄时改用视口安全范围；极短窗
  保留至少一行实际正文并允许外层滚动。不改变注解浮层的内容区边界。

### 密集详情的文字角色

目标详情沿用系统字体栈。共享 `ui.css` 拥有正文（14px／1.6）与段间距
（0.65em）角色；桌面阅读、编辑和删除说明共用它。标题沿用共享 14px，
状态为 12px。粗指针下编辑框继承已有共享输入规则（16px），阅读文字
不随之放大。文稿、代码与其他应用的阅读排版仍按各自用途决定。

目标正文是保留换行的纯文本段落，不作为 Markdown 解析；空行通过段距
表达，不用放大行高制造空白。复制使用完整原字符串，进入编辑也以原文
填充。编辑框按内容增长，最小高度受 140px／32vh 限制，不为短目标保留
340px 固定空白。实现须检查段落、阅读和编辑的 computed 字号／行高，
以及短内容高度；只检查容器的字号不能证明子段落未被全局样式覆盖。

Impeccable 提供分析与复核流程，不会自动执行所有字体规范；shadcn/ui
对照也不等于组件已经接入。文字角色、源码归属、实际渲染和回归断言
共同约束这次修改，最终视觉判断另记，不能以测试通过替代。

### 交流区的组合密度与错误层级

- 回复来源使用实际输入的短摘录，不以“原消息”冒充内容。历史分页外的
  原输入沿用 Runtime 已返回并获授权的因果来源生成预览，不为一行引用
  扫完整历史、插入重复消息或调用模型。短引文保持现有单行与中性引用线，
  身份仍由精确 input ID 决定，不能按摘要匹配或把预览作为权限。
- 关联、元信息与状态是同一内容组，不得各自累加块间距。复用
  `--ui-space-1`（4px）、`--ui-space-2`（8px）：正文到资源入口 8px，
  同组状态 4px；资源入口与阅读情境使用 12px/1.5 元信息角色。
- 阅读关联为 24px 紧凑行，移除沿用共享 `icon-xs`。与输入首行的实际
  墨迹间距不得超过 12px；空输入不因关联再预留一块说明区。触控目标仍为
  44px；展开内容按需占位，不常驻不可见预览的高度。
- 失败只保留一处可读说明。已有准确关联的错误回复时，输入气泡不再重复
  “执行失败”及“请查看错误信息”；没有错误回复时仍必须显示失败原因。
  具体诊断放入可操作的“错误详情”，不得把英文协议异常直接当普通回答。
- 不以删除真实错误、缩小正文或负边距掩盖密度问题；权限、重试、原文、
  来源身份与执行事实保持。验收必须测组合后的 rect、间距、字号、触控、
  长文和窄窗，并检查完整原 App 截图，不以单组件 CSS 或截图裁剪代替。

对照 shadcn/ui 的 Field/Alert 组合职责，不照搬其页面示例的留白，也不称
Desktop 已迁移组件库；具体像素基线由上述 Morphz token 与测试共同拥有。

## 组件对照与实施边界

| shadcn/ui 参照        | Desktop 当前责任                                    | 不得冒充的完成                     |
| --------------------- | --------------------------------------------------- | ---------------------------------- |
| Button / Button Group | 共用尺寸与主次动作配方，密集次级动作使用明确小尺寸  | 已安装／全局替换 shadcn Button     |
| Collapsible / Sidebar | 目录展开、主体栏和目标关联执行，保持 DOM 与焦点顺序 | 替换三栏产品职责或来源授权         |
| Dialog / Alert Dialog | 复用原生模态钩子，按内容定宽高，删除保留本人确认    | 仅换样式就完成模态／确认迁移       |
| Tooltip               | 统一短名称／全文提示，键盘和 Escape 可达            | 用 hover 替代独立查看入口          |
| Tabs                  | 同一工作现场的稳定切换，不重复标题／状态行          | 切页即创建进程、发送输入或丢失草稿 |

整套组件库接入须另按实际消费组件、主题映射、原生焦点、门户边界、
依赖体积和替换顺序实施。不能直接执行初始化覆盖现有样式，或保留两套
长期竞争的控件权威；接入前后的实际范围都必须明确记录。

## 交付前的密度检查

1. 读取当前源码、原 App 和本文件；以 [Impeccable audit](https://impeccable.style/docs/audit/)
   区分实现检查与视觉判断。工具不可用须说明，不能伪造自动审计结果。
2. 检查整个相关工作面，不只截图中的一个按钮；区分内容少导致的空画布，
   与固定最小高度／重复 padding 造成的结构性浪费。
3. 回归既检查最小点击区，也检查最大间距和无内容占位高度。目标紧凑行
   包含箭头／查看中心距、上下 padding 和标题／状态间距；不只有“不越界”。
4. 检查亮暗、四强调色、窄窗、200% 缩放、鼠标／键盘与模拟粗指针，说明
   哪些是原机、哪些是自动夹具；模拟触控不冒充实体触屏验收。
5. 查看实际渲染后才交付；构建、断言通过或自评分不等于审美合格。保留
   原资料、身份、草稿、Session、进行中的执行和安排；不重放写入验证 UI。
6. 每次 UI 修改都截图审看完整受影响界面及必要状态，记录具体视觉判断；
   不只检查局部按钮或不越界。不确定时寻求独立视觉复核，对外只使用
   合成或明确脱敏的图片，不默认发送用户任务原文。

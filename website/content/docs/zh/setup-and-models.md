设置向导同时保存模型服务实例、认证账号和模型路由，以建立一条完整的模型请求路径。

## 两种设置界面

| 命令 | 适用场景 |
|---|---|
| `morphz setup` | 本机或可访问控制台的环境，默认选择 |
| `morphz setup --tui` | SSH、无图形桌面或纯终端环境 |
| `morphz setup --no-open` | 启动控制台设置向导，但不自动打开浏览器 |

控制台和终端界面写入同一套配置。

## 设置向导保存什么

1. **模型服务实例**：端点、协议与服务方言；
2. **认证账号**：OAuth 身份或 API 密钥的引用；
3. **模型路由**：用户可选择的名称如何解析到物理模型和账号；
4. **模型容量**：只有服务目录明确返回，或用户明确覆盖时才保存。

OAuth 令牌和 API 密钥不写入普通 TOML 配置。配置文件只保存对密钥存储的引用。

## 为什么登录后还可能没有模型

登录成功只证明 Morphz 获得了认证材料。模型选择器还要求存在已启用的模型路由。如果服务提供模型目录，控制台会显示服务真实返回的模型；如果服务不提供目录，用户必须填写服务真实接受的物理模型名。

Morphz 只显示服务目录返回或用户明确配置的模型名；系统生成的路由 ID 不会作为用户别名展示。

## 默认模型

当前默认模型由 `[llm].model` 指向的模型路由决定。选择器显示路由的 `display_alias`；没有显示别名时，显示服务返回或用户填写的真实物理模型名。

修改后可以用以下命令解释最终配置来源：

```bash
morphz config explain --format=json
```

这比只查看某一层 TOML 更可靠，因为 Morphz 会合并用户配置、项目偏好和命令行覆盖。
